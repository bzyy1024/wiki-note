# 06 网状思维与线性文本：你为什么总是写一半卡住

> 第二卷·心法篇 第一章

---

## 一、写到一半卡住的那个晚上

上个月你打开一个空白文档，准备写一份"年度技术总结"。标题写好了，目录列了五节——"项目成果""技术沉淀""团队贡献""踩过的坑""未来规划"。

然后你开始写第一节。开头一句"在过去的一年里，我们团队..."，写完。下一句"主要完成了以下几个项目..."，写完。第三句——光标闪。

你脑子里的画面很清楚：今年做了订单服务拆分、消息队列迁移、可观测性建设、新一代 API 网关。这些都是"项目成果"。但你不知道**先写哪个、按什么顺序写、每个写多深**。

你停了十分钟，最后关掉文档，想着"明天再说"。

"明天"你打开同一个文档，光标还在原位。你又写了一句"订单服务拆分是今年最重要的项目..."，又卡住。你重新关掉。

这种情况每个写过东西的人都遇到过。你想的很清楚，但你写不出来。

这不是"拖延症"，不是"灵感没来"，是**网状思维和线性文本的冲突**。

你的脑子是网状的——所有想法同时存在，互相连接；读者的脑子是线性的——只能一个接一个读。

**写作的过程，是把"网状思维"翻译成"线性文本"**。这个翻译过程会卡住，因为你要做很多决定：先说哪个、后说哪个、哪些删掉、哪些展开。这些决定不是"对错"的问题，是"结构选择"的问题。

第一卷讲了"充实度"的四个维度（密度、结构、论证、深度）。这一章开始讲"怎么把脑子里的东西写出来"——讲的是"想法到文本"的过程。

---

## 二、网状 vs 线性：四种思维模式

把"脑子里想东西"和"写东西"分开来看，它们的思维模式是不一样的。

**模式一：网状思维**。

所有想法同时存在，互相连接。当你"想清楚"的时候，你脑子里是 N 个节点和 N×N 条边的图。每个节点都能跳到任何其他节点。

这就是为什么你"想清楚"一件事时，会感觉"恍然大悟"——不是按顺序推导出来的，是突然"看到"全局。

**模式二：线性思维**。

按顺序串行处理。当你"写东西"的时候，你只能一个字一个字往下写。前一句没写完，后一句出不来。

写作是串行的。

**模式三：树状思维**。

从上到下分叉。一个核心论点，下面挂几个分论点，每个分论点下面挂几个论据。这是"金字塔"的思维模式——下一章会详细讲。

**模式四：图状思维**。

节点和边都有，但比"网状"稀疏——是有结构的图，不是密密麻麻的图。这是"大纲"的思维模式——下面会讲。

四种思维模式的关系：

```
网状（图状）= 脑子里的状态
线性 = 写作的物理过程
树状 = 段落 / 章节的内部结构
```

写作的任务是：**从"网状"出发，先整理成"图状"（大纲），再拆解成"树状"（段落 / 章节），最后串成"线性"（成稿）**。

这就是为什么你"想清楚"但"写不出来"——你跳过了中间的"图状"和"树状"两个步骤，直接从"网状"到"线性"。

网状 → 线性：会卡住。
网状 → 图状 → 线性：会顺畅。
网状 → 图状 → 树状 → 线性：会非常顺畅。

## 三、为什么"先写再说"是错的

很多人解决"卡住"问题的方式是"先写再说"——打开文档，从第一个字开始写。

这种做法有两个问题。

**问题一：你会在"已经写好的内容"上产生沉没成本**。

你写了 500 字，回头看，结构散、内容浅。你想重写——但你已经花了一个小时在这 500 字上。你不舍得删，于是你"在 500 字的基础上改"——越改越乱，越乱越不舍得删。最后的产物是"500 字骨架 + 500 字补丁"——一篇缝合怪。

**问题二：你会在"已经选定的开头"上被锚定**。

你写了"在过去的一年里..."，接下来的所有内容都被这句话锚定——你想讲"团队协作"也得绕回到"在过去的一年里，我们团队..."。这个开头定死了你的整个文档。

"先写再说"不是不能用，是**用在写完之后**，不是**用在写之前**。写之前要做的是"画图"——下面讲。

## 四、写作的四个阶段

把写作过程拆开来看，所有写作都跑不出四个阶段。

**阶段一：发散**（想）。

你脑子里有一团模糊的想法。你不知道要写什么，但你隐约知道"有什么东西要写"。这个阶段不要急着组织——让想法自由涌现。

阶段一的核心动作：**写下关键词**。

不要写完整的句子，不要追求通顺——把脑子里的关键词倒出来。可以是名词（订单服务拆分、消息队列、可观测性）、可以是动词（重构、迁移、上线）、可以是疑问（为什么会卡？接下来怎么走？）。

关键词越多越好。先不要筛选。

**阶段二：整理**（画）。

关键词倒得差不多了，开始整理它们之间的关系——哪些是核心、哪些是边缘、哪些是衍生、哪些是反例。

阶段二的核心动作：**画图**。

把关键词画成节点，关系画成边。节点之间可以是"递进""并列""对比"等关系。画到你觉得"图能讲清楚"为止。

**阶段三：组织**（写大纲）。

图画好了，把图翻译成大纲——一段话对应一个节点，一节对应一组节点。

阶段三的核心动作：**写大纲**。

大纲不用写得详细——一段写一句"这段要讲什么"。每段对应图上的一个节点。

**阶段四：成稿**（写正文）。

大纲有了，按大纲一条一条写。每写一段，回头看大纲，确认这段对应哪个节点。

阶段四的核心动作：**写正文 + 反复检查**。

四个阶段的关系：

```
发散（想） → 整理（画） → 组织（写大纲） → 成稿（写正文）
```

跳阶段会出大问题：

- 跳过发散，直接写正文 → 写出来空洞。
- 跳过整理，直接写正文 → 结构散。
- 跳过组织，直接写正文 → 节奏乱。
- 跳过成稿后的检查 → 错误没被发现。

## 五、发散阶段：怎么倒关键词

发散的核心是"放空"——不要急着判断对错、不要急着筛选、不要追求完美。

具体做法：

**做法一：定时 10 分钟，狂写关键词**。

打开一个新文档（或者一张纸），给自己 10 分钟时间，把所有想到的关键词写下来。想到什么写什么，不要停。10 分钟到了停。

**做法二：从一个核心词开始联想**。

脑子里一个核心词（比如"订单服务拆分"），从这个词往外联想——触发点、相关点、对比点、反例点。比如：

- 订单服务拆分
  - 触发点：耦合严重
  - 相关点：循环依赖、部署阻塞、故障传导
  - 对比点：服务合并、API gateway
  - 反例点：拆完之后反而难维护

**做法三：模拟读者问题**。

假装读者会问什么问题，每个问题一个关键词。比如读者会问：

- "为什么要拆？"
- "拆了之后有什么好处？"
- "拆的时候踩过什么坑？"
- "为什么不合并？"
- "如果不拆会怎样？"

每个问题一个关键词。10 个问题就是 10 个关键词。

三个做法选一个用。发散阶段的核心是**数量**——关键词越多，后续整理越有素材。

## 六、整理阶段：怎么画图

关键词倒得差不多了，开始整理——画图。

图的画法：

**步骤一：识别核心节点**。

从所有关键词里挑出 3-5 个"核心节点"——这是你这份文档要讲的几个主要话题。

挑核心节点的标准：决策视角、读者视角、价值视角（上一章讲过）。

**步骤二：识别关系**。

核心节点之间的关系有三种：

- **递进**：A 是 B 的基础，B 是 C 的基础。
- **并列**：A、B、C 是同一层级。
- **对比**：A 和 B 在某些维度对立。

在节点之间画线，标注关系。

**步骤三：识别边缘节点**。

非核心节点挂在核心节点下面——它们是核心节点的"展开"。比如"核心节点：为什么拆"下面挂"边缘节点：耦合、循环依赖、阻塞"。

**步骤四：识别反例节点**。

读者可能的反驳、自己能想到的反例，挂在核心节点旁边——它们是核心节点的"反驳"。

最后画出来的图大概长这样：

```
（核心节点 1：现状）
    ├── 边缘节点 1.1
    ├── 边缘节点 1.2
    └── 边缘节点 1.3
（核心节点 2：方案）
    ├── 边缘节点 2.1
    ├── 边缘节点 2.2
    └── 反例节点 2.3
（核心节点 3：风险）
    ├── 边缘节点 3.1
    └── 反例节点 3.3
```

这张图就是你的"骨架"。

**画图的物理形式不重要**——可以用白板、可以用思维导图软件、可以用纸笔、可以用 markdown 列表。重要的是**视觉化**——你看到的是"图"，不是"线性列表"。

## 七、组织阶段：怎么写大纲

图画好了，把图翻译成大纲。

大纲的写法：

**第一层：节**。

每个核心节点对应一节。节标题用"结论式"——不是"主题"，是"判断"。上一章讲过。

**第二层：段**。

每节下挂几个段落。每个段落对应一个边缘节点或反例节点。段落的"段首句"是这个节点的"结论"。

**第三层：句**。

每段下挂几个句子。每个句子是"段首句结论"的支撑——数据、案例、类比。

三层大纲：

```
节 1：核心判断 1（结论式）
  - 段 1.1：本段核心论点（结论式）
    - 句 1.1.1：支撑 1
    - 句 1.1.2：支撑 2
    - 句 1.1.3：支撑 3
  - 段 1.2：本段核心论点（结论式）
    - ...
节 2：核心判断 2（结论式）
  - ...
```

三层大纲写出来，每层一句话——加起来 30-50 行。这就是你的"结构图"。

写大纲的时候不要写完整句子——只写"这段要讲什么"。完整句子留给成稿阶段。

---

## 八、成稿阶段：怎么写正文

大纲有了，按大纲一条一条写正文。

成稿的三个技巧：

**技巧一：按节点写，不要按顺序写**。

如果某个节点你已经想清楚，就先写它——不用按大纲顺序。比如"风险"那一节你已经想清楚了，先写"风险"，再回头写"方案"。

按节点写的效率比按顺序写高一倍——因为你不用每次都"重新进入状态"。

**技巧二：写完一段回头看大纲**。

每写完一段，回头看大纲，确认这段对应哪个节点。如果不对，回到大纲调整。

**技巧三：每个段落写完做"删除实验"**。

这是第二章讲过的方法。写完一段，把每句话做删除实验，标 L1 / L2 / L3 / L4。L1 砍、L2 砍一半、L4 补一两个。

## 九、反例：不做发散阶段的写作

举一个反例，演示"不做发散阶段"会写出什么。

上周我帮同事改一份产品规划文档。原稿 3000 字，分五节：愿景、目标、策略、计划、预算。

我读完发现一个问题：**五节之间没有明确的逻辑关系**。

> 第一节讲"愿景"——我们要做最好的产品。
> 第二节讲"目标"——今年要新增 100 万用户。
> 第三节讲"策略"——通过内容运营、品牌投放、渠道合作三种方式实现。
> 第四节讲"计划"——Q1 上线新版本，Q2 做活动，Q3 上新品类。
> 第五节讲"预算"——今年总预算 5000 万。

每节都有内容，每节都讲到了。但节与节之间没有"为什么这个之后是这个"的逻辑——读者读完不知道"愿景 → 目标 → 策略 → 计划 → 预算"是怎么推导出来的。

我问同事："你写之前画图了吗？"

他说："没有。我直接按'愿景目标策略计划预算'这个模板填的。"

这就是"跳过发散、直接写正文"的代价。他按模板填，但模板里的关系是"通用模板"的关系，不是他这份文档实际的关系。

改写方法：先做发散——把所有想到的关键词倒出来。然后画图——找出"愿景 → 目标 → 策略 → 计划 → 预算"实际的逻辑链。最后按图写大纲、写正文。

改完后的版本：

```
1. 我们的愿景：成为 X 行业最受信的产品。
2. 今年的现状：用户增长停滞，新客成本上升 30%。
3. 今年的策略：从获客转向留存，提升单位用户价值。
4. 今年的计划：留存提升的具体动作（产品、内容、运营）。
5. 今年的预算：每个动作的预算分配。
```

五节之间有清晰的"为什么是这个之后是这个"的逻辑。读者读完能复述出"为什么今年要做这些"。

## 十、心法：从"图"出发，不要从"字"出发

讲到这里，把这一章的逻辑串成一条线。

**写作的本质是"翻译"**——把脑子里的"网状思维"翻译成读者的"线性文本"。

直接翻译会卡住。**正确的做法是先把"网状"整理成"图状"，再翻译成"线性"**。

四个阶段：发散 → 整理 → 组织 → 成稿。跳阶段会出大问题。

我自己的写作习惯（这是我从卡住到不卡住的关键）：

1. **接到一个写作任务，先不打开文档**。用 10 分钟倒关键词（发散）。
2. **关键词倒完，画图 10 分钟**（整理）。核心节点、边缘节点、反例节点。
3. **图画好，写大纲 10 分钟**（组织）。三层大纲，30-50 行。
4. **大纲有了，开始写正文**（成稿）。按节点写，不按顺序写。
5. **每写一段做删除实验**（充实度检查）。

总耗时：倒关键词 10 分钟 + 画图 10 分钟 + 大纲 10 分钟 + 写正文 60 分钟 + 改稿 30 分钟 = 2 小时。

"先写再说"的方式看起来更快——直接打开文档写——但实际上会卡住、重写、缝合。最后的产物质量差，时间也没省。

**从"图"出发，是把"卡住"变成"流畅"的关键**。下一章我们讲"大纲的艺术"——把"画图"这一步做细。

## 十一、思考题

### 思考题 1：观察自己"卡住"的瞬间

回想你最近一次"写到一半卡住"的经历。按以下步骤分析：

1. 当时的写作任务是？（不超过 30 字）
2. 你打开文档的时候，脑子里有完整的"图"吗？
3. 你在卡住之前，写了多少字？哪些字？
4. 卡住的时候，你脑子里在想什么？
5. 你当时是怎么处理卡住的？（继续硬写 / 删掉重来 / 关掉 / 求助）

写一篇 300-500 字的"卡住分析"。

### 思考题 2：拿一个写作任务做"发散 → 整理 → 组织"

找一个你最近要写的写作任务（可以是工作文档、博客、邮件）。按本章方法做：

1. **发散**（10 分钟）：把想到的关键词全写下来。
2. **整理**（10 分钟）：画一张图，标核心节点、边缘节点、反例节点。
3. **组织**（10 分钟）：按图写三层大纲。
4. **成稿**（60 分钟）：按大纲写正文。

做完之后，对比"以前直接写"的体验——这次还卡住吗？

### 思考题 3：分析一份"卡住痕迹明显"的文档

找一份你读过的"读起来卡"的文档（结构散、节与节之间没逻辑、不知道作者在讲什么）。做一份"卡住分析"：

1. 这份文档的节数是多少？每节字数？
2. 节与节之间有没有过渡？
3. 能不能推断出作者的"图"——他脑子里原本是怎么想的？
4. 作者卡在哪里？是发散阶段？整理阶段？组织阶段？成稿阶段？

写一篇 500 字的分析。

### 参考答案

#### 思考题 1 参考答案

大部分人分析完会发现自己"卡住"的模式惊人一致：

- 接到写作任务 → 直接打开文档 → 从第一个字开始写 → 写到某个位置卡住 → 不知道怎么继续 → 关掉 / 重来。

这个模式的核心问题是**跳过了"发散"和"整理"两个阶段**——直接从"想"跳到"写"。

改写方法：

1. 接到任务，先别打开文档。
2. 用 10 分钟倒关键词（发散）。
3. 用 10 分钟画图（整理）。
4. 用 10 分钟写大纲（组织）。
5. 然后才开始写正文（成稿）。

我自己的改写经验：从"直接写"切换到"先发散再写"，第一次会觉得"麻烦"；做完几次之后会发现，"先发散再写"反而更快——因为发散阶段已经把 80% 的难点都解决了。

#### 思考题 2 参考答案

做完这道题大部分人会发现：

- 直接写 → 写到 1/3 卡住 → 删掉重来 → 再写到 1/3 卡住 → 关掉。总耗时 2-3 小时，产物质量差。
- 发散 + 整理 + 组织 + 成稿 → 全程不卡住 → 总耗时 1.5 小时，产物质量高。

"先发散再写"看起来多花 30 分钟准备（发散 + 整理 + 组织），实际反而**省**时间——因为减少了卡住和重写。

我自己的写作经验：所有"卡住"都源于"跳过发散和整理"。一旦做了这两步，写作变成"翻译"——把已经整理好的图翻译成线性文本。

#### 思考题 3 参考答案

"卡住痕迹明显"的文档有两种典型：

1. **节数过多**（≥ 7 节）——作者没做"整理"步骤，所有话题都塞进去。这种文档"百科全书"式，每节都浅。
2. **节标题模糊**（"背景""现状""方案"）——作者没做"组织"步骤，没把"图"翻译成"判断式标题"。

分析这种文档时，可以尝试"逆向复原作者的图"——如果你是作者，你脑子里原本是怎么想的？你能复原出那张图吗？如果不能，说明作者的图本身有问题。

## 十二、动手练习

### 练习 1：观察自己的"卡住"模式

回想你最近三次"写到一半卡住"的经历。按"思考题 1"的方法做"卡住分析"。

写一篇 500 字的"卡住分析报告"，列出三个共同点。

### 练习 2：用一个写作任务做"四阶段"

找一个你最近要写的写作任务（可以是工作文档、博客、邮件）。按本章方法做完整四阶段：

1. **发散**（10 分钟）：关键词。
2. **整理**（10 分钟）：画图。
3. **组织**（10 分钟）：三层大纲。
4. **成稿**（60 分钟）：按大纲写正文。

做完之后对比体验：还卡住吗？

### 自评标准

**练习 1 自评标准**：

- 找到至少一个共同点——过关。
- 找到三个共同点——优秀。
- 找不到共同点——再回想几次。

**练习 2 自评标准**：

- 全程不卡住——过关。
- 写完产物能让一个同事讲出核心论点——优秀。
- 写到一半卡住——重新做"发散"和"整理"。

## 十三、小结

这一章讲了"为什么你总是写一半卡住"的本质：

| 概念 | 一句话 |
|---|---|
| 网状 vs 线性 | 脑子是网状的，写出来是线性的。 |
| 四个阶段 | 发散（想）→ 整理（画）→ 组织（写大纲）→ 成稿（写正文）。 |
| 发散 | 倒关键词，数量为先。 |
| 整理 | 画图，核心节点 + 边缘节点 + 反例节点。 |
| 组织 | 把图翻译成三层大纲。 |
| 成稿 | 按节点写正文，每段做删除实验。 |

**写作的本质是翻译**——把脑子里的图翻译成线性文本。

跳过阶段会卡住。按四阶段走会流畅。

> **心法**
>
> 写作不是从"字"开始的，是从"图"开始的。
>
> 先发散（倒关键词），再整理（画图），再组织（写大纲），最后成稿（写正文）。
>
> 跳过"图"直接写"字"，是卡住的根。
>
> 接到写作任务，先别打开文档。先想 30 分钟，再写 60 分钟。
