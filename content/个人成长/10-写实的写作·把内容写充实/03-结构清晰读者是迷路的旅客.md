# 03 结构清晰：读者是迷路的旅客

> 第一卷·认知地基 第三章

---

## 一、群里没人回的那条消息

上周你在公司群里发了一段 500 字的产品分析。讲的是"为什么这个新功能不应该用方案 A，应该用方案 B"。你写了四段，分别讲了背景、问题、方案、对比。你自认为逻辑清楚、立场明确。

发出去之后，群里没人回。

第二天早上，有人私聊你："这事你怎么看？"——他根本不知道你昨天在群里发过。

你心里有点委屈："我不是昨天发过了吗？"

但你冷静下来想：他没看到你的消息是有道理的。

你那条消息**没有路标**。

读者扫一眼：开头没明确抛出"我要解决什么问题"——他不知道这是讲什么的；中间四段，每段都差不多长，没有"主次"——他不知道重点在哪；结尾没有"我希望读者带走什么"——他不知道你要他做什么。

于是他扫了一眼，关掉了。他没义务替你"看出重点"。**让他看出重点是你的责任。**

这件事的本质，是**读者的注意力是稀缺资源**。你写文档的过程是往他脑子里"塞东西"，但他脑子里能同时装下的东西是有限的。你塞得不有序，他就装不下。

这一章讲的就是怎么"有序地塞"。

---

## 二、读者为什么会迷路——一个认知科学的事实

先讲一个硬数据。

心理学家 George Miller 1956 年发表的论文《The Magical Number Seven, Plus or Minus Two》提出：**人的工作记忆容量是 7±2 个 chunk**。

后续研究把这个数字修订得更精确：短时记忆容量是 **4±1 个 chunk**（Cowan 2001）。

什么意思？

读者读你的文档，他脑子里**同时**能装下的概念数量大概是 4 个左右。超过 4 个，他就会开始丢东西——丢的顺序通常是"次要的先丢"，然后是"非主线的内容"，最后如果还装不下，他连主线都丢。

你的文档写得烂不烂，和"他能不能装下"有直接关系。

举一个反例。我见过有人写产品介绍，开了"七大优势"。每条优势一段，七段密密麻麻。

读者读第一条，他脑子里装着"第一条优势是什么"。读第二条，他脑子里要同时装着"第一条 + 第二条"。读到第四条，他脑子里有四个 chunk 了，开始丢。读到第七条，他只记得前两条。

最后他读完，记住的是"好像讲了很多优势，但具体是哪些想不起来"。

**七个优势读者记不住，三个他能记住。**

这不是读者的问题，是你没帮读者分主次。

再举一个反例。一份设计文档，第一节"背景"讲了 800 字。读者读完背景，脑子里已经塞了背景里的所有细节。开始读"问题"时，他脑子里还要**同时**装着"背景"——因为他不知道"问题"和"背景"的关系。

如果"背景"和"问题"之间没有显式连接，读者会以为"问题"是新主题——他就把背景丢了。或者反过来，他为了不丢背景，开始跳读"问题"，因为"问题"读不下去。

**结构清晰就是显式告诉读者"现在我们在哪里、接下来要去哪里、刚才讲的东西和接下来讲的是什么关系"。**

读者不需要自己推理这些关系。你帮他推理好了，他只要跟着走就行。

## 三、结构的三种基本类型

把"信息之间的逻辑关系"抽出来，所有关系都跑不出三种基本类型。

**类型一：递进**。

A 是 B 的基础，B 是 C 的基础，C 是 D 的基础。每一层在前一层之上推进。读者读 A，才能读 B；读 B，才能读 C。

典型场景：问题分析、设计文档的"问题 → 原因 → 方案 → 风险"、教程的"基础概念 → 进阶概念 → 综合应用"。

> 例：HTTP 协议 → HTTP/1.1 的队头阻塞问题 → HTTP/2 的多路复用 → HTTP/3 的 QUIC。

**类型二：并列**。

A、B、C、D 之间是同一层级的并列项。它们之间的关系是"它们都属于 X"，而不是"A 推导 B"。

典型场景：方案对比、特性列举、选项说明。

> 例：本项目支持的部署方式有四种：本地部署、Docker 部署、Kubernetes 部署、混合云部署。

**类型三：对比**。

A 和 B 在某些维度上对立。通过对比让读者看清"A 和 B 的差异在哪""在什么场景下选 A、什么场景下选 B"。

典型场景：方案选型、技术选型、优劣对比。

> 例：PostgreSQL vs MySQL——一致性优先选 PostgreSQL，性能优先选 MySQL。

这三种类型之外的所有"结构"，基本上都是这三种的组合或变形。学会这三种，你就能拆解任何你看过的文章结构。

## 四、段落的路标：段首句必须是核心论点

讲完段与段之间的结构，再讲段内的结构。

**一条硬规则：段首句就是本段的核心论点**。

为什么？

读者读你的一段话，他不会逐字读。他会先扫段首句——如果段首句引起他的兴趣，他会继续读；如果段首句含糊，他会跳过这一段。

一个反例：

> 在过去的一周里，我们团队围绕新功能的方案做了多次讨论。经过反复权衡，我们最终决定采用方案 B。具体来说，方案 B 在性能、可维护性、扩展性三个方面均优于方案 A。性能方面，方案 B 减少了 30% 的接口调用次数；可维护性方面，方案 B 的代码结构更清晰；扩展性方面，方案 B 更容易支持新场景。

这段话的段首句是"在过去的一周里..."——这是一个氛围铺垫，对读者毫无信息。读者扫这段时，会跳过；即使不跳过，他读完也不知道"我们做了什么决定"。

改成：

> 我们决定采用方案 B。理由三点：性能、可维护性、扩展性。性能方面，方案 B 减少了 30% 的接口调用次数；可维护性方面，方案 B 的代码结构更清晰；扩展性方面，方案 B 更容易支持新场景。

段首句是"我们决定采用方案 B"。读者扫这一段，第一眼就知道"哦，决定是 B"。他要不要读下去，看他关不关心 B 的理由。

**段首句的核心论点之后，整段剩下的部分都是对这个论点的"支撑"。** 支撑可以是数据、可以是反例、可以是论证、可以是类比——但**必须支撑段首句**。

如果一段话里后面几句和段首句没关系，那这几句话应该拆出去，要么合到下一段，要么独立成段。

## 五、节与节之间的连接：路标句

段首句是段内的路标。**节与节之间也需要路标**——这种路标叫"过渡句"。

过渡句的作用是告诉读者"上一节讲完了什么，这一节要讲什么，它们之间是什么关系"。

举一个反例。

我见过一个产品文档，结构是这样的：

```
1. 背景
2. 现状
3. 方案
4. 风险
```

读者读完"背景"，开始读"现状"——他不知道"现状"和"背景"是什么关系。读完"现状"，开始读"方案"——他不知道"方案"是怎么从"现状"推导出来的。读完"方案"，开始读"风险"——他更不知道为什么"方案"会引出"风险"。

这种文档读起来像四篇独立的文章拼在一起——每节自洽，但节与节之间断了。

**加了过渡句之后**：

```
1. 背景
2. 现状（在背景所述的市场环境下，我们当前的产品有 X 个问题）
3. 方案（针对现状中的 X 个问题，我们提出以下方案）
4. 风险（实施这个方案可能遇到的风险包括 A、B、C）
```

读者读完每一节，他知道"下一节是什么、为什么是下一节"。他不需要自己拼图。

**过渡句有两种写法**：

第一种是"承接式"——上一节讲了什么，下一节接着讲。

> 上一节我们讲了为什么要做这个项目。这一节我们讲目前项目面临的核心问题。

第二种是"推导式"——从上一节的结论推导出这一节。

> 上一节我们确认了核心问题是 X。这一节我们针对 X 提出三种候选方案。

两种都可以，看场景。"承接式"用于"叙述推进"，"推导式"用于"逻辑推进"。技术文档里"推导式"更常见——每一步都是从前一步的结论推出来的。

## 六、反例：时间顺序不是结构

最后一个反例，关于"时间顺序"。

很多人写文档，会自然地按时间顺序组织："过去发生了什么""现在我们在做什么""未来我们要做什么"。

时间顺序不是结构——**时间顺序是"事情发生的顺序"，结构是"读者理解的顺序"**。

两者经常不一样。

举个反例。某个项目的"立项文档"，作者按时间顺序写：

```
1. 立项时间：2024 年 3 月
2. 项目背景：当时市场上 X 类产品供给不足
3. 项目目标：填补市场空白
4. 团队组建：2024 年 5 月完成
5. 当前进展：核心功能已完成 80%
6. 未来规划：2024 年底上线
```

读者读完这六节，他知道了"时间线"，但他**不知道这个项目为什么要做、做了有什么价值、风险是什么**。

按"读者理解的顺序"重写：

```
1. 项目目标：填补 X 类产品市场空白
2. 现状分析：当前供给不足，需求方有 Y 个未满足场景
3. 方案：我们要做的是 Z
4. 当前进展：核心功能已完成 80%，预计 Q4 上线
5. 风险：包括 A、B、C 三个
```

读者读完，他从"为什么做"开始，再到"现在做到哪"，再到"有什么风险"。这是一个**决策视角的顺序**，不是时间顺序。

时间顺序适合"日记""回忆录""项目复盘"。**设计文档、立项文档、方案说明**这些"决策类"文档，按时间顺序写是反模式。

## 七、几个常见的"结构坏味道"

讲完结构本身，再列几个常见的"结构坏味道"。这些坏味道读者一般不会告诉你，但他们默默感受到了——他们感受到的"读得累"，多半来自这些坏味道。

**坏味道一：节太多**。

一份 3000 字的文档，分了 8 节。每节约 400 字。读者读每节时脑子里装"这一节是什么"——读 8 节要装 8 个主题。他记不住。

解决：节数 ≤ 5。如果内容多到需要 8 节，考虑拆成两份文档。

**坏味道二：节标题模糊**。

节标题是"现状分析""问题分析""方案设计"——读者光看标题不知道这节要讲什么。

解决：节标题要是"这一节的结论"，不是"这一节的主题"。

反例：

```
1. 背景
2. 现状
3. 方案
```

正例：

```
1. 用户增长停滞，新获客成本上升 30%
2. 现有渠道效率低，自有渠道占比 < 20%
3. 三个优化方案：渠道扩张、内容运营、付费投放
```

读者扫正例的标题就知道"哦，要讲增长问题、渠道问题、解决方案"。

**坏味道三：每节字数差不多**。

"背景" 500 字，"现状" 500 字，"方案" 500 字，"风险" 500 字——读者不知道哪节是重点。

解决：主节篇幅长、辅节篇幅短。**决策类文档，"方案"那一节应该占整篇的 30-40%**——这是你希望读者重点读的部分。如果"方案"只占 20%，说明你把重点写错了地方。

**坏味道四：节内段落长度均匀**。

每段都四五句，没有长短变化——读者读起来没有"节奏感"，不知道哪段是重点。

解决：**主段落长（5-8 句），辅段落短（1-3 句）**。短段落是"路标"或"小结"，长段落是"展开"。这种节奏让读者一眼看出"哪里是重点"。

**坏味道五：突然冒出新主题**。

读到第三节，突然出现一个第一节、第二节都没提过的概念——读者懵了。

解决：**每节只讲和它名字相关的内容**。如果非要引入新概念，要在引入时显式说明"这个概念是新的，意思是 X"。

## 八、心法：结构不是你的，是读者的

讲到这里，把这一章的逻辑串成一条线：

读者的注意力是有限的资源（4±1 个 chunk）。结构清晰的本质，是**帮读者分配注意力**。

三种基本结构（递进、并列、对比）足以描述任何文档的逻辑骨架。

段首句是段内的路标——读者扫一眼就知道这一段在讲什么。

过渡句是节间的路标——读者读完上一节就知道下一节是什么关系。

时间顺序不是结构，决策视角的顺序才是。

最后一条心法：**结构不是你的，是读者的**。

你写文档的时候，脑子里有完整的故事——你从背景讲到方案讲到风险，所有内容你都清楚。但读者没参与你的思考过程，他只能一段一段读。

你的任务是**把脑子里的"网状结构"翻译成读者的"线性路径"**。这条路有起点、有路标、有终点。读者顺着走，就能到达你想到达的地方。

这条路不是你走的那条——你走的是"想到什么写什么"，他要走的是"能跟着走"。

下一章我们讲"论证扎实：把'我想说的'变成'读者信服的'"——这是结构的下一个层次。结构清晰只能让读者"看懂你说的话"，论证扎实让读者"信服你的话"。

## 九、思考题

### 思考题 1：拿一份文档做"路标体检"

找一份你最近写的结构比较长的文档（1500 字以上）。按以下步骤做路标体检：

1. **节标题体检**——每个节标题是不是"结论"而不是"主题"？
2. **段首句体检**——每段的第一句话是不是本段核心论点？
3. **过渡体检**——节与节之间有没有过渡句？过渡句有没有说清"上下节的关系"？
4. **节奏体检**——主段落和辅段落有没有长短区分？

每一项体检写 100-200 字的"体检报告"。

### 思考题 2：把一份"时间顺序"文档改写为"决策顺序"

找一份按时间顺序写的文档（项目周报、月报、立项报告都可以），按"决策视角的顺序"重写。

具体步骤：

1. 先列出这份文档要解决的"决策问题"是什么（不超过 30 字）。
2. 列出读者读完应该带走的 3-5 个判断。
3. 按"决策问题 → 关键判断 → 行动建议"的顺序重写每节。
4. 删掉所有"时间节点"信息（除非时间节点本身是关键判断）。

写完之后对比一下：旧版本读者读完记住什么？新版本读者读完记住什么？

### 思考题 3：分析一段"路标清晰"的文字

找一段你读过的"路标清晰"的技术文章（RFC、官方文档、学术论文都可以）。做一份"路标分析"：

1. 这段文章的节标题是不是"结论式"？
2. 每段的段首句是不是核心论点？
3. 节与节之间的过渡是什么方式（承接式 / 推导式）？
4. 主段落和辅段落的节奏分布是什么？

写一篇 500 字的分析。

### 参考答案

#### 思考题 1 参考答案

做完这道题大部分人会发现：

- **节标题体检**：节标题多是"主题式"——"背景""现状""方案"。读者扫标题不知道内容。
- **段首句体检**：很多段落的段首句是"在过去的一周里""经过讨论""综上所述"——这些不是核心论点，是凑字。
- **过渡体检**：节与节之间没有过渡句。读者读完一节直接跳到下一节。
- **节奏体检**：段落长度均匀，没有"主辅"区分。

标准的"路标坏味道"组合。

改写这份文档的标准动作：

1. **节标题改为"结论式"**。"背景" → "用户增长停滞，新客成本上升 30%"。"方案" → "三个备选方案：渠道扩张、内容运营、付费投放"。
2. **段首句改为"核心论点"**。每段第一句话直接给出本段结论，后面跟支撑。
3. **补过渡句**。每节结尾加一句"下一节我们讲..."，或每节开头加一句"上一节我们确认了...，这一节我们讲..."。
4. **节奏重排**。主段落（5-8 句）和辅段落（1-3 句）按 1:3 比例排布。

我自己的改稿习惯：写完第一稿后做"路标体检"，把每节的段首句单独列出来读一遍。如果段首句连起来是一段通顺的话，说明结构清晰；如果段首句连起来不知所云，说明结构散了。

#### 思考题 2 参考答案

"时间顺序"文档改写为"决策顺序"，关键是问自己一个问题：**"读者读这份文档要做的是什么决策？"**

回答这个问题之后，所有内容按"决策需要"的优先级排：

- 决策需要的核心信息 → 放最前面。
- 决策需要的背景 → 放核心信息之后。
- 决策不需要的细节 → 砍掉。

一个反例：我见过一个项目的"立项报告"，原本按时间顺序写了 6 节。改写后变成 4 节：

- 原"立项时间""团队组建""当前进展" → 砍掉或合并成"项目时间表"一节放最后。
- 原"项目目标""市场背景" → 合并成"项目目标"放第一段。
- 原"方案" → 拆成"现状分析"和"方案设计"两节。
- 原"风险" → 放最后。

新版本读者读完知道"为什么做、怎么做、有什么风险"。旧版本读者读完知道"什么时候发生了什么"——但不知道"我们为什么要做"。

#### 思考题 3 参考答案

路标清晰的文字有三个共同点（这三个共同点都来自"帮读者分配注意力"这个目标）：

1. **节标题是"结论式"**。读者扫标题就知道每节讲什么。RFC 的章节标题几乎全是结论式，例如"3.2 Connection Migration"、"3.3 Stream Multiplexing"——读者扫一眼就知道这一节具体讲什么功能。

2. **段首句是"核心论点"**。读者扫段首句就知道段内讲什么。学术论文尤其如此，几乎每段的段首句都是一个论点。

3. **节间过渡是"推导式"**。读者读完上一节就知道下一节为什么存在。例如 RFC 常常这样过渡："Having established the motivation, we now turn to..."——明确告诉读者"上一节是动机，这一节开始讲实现"。

你的分析应该围绕这三点写（不一定全部涉及，但至少触及两点）。如果你读完只写得出"作者写得很清楚"这种笼统的话，说明你还没把"清晰"拆开来——回到这一章的核心：**结构清晰的本质是帮读者分配注意力**。

## 十、动手练习

### 练习 1：给一份工作文档加"路标"

找一份你最近写的、结构比较长的工作文档（1500 字以上）。按"路标体检"的标准加路标：

1. **改节标题**：把"主题式"标题改成"结论式"标题。
2. **改段首句**：把每段的段首句改成"本段核心论点"。
3. **补过渡句**：在节与节之间补一句过渡句。
4. **调整节奏**：主段落加长，辅段落缩短。

写完之后发给同事，让他读完之后告诉你"这份文档的核心结论是什么"。如果他能说出来，说明路标够了；如果他说不出，说明还要再调。

### 练习 2：把一段"时间顺序"文档改写为"决策顺序"

找一段你最近写的项目周报或进度报告，按"决策顺序"重写。

具体要求：

- 砍掉所有"时间节点"细节（除非时间节点本身是决策依据）。
- 第一节必须是"这份文档要解决的决策问题"。
- 最后一节必须是"读者应该带走的判断"。
- 节数 ≤ 5。

写完之后对比新旧版本，自评：旧版本读者读完能记住什么？新版本读者读完能记住什么？

### 自评标准

**练习 1 自评标准**：

- 同事能用一句话讲出文档核心结论——过关。
- 同事讲不出，但你能指出文档中哪段是核心结论——勉强过关。
- 同事讲不出，你也指不出——没过，重新来。

**练习 2 自评标准**：

- 新版本读者读完知道"这份文档要决策什么"——过关。
- 新版本读者读完知道"为什么这么决策"——优秀。
- 新版本读者读完只记住"什么时候发生了什么"——没过关。

## 十一、小结

这一章的核心论点：**结构清晰的本质是帮读者分配注意力**。

| 概念 | 一句话 |
|---|---|
| 工作记忆容量 | 4±1 个 chunk。读者脑子里同时只能装 4 个左右概念。 |
| 三种基本结构 | 递进、并列、对比。所有文档结构都是这三种的组合。 |
| 段首句 | 必须是本段的核心论点。 |
| 过渡句 | 必须说清"上下节是什么关系"。 |
| 时间顺序 | 不是结构，是"事情发生的顺序"。决策类文档按决策视角排。 |

节标题是结论式、段首句是核心论点、节间有过渡、主辅有节奏——这四条是"路标"的最小集合。

结构不是你的，是读者的。你的任务是把你脑子里的网状结构翻译成读者的线性路径。

下一章讲"论证扎实：把'我想说的'变成'读者信服的'"。结构清晰只能让读者"看懂你说的话"，论证扎实让读者"信服你的话"。

---

> **心法**
>
> 读者脑子里同时只能装 4±1 个 chunk。
>
> 你的任务是把这 4 个 chunk 显式分配给他——节标题是第一层 chunk，段首句是第二层 chunk，过渡句是路标。
>
> 段首句必须是本段核心论点，过渡句必须说清上下节关系。
