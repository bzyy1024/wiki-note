# 08 金字塔原理：从一个核心论点向下展开

> 第二卷·心法篇 第三章

---

## 一、读者说"读起来逻辑不清"的那份文档

去年我帮一个朋友改过他写的一份方案文档。原稿 4000 字，分六节。

我读完跟他说："你这份文档读起来逻辑不清。"

他不服："我每节都讲到了，怎么逻辑不清？"

我说："你读完能复述这份文档的核心论点吗？"

他愣了一下，答不上来。

我又问："你这份文档要解决的核心问题是什么？"

他想了一会儿，答："是关于迁移的。"

"迁移什么？"

"......数据库迁移。"

"迁移到哪？"

"......PostgreSQL。"

"为什么？"

"......读起来更顺。"

我指出了问题：他的文档没有"核心论点"。**所有内容都是并列的——背景、现状、方案、风险、收益、计划——没有哪个是"中心"。**

读者读完不知道作者要说"一个什么判断"——他只看到六个并列的话题。

我给他的建议：**先把"核心论点"提炼出来——一句话告诉读者"我推荐什么、为什么"**。然后所有内容围绕这个核心论点展开。

他试了一下，把核心论点写成："**我们推荐在六个月内将订单库从 MySQL 迁移到 PostgreSQL，理由是性能、可维护性、合规性三个维度。**"

然后把所有内容按"性能 / 可维护性 / 合规性"三个维度重组。

改完之后，他自己读了一遍，反馈："哦，原来是这样。"——他自己之前都没意识到自己要说的是什么。

这件事的本质是**金字塔原理**——任何一篇文档都应该有一个清晰的"核心论点"，其他所有内容都是这个核心论点的支撑。

这一章讲金字塔。

## 二、金字塔原理：一个核心论点

金字塔原理是 Barbara Minto 在 1973 年提出的结构化思维工具。它的核心思想：

> **任何一篇文档都应该是"一个中心思想 + 3-7 个分论点 + 每个分论点的论据"的金字塔结构。**

金字塔的形状：

```
            [中心思想]
           /     |     \
        [分论点 1] [分论点 2] [分论点 3]
       / | \      / | \      / | \
    [论据] [论据] [论据] [论据] [论据] [论据]
```

每一层都是下一层的"概括"，下一层都是上一层的"支撑"。

**关键约束**：

- **一个中心思想**：整篇文档只能有一个核心判断。所有内容必须围绕这个判断。
- **3-7 个分论点**：分论点数 ≤ 7。超过 7 个读者记不住。
- **每个分论点 3-7 个论据**：论据数 ≤ 7。同样是认知容量限制。
- **纵向关系**：上层是下层的概括，下层是上层的支撑。
- **横向关系**：同一层的论点之间要 MECE（互斥 + 完备）——下面单独讲。

读者读金字塔结构的文档，他每读一层都能"概括"出上一层——这让他读完能复述。

举个例子。

假设你要写一篇文档推荐"团队采用 GitOps"。金字塔结构：

```
[中心思想] 我们应该采用 GitOps，理由是部署可靠性、可观测性、回滚效率三个维度。

[分论点 1] GitOps 提升部署可靠性
  - 部署过程全自动化，减少人为错误（论据）
  - 部署前自动验证，提前发现问题（论据）
  - 部署历史全记录，便于审计（论据）

[分论点 2] GitOps 提升可观测性
  - 部署状态可实时查询（论据）
  - 配置变更可追溯（论据）
  - 异常情况自动告警（论据）

[分论点 3] GitOps 提升回滚效率
  - 回滚操作秒级完成（论据）
  - 回滚后可继续迭代（论据）
  - 回滚过程不中断服务（论据）
```

读者读完，他能复述出"作者要推荐 GitOps，理由三个：可靠性、可观测性、回滚"——这就是金字塔结构的力量。

## 三、自上而下 vs 自下而上

金字塔有两种写法：**自上而下** vs **自下而上**。

**自上而下**：先想核心论点，再想分论点，再想论据。

适用场景：你的核心论点已经清楚，要把它"展开"。

具体做法：

1. 写出核心论点（一句话）。
2. 列出支撑核心论点的分论点（3-7 个）。
3. 对每个分论点列出论据（3-7 个）。
4. 检查结构：纵向（支撑关系）、横向（MECE）。

**自下而上**：先想论据，再归纳成分论点，再提炼核心论点。

适用场景：你还没想清楚核心论点，但有很多素材。

具体做法：

1. 把所有论据写出来——事实、数据、案例、观察。
2. 把论据按"相似性"分组（3-7 个一组）。
3. 对每组论据归纳一个分论点（这一步是"归纳"）。
4. 对所有分论点归纳一个核心论点（这一步是"提炼"）。

两种写法的关系：

- **自上而下**是"演绎"——从结论往下推。
- **自下而上**是"归纳"——从材料往上抽。

大部分人习惯"自下而上"——他们先想一堆材料，再归纳。但写作时建议**自上而下**——因为读者读金字塔结构是从上往下读的。

我自己的习惯：**先用自下而上收集素材，再用自上而下组织结构**。先用 10 分钟倒关键词（自下而上），再用 20 分钟写金字塔（自上而下）。

## 四、MECE 原则：相互独立、完全穷尽

金字塔的横向关系有 MECE 约束——**M**utually **E**xclusive, **C**ollectively **E**xhaustive（相互独立、完全穷尽）。

- **相互独立**：同一层的论点之间不重叠。
- **完全穷尽**：所有论点加起来覆盖了上层论点的全部支撑。

MECE 的反例。

**反例一：不独立**。

```
[中心思想] 我们应该重构订单服务

[分论点 1] 重构能提升性能
[分论点 2] 重构能提升可维护性
[分论点 3] 重构能提升代码可读性
```

"可维护性"和"代码可读性"重叠——可读性是可维护性的子集。

**正确做法**：

```
[分论点 1] 重构能提升性能（运行效率）
[分论点 2] 重构能提升可维护性（修改成本）
[分论点 3] 重构能提升可扩展性（新增功能成本）
```

三个维度：性能 / 可维护性 / 可扩展性。它们之间独立。

**反例二：不穷尽**。

```
[中心思想] 项目失败的原因

[分论点 1] 技术方案有问题
[分论点 2] 团队协作有问题
```

漏了"市场需求"——可能项目失败是因为产品没市场。

**正确做法**：列出所有可能的原因，确保加起来覆盖"项目失败"的所有维度。

MECE 的检查方法：

- **独立性**：同一层的两个分论点，能不能出现"既是 A 又是 B"的情况？如果能——不独立。
- **穷尽性**：上层论点能不能被这些分论点完全支撑？如果不能——不穷尽。

MECE 是金字塔质量的关键。**不 MECE 的金字塔，读者读完会有"漏了什么"或"重复了"的感觉**。

## 五、序言的结构：SCQA

金字塔的顶端是"核心论点"。但核心论点之前，读者需要"背景"——为什么这个问题值得讨论？

经典的"序言"结构是 SCQA：

- **S**ituation（情境）：读者熟悉的背景。
- **C**omplication（复杂性）：情境中出现的矛盾。
- **Q**uestion（问题）：因为复杂性带来的核心问题。
- **A**nswer（答案）：核心论点作为答案。

SCQA 的逻辑：先讲读者熟悉的背景 → 引入复杂性 → 提出问题 → 给出答案（核心论点）。

举一个例子。

```
[S] 我们的订单服务运行在 MySQL 上已经三年。
[C] 但 QPS 上升到 5000 之后，MySQL 的查询延迟开始升高，最近一个月出现了 5 次 P1 事故。
[Q] 我们应该怎么办？
[A] 我们应该将订单库迁移到 PostgreSQL——性能、可维护性、合规性三个维度都更优。
```

读者读完序言，已经知道"情境是什么、问题是什么、作者的答案是什么"——他有了"上下文"，可以开始读正文。

**SCQA 的反例**：

- 跳过情境：直接讲答案——读者不知道"为什么要听这个"。
- 跳过问题：直接讲答案——读者不知道"作者在回答什么"。
- 跳过答案：讲了 S、C、Q 但不给 A——读者期待落空。

## 六、怎么用金字塔改造现有文档

如果你有一份"散"的文档，按以下步骤改造成金字塔结构：

**步骤一：列出所有论点**。

把文档里的所有主要论点（包括分论点和论据）列出来。

**步骤二：识别核心论点**。

问自己："这份文档要表达的核心判断是什么？"——用一句话回答。

如果答不上来——这份文档没核心论点，需要先提炼。

**步骤三：识别分论点**。

核心论点下面应该有几个分论点支撑。检查你的论点列表，把所有"分论点"挑出来（3-7 个）。

**步骤四：检查 MECE**。

分论点之间相互独立吗？加起来完全穷尽吗？

如果不独立——合并或拆开。
如果不穷尽——补漏。

**步骤五：分配论据**。

每个分论点下面挂几个论据。检查每个论据是不是真的支撑这个分论点。

**步骤六：重组文档**。

按金字塔结构重组——核心论点先讲（结论先行），然后分论点 1、分论点 2、分论点 3，最后论据。

**步骤七：补序言**。

用 SCQA 结构补一段序言，让读者进入上下文。

七个步骤做完，你的文档就是金字塔结构。

## 七、反例：为什么"并列堆叠"不是金字塔

举一个反例，演示"并列堆叠"和"金字塔"的差距。

**反例：并列堆叠**。

```
[背景]
[现状]
[问题]
[方案]
[风险]
[收益]
```

这是"通用模板"——六个并列的话题。

读者读完，不知道作者的核心论点是什么——他只看到六个话题。

**正例：金字塔**。

```
[核心论点] 推荐 X 方案，理由三点：性能、可维护性、合规性。

[分论点 1] X 方案在性能上更优
  - 数据 1
  - 数据 2

[分论点 2] X 方案在可维护性上更优
  - 数据 1
  - 数据 2

[分论点 3] X 方案在合规性上更优
  - 数据 1
  - 数据 2

[风险] X 方案有两个风险：迁移成本、团队学习成本。
```

读者读完知道"作者推荐 X，理由三点"。金字塔让作者的核心论点显式可见。

"并列堆叠"和"金字塔"的本质区别：

- **并列堆叠**：所有话题是"主题"，没有"判断"。
- **金字塔**：所有内容围绕"一个判断"展开。

判断式标题是金字塔的核心——上一章讲过，这里再强调一次。

## 八、金字塔的局限

讲完金字塔的优点，也要讲它的局限。

**局限一：金字塔假设读者已经认同"问题值得讨论"**。

如果读者根本不知道"为什么要讨论这个问题"，金字塔不解决——你需要先讲"情境"。

SCQA 解决这个局限——它把"情境"放在金字塔之前。

**局限二：金字塔假设读者会按顺序读**。

如果读者跳读，金字塔会被破坏——他可能读到分论点 3，没读到核心论点。

这意味着**核心论点要重复**——开头讲一次，每节开头再讲一次，最后结尾再讲一次。让跳读的读者也能拿到核心论点。

**局限三：金字塔不适合"探索型"文档**。

如果文档本身是"探索"——作者还不知道结论——金字塔不适用。

这种情况下，应该用"日记式"或"复盘式"——按时间顺序写，把"探索过程"展示出来。

**局限四：金字塔假设内容是"论证型"**。

如果文档是"叙事型"（讲一个故事）、"教程型"（教一个技能）、"综述型"（扫一个领域），金字塔要变形——不能死板套用。

金字塔的"原型"是论证型文档。其它类型文档用金字塔时要做调整。

## 九、心法：金字塔的本质是"判断 + 支撑"

讲到这里，把这一章的逻辑串成一条线。

**金字塔的本质是"判断 + 支撑"**：

- 顶端是"判断"——这篇文档要说什么。
- 下面是"支撑"——为什么这么说。

判断式标题、SCQA、MECE、自上而下——这些技法都是为了让"判断 + 支撑"清晰可见。

我自己的写作习惯（金字塔版本）：

1. **先写核心论点**——一句话讲"这篇文档要说什么"。
2. **再写 SCQA**——情境、复杂性、问题、答案。
3. **再写分论点**——3-7 个，每个是"判断"。
4. **再写论据**——每个分论点 3-7 个论据。
5. **检查 MECE**——独立性 + 完备性。
6. **按金字塔写正文**——核心论点先讲，然后分论点 1、2、3，最后论据。
7. **核心论点重复三遍**——开头、分论点转换处、结尾。

这个习惯让我的文档"结构清晰度"提升一个档次。

下一章讲"模块化思维：每个章节是自洽的小宇宙"——金字塔的下一个层次。读完你会理解为什么有的章节单独抽出来也能读懂。

## 十、思考题

### 思考题 1：提炼一份文档的核心论点

找一份你最近写的文档（1500 字以上）。按本章方法做：

1. 用一句话回答"这份文档要表达的核心判断是什么"——写下来。
2. 列出所有"分论点"（3-7 个）。
3. 列出每个分论点的论据。
4. 检查 MECE——分论点之间相互独立吗？加起来完全穷尽吗？

写完之后对比：你原来的文档结构和你提炼出来的金字塔结构差距在哪？

### 思考题 2：用 SCQA 写一段序言

拿"思考题 1"那份文档，按 SCQA 结构重写序言：

- **S**（情境）：读者熟悉的背景。
- **C**（复杂性）：情境中出现的矛盾。
- **Q**（问题）：因为复杂性带来的核心问题。
- **A**（答案）：核心论点作为答案。

写完之后自评：读者读完序言，知道"作者要说什么"吗？

### 思考题 3：分析一份"金字塔结构"的文档

找一份你读过的"金字塔结构明显"的文档（学术论文、官方 RFC、技术博客都可以）。做一份"金字塔分析"：

1. 这份文档的核心论点是什么？（一句话）
2. 分论点有几个？分别是什么？
3. 每个分论点的论据是什么？
4. 分论点之间 MECE 吗？
5. 这份文档"金字塔感"强在哪？

写一篇 500 字的分析。

### 参考答案

#### 思考题 1 参考答案

大部分人做完这道题会发现：**自己原来的文档结构和自己提炼出来的金字塔结构差距很大**。

最常见的差距：

- 原来文档有 6-8 节，但金字塔只有 3-4 个分论点——原来的"节"太多。
- 原来文档每节字数差不多，但金字塔有主有辅——原来的"主次"不清。
- 原来文档的节标题是主题式，但金字塔的标题是判断式——原来的"判断"没显式化。

改写方法：

1. 列出所有原来的节，挑出"分论点"。
2. 砍掉 / 合并不在金字塔里的节。
3. 把每节改写成判断式标题。
4. 调整篇幅——主分论点多写，辅分论点少写。

我自己的改稿经验：**"散"的文档大都是"金字塔没建好"**。金字塔建好了，文档自然不散。

#### 思考题 2 参考答案

大部分人写完 SCQA 之后会发现：**自己原来的序言要么太长、要么太短、要么缺一个环节**。

最常见的 SCQA 错误：

- 跳过情境：直接讲"问题"——读者没准备好。
- 跳过问题：直接讲"答案"——读者没期待答案。
- 答案太长：核心论点用一段话讲——读者记不住。

正确的 SCQA 应该是"四句话"——S 一句、C 一句、Q 一句、A 一句。A 就是核心论点那一句话。

我自己的习惯：**序言不超过 100 字**——四句话讲完 S、C、Q、A。读者读完 100 字就进入上下文。

#### 思考题 3 参考答案

"金字塔结构明显"的文档有四个共同点：

1. **核心论点显式可见**。读者读完第一段就知道作者要说什么。
2. **分论点 MECE**。3-7 个分论点，之间相互独立，加起来完全穷尽。
3. **判断式标题**。每个分论点的标题是一个判断，不是主题。
4. **核心论点重复**。开头、分论点转换处、结尾都重复核心论点。

你的分析应该围绕这四点写（不一定全部涉及，但至少触及两点）。如果你读完只写得出"作者结构清楚"——回到这一章的核心：**金字塔的本质是"判断 + 支撑"**。

## 十一、动手练习

### 练习 1：把一份文档提炼为金字塔

找一份你最近写的、写得"散"的文档（1500 字以上）。按以下步骤提炼为金字塔：

1. 用一句话回答"这份文档要表达的核心判断是什么"。
2. 列出 3-7 个分论点。
3. 对每个分论点列 3-7 个论据。
4. 检查 MECE。
5. 按金字塔结构重写文档。

写完之后发给同事，让他读完讲出"核心判断"。如果能——过关；如果不能——回到第 1 步，重新提炼核心判断。

### 练习 2：用 SCQA 写一段 100 字以内的序言

拿"练习 1"那份文档，按 SCQA 结构写一段不超过 100 字的序言：

- S 一句。
- C 一句。
- Q 一句。
- A 一句。

写完之后自评：读者读完这 100 字，能讲出"作者要说什么"吗？

### 自评标准

**练习 1 自评标准**：

- 核心判断能用一句话讲出来——硬性指标。
- 分论点 ≤ 7 个——硬性指标。
- 同事能用一句话讲出文档核心判断——硬性指标。

**练习 2 自评标准**：

- 序言 ≤ 100 字——硬性指标。
- 包含 S、C、Q、A 四个环节——硬性指标。
- 读者读完能讲出"作者要说什么"——硬性指标。

## 十二、小结

这一章把"金字塔原理"讲清楚了：

| 概念 | 一句话 |
|---|---|
| 金字塔结构 | 一个中心思想 + 3-7 个分论点 + 每个分论点的论据。 |
| 自上而下 | 先核心论点，再分论点，再论据。 |
| 自下而上 | 先论据，再归纳分论点，再提炼核心论点。 |
| MECE | 相互独立 + 完全穷尽。 |
| SCQA | 情境、复杂性、问题、答案——序言的四要素。 |
| 心法 | 金字塔的本质是"判断 + 支撑"。 |

**金字塔的本质是"判断 + 支撑"**——顶端是判断，下面是支撑。

判断式标题、SCQA、MECE、自上而下——这些技法都是为了让"判断 + 支撑"清晰可见。

下一章讲"模块化思维：每个章节是自洽的小宇宙"——金字塔的下一个层次。读完你会理解为什么有的章节单独抽出来也能读懂。

> **心法**
>
> 任何一篇文档都应该是"一个判断 + 支撑这个判断的内容"。
>
> 判断显式可见——核心论点用一句话讲出来。
>
> 支撑 MECE——分论点相互独立、加起来完全穷尽。
>
> 核心论点重复三遍——开头、分论点转换处、结尾。
