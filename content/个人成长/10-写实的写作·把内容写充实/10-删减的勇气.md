# 10 删减的勇气：知道什么不要写

> 第二卷·心法篇 第五章

---

## 一、那个"舍不得删"的下午

去年我做过一次艰难的删稿。

任务是给公司年刊写一篇 8000 字的技术综述。我花了三周时间，写了 12000 字。编辑让我砍到 8000 字——意味着我要删掉 4000 字。

我打开文档，从头读到尾。

每读一段我都想："这段不能删，写了三小时。"
读到下一段："这段也不能删，是关键转折。"
再下一段："这段是引子，删了读者进不去。"
再下一段："这段是案例，没案例读者不信。"
再下一段："这段是延伸，删了显得不完整。"

最后我花了六个小时，删了 800 字——还差 3200 字。

我找编辑请教。编辑说："你每段都'不能删'，是因为你在保护自己，不是在保护读者。你觉得删了显得你'写得少'、'准备不足'。但读者要的是'内容到位'，不是'字数多'。"

他又说："换个思路——假装你是读者，假装你时间有限只能读 8000 字。你想让读者读哪 8000 字？"

我换了个思路。从头读，每一段问自己："如果我只能读 8000 字，这一段我会读吗？"

很多段我答"不会"。那些段被我砍了。

四小时内我砍完 4000 字，剩下的 8000 字每一段都是"我会读的"。

这件事让我意识到：**写得长容易，写得短难**——难的不是"删"，是"判断什么该删、什么该留"。

这一章讲删减。

---

## 二、为什么"写得长容易，写得短难"

写得长容易，因为：

- **不用做取舍**：每个想法都可以写下来。
- **不用做判断**：不用决定"哪个更重要"。
- **有沉没成本**：已经写的内容舍不得删。

写得短难，因为：

- **要做取舍**：每个想法都要判断"该不该写"。
- **要做判断**：决定"哪个更重要"。
- **要承受代价**：删的内容可能是你花了几小时写的。

删稿的痛苦本质上和"丢弃代码"一样——你写的每段话都是你的"作品"，删掉它意味着你"没产出"。

但反过来——**没删掉的废话才是"没产出"**。读者读完一堆废话，他什么也没带走，那才是真的没产出。

## 三、删减的三条原则

删减有三条原则。删之前用这三条原则做判断。

**原则一：删掉"读者能自己想到"的内容**。

读者读完某段，他自己就能推出结论——这段就是"读者能自己想到"的内容，删掉。

反例：

> "在微服务架构中，服务之间的调用是通过 RPC 完成的。RPC 的特点是..."

读者读完"服务之间的调用是通过 RPC 完成的"，他自己能推出"RPC 是核心"。下面那段"RPC 的特点是..."他自己能想到——你不用讲。

正例：

> "我们的服务间调用走 RRPC（自研 RPC 框架），每个 RRPC 调用的平均耗时是 50ms。"

只讲"用什么"和"具体数据"——"RPC 的特点"留给读者自己推断。

**原则二：删掉"重复的"内容**。

同一段话里说过两遍、或者前后两段话说过同样的事——这是"重复"，删掉。

反例：

> "我们要做这件事。这件事很重要。这件事必须做。"

三句说同一件事——保留第一句，后两句删掉。

正例：

> "我们要做这件事——因为它是 X。"

只讲一件事。

**原则三：删掉"次要的"内容**。

一份文档有"主要论点"和"次要论点"。次要论点占的篇幅应该比主要论点少——如果次要论点的篇幅和主要论点一样，甚至更多，那次要论点删掉。

判断"主要 vs 次要"：用上一章的"决策视角 / 读者视角 / 价值视角"——支持决策的、支持读者判断的、价值最大的，是主要论点。其他都是次要论点。

## 四、删减的具体技法

三条原则之外，还有四个具体技法。

**技法一：砍段**。

整段没贡献——删。

判断方法：把这一段的段首句抽出来，看它是不是"本段核心论点"。如果段首句不贡献核心论点，删。

举例：

> "接下来我们讲 PostgreSQL 在我们场景下的具体表现。"
>
> "PostgreSQL 在我们的场景下表现优异。具体来说，QPS 从 200 提升到 1500，P99 延迟从 800ms 降到 120ms，错误率从 0.1% 降到 0.01%。"
>
> "这三个指标的提升对我们的业务意义重大。"

第一段是过渡——删。
第三段是修辞——删。
保留第二段——它是核心数据。

**技法二：砍句**。

一句话没贡献——删。

判断方法：每个句子做"删除实验"——第二章讲过。删了意思不变，就是 L1 或 L2，删。

举例：

> "在我们的压测中，我们测试了 PostgreSQL 在 1000 并发下的性能。我们发现 PostgreSQL 的 QPS 达到了 1500。"

第一句"在我们的压测中，我们测试了 PostgreSQL 在 1000 并发下的性能"——是铺垫，可以删。

改成：

> "PostgreSQL 在 1000 并发下的 QPS 达到了 1500。"

只保留核心数据。

**技法三：砍词**。

一个词没贡献——删。

判断方法：每个词读一遍，问"这个词删了意思变吗？"。

举例：

> "我们的系统在**很大程度**上提升了性能。"

"很大程度"——删了意思不变（"我们的系统提升了性能"意思一样）。

> "我们的系统**在性能、稳定性、可维护性三个方面**都提升了。"

"在性能、稳定性、可维护性三个方面"——具体维度，保留。

**技法四：砍节**。

整节没贡献——删。

判断方法：把这一节的核心论点抽出来，问"这一节是不是支持全文核心论点"。如果不支持——删或合并到附录。

## 五、删减的反模式：砍过头

讲完删减的正面，也要讲删减的反面——**砍过头**。

砍过头有三种典型。

**反模式一：砍到过度**。

> 原文："PostgreSQL 在 1000 并发下的 QPS 是 1500。"
>
> 砍后："PostgreSQL 在并发下表现好。"

过度砍——具体数字没了，读者不知道"好到什么程度"。

**判断标准**：砍完之后读者还能不能"信服你的判断"。如果不能——砍过头了。

**反模式二：砍错了内容**。

> 原文："PostgreSQL 比 MySQL 快（1500 QPS vs 200 QPS）。但 PostgreSQL 比 MySQL 难运维（运维人员需要学习新技能）。"
>
> 砍后："PostgreSQL 比 MySQL 快。"

砍错了——砍掉了"反例"（运维难度）。读者读完不知道"还有代价"。

**判断标准**：砍的时候是不是砍了"反例""让步""反驳"这类内容。如果是——可能砍错了。

**反模式三：不敢砍**。

> 原文："总之，我们要做这件事。这件事很重要。我们要努力。我们要加油。"

看着是"删减后的版本"，但还有"总之""加油"这种废话——不敢砍。

**判断标准**：删减后的版本还有没有 L1 / L2。有的话——继续砍。

## 六、几个常见的"舍不得删"

讲完删减的原则和技法，再列几个常见的"舍不得删"。

**舍不得一："这段话我写了很久。"**

这是沉没成本在作怪。你花了三小时写这段话，你不愿意承认"这三小时是浪费的"。

但反过来——**你花了三小时写这段话，正是它该删的理由**。如果你花了三小时才写出来，读者读完也要花三小时——读者没那么多时间。读者花三小时读一段话，他应该带走"三小时的信息量"；你花了三小时写一段话，它应该传递"三小时的信息量"。

**舍不得二："这段话读者可能感兴趣。"**

你不知道读者对什么感兴趣——除非你做过调研。

默认假设：读者只对他"要做决策"的内容感兴趣。其他内容他不感兴趣——不管你觉得多有趣。

**舍不得三："这段话领导可能要看。"**

领导要看的内容 ≠ 你应该写的内容。

领导要的是"决策依据"，不是"全面铺陈"。你把决策依据写清楚（数据、方案、风险），领导就够看了。其他内容领导不会看——写了也是浪费。

**舍不得四："这段话不写显得我不专业。"**

你用"专业感"代替"内容"——你写一堆术语、引用、案例，只是为了让读者觉得你"懂"。

但"专业"不是"装"出来的。**专业是"解决问题"——你帮读者做了决策，你就是专业的**。读者读完你的文档做了决策，他会觉得你专业。读者读完你的文档没做任何决策，他会觉得你"装"。

**舍不得五："这段话是我想到的，不写出来可惜。"**

你想到的 ≠ 读者需要的。

读者需要的是"帮他做判断"的内容。你想到的可能是"对世界的好奇"——读者不需要为你的好奇买单。

## 七、心法：删减是"读者优先"的体现

讲到这里，把这一章的逻辑串成一条线。

**删减的本质是"读者优先"**——你站在读者的角度，决定什么该写、什么不该写。

写得长是"作者视角"——作者想说的都写下来。
写得短是"读者视角"——读者需要的才写下来。

写作者的本事不是"会写"，是"会删"。

我自己的删稿习惯（精炼版）：

1. **写完第一稿**——不要在第一稿做删减。第一稿是给自己看的，"放开来写"。
2. **通读一遍**——逐段问"如果我只能读全文的 30%，这一段我会读吗？"
3. **砍掉"不会读"的段**——通常砍掉 30-50% 的篇幅。
4. **回头补 L4**——砍完之后剩的内容密度上升，但 L4 可能减少。在关键节点补 1-2 个洞察。
5. **最后通读**——再次做"删除实验"，确认 L1 = 0、L2 ≤ 5%。

这个习惯让我大部分文档最终篇幅是初稿的 60-70%——但读者读完带走的判断更多。

写作者的本事是**"知道自己不写什么比知道自己写什么更重要"**。

下一章讲"留白的力量：少即是多，但不是少就是多"——删减的下一个层次。读完你会理解"留白"和"偷懒"的区别。

## 八、思考题

### 思考题 1：拿一份文档做"30% 砍稿挑战"

找一份你最近写的 1500 字以上的文档。按本章方法做"30% 砍稿"：

1. 通读一遍，每段标"会读 / 不会读"。
2. 砍掉所有"不会读"的段——目标砍 30% 篇幅。
3. 砍完后回头补 1-2 个 L4 洞察。
4. 最后做"删除实验"——确认 L1 = 0、L2 ≤ 5%。

写完之后对比：旧版本读者读完带走的判断是什么？新版本读者读完带走的判断是什么？

### 思考题 2：识别一段"舍不得删"的段落

找一段你最近写的、舍不得删的段落。按以下步骤分析：

1. 这段的核心论点是什么？
2. 这段的核心论点是支持全文核心论点吗？
3. 这段的核心论点是 L1 / L2 / L3 / L4 哪一层？
4. 如果删了它，读者会失去什么判断？

写一篇 300 字的"舍不得删"分析。

### 思考题 3：分析一段"删减得当"的文档

找一段你读过的"删减得当"的文档——比如某个写得极简的技术博客、某本写得好的书的一章。做一份"删减分析"：

1. 这份文档砍掉了什么？
2. 它怎么决定"砍什么、留什么"？
3. 它"删减得当"在哪？
4. 你能从中学到什么？

写一篇 500 字的分析。

### 参考答案

#### 思考题 1 参考答案

大部分人做完这道题会发现：**30% 砍稿不难——很多文档有 30% 是废话**。

最常见的"废话"：

- 过渡段（"接下来我们讲..."）——读者已经知道接下来要讲什么。
- 修辞段（"这件事非常重要"）——读者知道重要不重要由他判断。
- 重复段（前面讲过的内容又讲一遍）——读者读完会烦。

砍完之后回头补 L4——在关键节点加 1-2 个洞察。补 L4 的方法：每段问自己"读者读完应该带走什么判断"，把这个判断写出来。

我自己的经验：30% 砍稿后文档的"读者反馈"会更好——读者读完带走的判断更多。

#### 思考题 2 参考答案

大部分人分析完会发现自己"舍不得删"的段落通常是 L1 或 L2——根本没贡献。

几个常见的"舍不得删"模式：

- "这段话我写了很久" → 沉没成本，砍。
- "这段话读者可能感兴趣" → 你不知道读者需要什么，砍。
- "这段话领导可能要看" → 领导不需要这个，砍。
- "这段话显得我专业" → "装专业"是反模式，砍。
- "这段话是我想到的" → 你的好奇不是读者的需求，砍。

我自己的经验：**"舍不得删"往往是"该删"**。你舍不得，是因为这段话对你有情感价值（你写的、你想的、你花的时间）；但对读者没有信息价值。

#### 思考题 3 参考答案

"删减得当"的文档有三个共同点：

1. **每一段都有 L3 或 L4 贡献**。没有"废话"段——每段要么传递事实，要么传递洞察。
2. **过渡和修辞极简**。过渡不"勾引"读者，修辞不"装饰"内容。
3. **结构直接**。核心论点开门见山，分论点直接展开，不绕弯。

你的分析应该围绕这三点写（不一定全部涉及，但至少触及两点）。如果你读完只写得出"作者写得简洁"——回到这一章的核心：**删减的本质是"读者优先"**。

## 九、动手练习

### 练习 1：给一份文档做"30% 砍稿挑战"

找一份你最近写的 1500 字以上的文档。按以下步骤做：

1. 通读一遍，每段标"会读 / 不会读"。
2. 砍掉所有"不会读"的段——目标砍 30% 篇幅。
3. 砍完后回头补 1-2 个 L4 洞察。
4. 最后做"删除实验"——确认 L1 = 0、L2 ≤ 5%。

写完之后发给同事，让他读完之后讲"这份文档的核心判断"。如果能讲出——过关；如果讲不出——回到大纲，重新组织。

### 练习 2：识别"舍不得删"的段落并砍掉

找一段你最近写的、舍不得删的段落。按以下步骤分析并砍掉：

1. 这段的核心论点是什么？
2. 这段的核心论点是支持全文核心论点吗？
3. 这段的核心论点是 L1 / L2 / L3 / L4 哪一层？
4. 如果删了它，读者会失去什么判断？

写一篇 300 字的"舍不得删"分析。如果分析结果是"该删"——把它删掉。

### 自评标准

**练习 1 自评标准**：

- 砍掉 30% 篇幅——硬性指标。
- 同事能用一句话讲出文档核心判断——硬性指标。
- L1 = 0、L2 ≤ 5%——硬性指标。

**练习 2 自评标准**：

- 分析结果指出"该删"——过关。
- 真的把它删了——硬性指标。
- 删完之后文档没受影响——硬性指标。

## 删减检查清单（实战）

写完一稿，过这条清单，比凭感觉"觉得还能删"准：

1. 有过渡段吗？（"接下来我们讲…"）有就砍——读者知道接下来讲啥。
2. 有修辞段吗？（"这件事非常重要"）有就砍——重不重要读者判。
3. 有重复段吗？（前面讲过又讲一遍）有就砍——读者会烦。
4. 每段标"会读/不会读"，砍掉所有"不会读"的——目标 30%。

**砍稿前后对照**

> 砍前："总之，我们要做缓存。缓存很重要。它能提速。我们要重视缓存建设。具体来说，我们在读路径加一层 Redis，把热点数据…"
> 砍后："读路径加一层 Redis 做缓存，把热点命中率从 60% 提到 95%，数据库压力降一半。"

砍前 50 字，砍后 38 字，信息却从"空"变"实"——因为砍掉了"总之/重要/要重视"三句废话，留下了具体动作和数据。这就是删减的本质：不是字数少，是 L1/L2 归零。

**删减与重写的配合。** 砍是"减"，但有时一段不是该砍，是该"换位置"——它支撑的是另一个论点。所以删减完做一镒"归位"：每段问"我到底在支撑谁"。支撑全文核心的留下，支撑别处的挪走，都不支撑的砍。这比盲目砍更准。

**一个容易忽略的点**：删减完密度上去了，但 L4（洞察）可能丢。所以第 4 步之后要"回头补 L4"——在关键节点加 1-2 个"读者读完该带走的判断"。砍是减法，补洞察是加法，两件事分开做，文章才既紧又深。

## 十、小结

这一章把"删减"讲清楚了：

| 概念 | 一句话 |
|---|---|
| 三条原则 | 删掉"读者能自己想到"、删掉"重复"、删掉"次要"。 |
| 四个技法 | 砍段、砍句、砍词、砍节。 |
| 反模式 | 砍过头、砍错、不敢砍。 |
| 五个"舍不得删" | 写久了、读者可能感兴趣、领导可能要看、显得专业、我想到的。 |
| 心法 | 删减是"读者优先"的体现。 |

**删减的本质是"读者优先"**——你站在读者的角度，决定什么该写、什么不该写。

写作者的本事不是"会写"，是"会删"。

**知道自己不写什么，比知道自己写什么更重要**。

> 写得长是"作者视角"——作者想说的都写下来。
>
> 写得短是"读者视角"——读者需要的才写下来。
>
> 知道自己不写什么，比知道自己写什么更重要。
>
> 写作者的本事不是"会写"，是"会删"。
