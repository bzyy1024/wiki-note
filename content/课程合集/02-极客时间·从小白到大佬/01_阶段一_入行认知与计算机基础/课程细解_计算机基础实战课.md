## 一、这门课到底讲什么

很多「计算机基础」课只是画个冯·诺依曼结构图就完事，这门课不一样——它让你**亲手写一颗 CPU**：从硬件描述语言（Verilog）到指令架构（RISC-V），一步步实现取指、译码、执行、访存、写回五级流水线，最后跑通 Hello World。

学完这条主线，再往上层走：C 语言、内存、进程、文件系统、浏览器原理，你会发现全部「通了」。

## 三、必须吃透的核心知识点

1. **五级流水线**：CPU 不是「做完一条再做下一条」，而是像流水线一样同时处理多条指令的不同阶段。取指、译码、执行、访存、写回五个阶段并行——这是 CPU 能「每秒几十亿条指令」的根本原因。

2. **虚拟内存**：每个程序都以为独占一整块内存，其实是操作系统用「页表」把虚拟地址映射到物理地址。这正是阶段一《内存知识》要深入的主题，两门课互为表里。

3. **进程调度**：为什么你同时开浏览器、听歌、写代码，感觉它们在「同时」跑？因为 CPU 在极短的时间片里快速切换进程。

4. **内功心法（第 40–41 讲是精华）**：内核和后端通用的设计思想——分层、抽象、缓存、异步。学完你会发现「Linux 内核」和「你的后端服务」用的是同一套设计哲学。

## 四、引发思考

1. RISC 和 CISC 的本质区别？为什么手机（ARM，RISC）和服务器（x86，CISC）走了不同路线，现在又在「精简」上殊途同归？
2. 手写 CPU 时，「译码」模块到底在做什么？为什么说它是「把 0/1 翻译成动作」的关键？
3. 虚拟内存解决了哪两个问题？（隔离 + 超卖）没有它，多进程会怎样？
4. 堆和栈的区别，除了「大小、方向」，在「分配速度」和「生命周期」上还有什么本质不同？
5. 浏览器为什么用「多进程」而不是「多线程」？（一个标签页崩溃不拖垮整个浏览器）
