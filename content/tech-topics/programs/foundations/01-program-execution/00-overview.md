---
前置知识: 无
难度: ⭐⭐

关键词: 编译, 链接, 装载, 执行, 程序生命周期

## 引入场景

你每天写Go代码，`go run main.go`，程序就跑起来了。但你有没有想过：从你写下的文字到CPU执行的电信号之间，究竟发生了什么？

这不只是好奇心。理解这个过程，能帮你：
- 读懂编译错误和链接错误
- 理解为什么Go二进制文件比较大
- 明白程序崩溃时的堆栈信息
- 做出更好的性能优化决策


### 四个阶段

| 阶段 | 做什么 | 输入 | 输出 |
|------|--------|------|------|
| **编译** | 将源代码翻译为机器指令 | `.go`/`.c` 源文件 | `.o` 目标文件 |
| **链接** | 将多个目标文件组合、解析符号引用 | `.o` 目标文件 + 库 | 可执行文件 |
| **装载** | 将可执行文件映射到内存 | 可执行文件 | 进程内存映像 |
| **执行** | CPU逐条执行指令 | 内存中的指令 | 程序运行结果 |

## 对话探索

**问题1：为什么不能一步完成？为什么要分成编译、链接、装载三步？**

💭 思考方向：
- 一个项目有很多源文件，全部重新编译效率如何？
- 标准库的代码（如fmt.Println），你需要每次都编译吗？
- 程序运行前，操作系统需要做什么准备？

📖 参考答案：
分步是为了**效率和灵活性**：

1. **编译独立化**：每个文件单独编译为`.o`文件。修改一个文件只需重编译那一个
2. **链接复用化**：标准库预先编译好，链接时直接使用。不必每次重新编译
3. **装载延迟化**：程序可能很大，但不需要全部加载到内存。操作系统只加载当前需要的部分

这是"分层"和"延迟计算"思想的经典应用——后面在theory层会深入讨论。

---

**问题2：Go的 `go build` 命令，内部执行了上面的哪些步骤？**

💭 思考方向：
- `go build` 输出的是什么文件？
- Go有链接步骤吗？
- `go run` 和 `go build` 有什么区别？

📖 参考答案：
`go build` 内部完整执行了**编译 + 链接**两大步骤：

```
go build main.go
  ├─ 1. 解析依赖：找出所有需要的包
  ├─ 2. 编译：每个包编译为目标文件
  ├─ 3. 链接：将所有目标文件链接为一个可执行文件
  └─ 4. 输出：生成最终的可执行二进制文件
```

`go run` 则多做一步——编译链接后直接执行（装载 + 运行）。

---

**问题3：你每天写的Go程序，编译后大概几MB，但C程序可能只有几KB。为什么差这么多？**

💭 思考方向：
- Go默认是静态链接还是动态链接？
- Go运行时（runtime）包含哪些东西？
- C的"Hello World"为什么可以很小？

📖 参考答案：
Go默认**静态链接**，把所有依赖（包括Go运行时）都打包进去：

- **Go运行时**：goroutine调度器、垃圾收集器、内存分配器等，约几MB
- **标准库代码**：你import的每个包的代码
- **无外部依赖**：不依赖系统的libc等动态库

而C的Hello World可以动态链接libc，自身只需要几KB。

这是**部署简单性 vs 文件大小**的权衡——Go选择了"编译一次，到处运行"。

## 小结

⭐ **核心要点**：
1. **四个阶段**：源码 → 编译 → 链接 → 装载 → 执行，每步都有明确的职责
2. **分步的意义**：效率（增量编译）、复用（预编译库）、灵活（按需加载）
3. **Go的特点**：`go build` = 编译 + 链接，默认静态链接，二进制大但部署简单
