书名：《非暴力沟通》

> 说明：以下拆解基于常见版本与公开认知整理，如与原书细节有出入，以原书为准。

# 1. 这本书适合谁看
适合在亲密关系、家庭、团队、管理场景中经常出现误解与冲突的人。

# 2. 一句话讲清这本书
冲突常来自“评价与指责”，而有效沟通来自“观察-感受-需要-请求”。

# 3. 作者到底想解决什么问题
作者要解决“明明在沟通，为什么越说越伤人”的问题，强调从攻击与防御转向连接与合作。

# 4. 全书核心框架
1. 观察：描述事实，不夹评价。
2. 感受：说出真实情绪，不做道德审判。
3. 需要：识别情绪背后的未满足需要。
4. 请求：提出具体可执行请求。
5. 共情倾听：先理解，再表达。

# 5. 核心观点详细拆解
## 观点一：区分观察与评价
1) 观点是什么：只说发生了什么，不贴标签。
2) 为什么对：标签会触发防御。
3) 容易误解的地方：以为“直言”就是评价。
4) 现实中怎么用：把“你总是”改成“这周有三次”。
5) 例子："你不负责"改为"这份文档截止前未提交"。

## 观点二：感受背后是需要
1) 观点是什么：情绪是信号，不是敌人。
2) 为什么对：识别需要才有解决路径。
3) 容易误解的地方：把感受当指责工具。
4) 现实中怎么用：先说“我感到…因为我需要…”。
5) 例子："我焦虑，因为我需要确定性"。

## 观点三：请求要具体且可选择
1) 观点是什么：清晰请求比模糊期待有效。
2) 为什么对：对方知道如何回应才可能合作。
3) 容易误解的地方：把命令当请求。
4) 现实中怎么用：给时间、动作、标准。
5) 例子："今天18点前给我两种方案草稿，可以吗？"。

# 6. 最重要的方法、模型或步骤
NVC对话四步：
1. 观察事实。
2. 表达感受。
3. 说明需要。
4. 提出可执行请求。

# 7. 普通人最容易忽略的关键点
- 把“我觉得你…”当感受表达。
- 忽视倾听，只忙着反驳。
- 请求不具体，结果无法执行。

# 8. 把这本书真正用起来
- 学习：小组讨论先复述对方观点。
- 工作：反馈时先事实，再影响，再请求。
- 关系：冲突时先连接情绪，再谈方案。
- 决策：分歧会议中显式区分需求层与方案层。
- 自我提升：每天记录一次NVC改写练习。

# 9. 30 分钟内的快速复盘版
非暴力沟通不是“说好听话”，而是把攻击式表达改成连接式表达。看事实、说感受、讲需要、提请求，冲突就更容易变合作。

# 10. 适合分享给别人的金句 / 重点句
- 评价让人防御，观察让人理解。
- 愤怒常是未被看见的需要。
- 请求越具体，关系越清晰。
- 倾听不是同意，是先理解。
- 沟通的目标是连接，不是压赢。

## 学习建议
从一个高频冲突场景开始，连续两周用NVC四步改写表达。每次对话后复盘：哪一步最容易漏，下一次如何补上。
