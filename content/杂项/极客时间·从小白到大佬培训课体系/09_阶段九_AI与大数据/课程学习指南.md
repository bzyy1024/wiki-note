# 阶段九 · 课程学习指南

> 本阶段按「AI 认知 → 机器学习 → 深度学习 → 推荐系统 → NLP → 大模型应用 → 大数据 → 数据分析 → 云计算」组织。★ 为必学主干。

# 一、AI 认知

## 1. 人工智能基础课 ★（第一门，AI 全景）

**为什么学**：AI 名词满天飞（机器学习、深度学习、神经网络、大模型……），这门课帮你建立正确的 AI 全景认知——AI 能干什么、不能干什么、原理大概是什么。先有地图，再上路。

**知识地图**：
- AI 发展史与三次浪潮
- 机器学习：监督/无监督/强化学习
- 深度学习与神经网络直觉
- 计算机视觉、NLP、语音
- 推荐系统、搜索
- AI 的边界与伦理

**经典案例**：小白问「深度学习是不是万能？」老师：**「不是。深度学习擅长『从大量数据里找模式』——看图、听声、翻译、推荐。但它在『逻辑推理』『小样本学习』『可解释性』上很差。你让 AI 判断『明天该不该买这只股票』，它只能说『基于历史规律，涨的概率是 60%』，不能替你负责。理解 AI 的边界，比理解 AI 的能力更重要。」**

**引发思考**：
1. 监督学习、无监督学习、强化学习各是什么？各举一个业务例子。
2. 「AI 会取代什么工作」——你的判断标准是什么？（规律性 vs 创造性）
3. 为什么说「数据是 AI 的燃料」？没有高质量数据，模型能好吗？

## 2. 王天一人工智能基础课 / 零基础 GPT 应用入门课（选学，视角与上手）

**为什么学**：王天一的课偏「机器学习的数学与原理直觉」（适合想深究的人）；GPT 入门课则教「零基础怎么用上大模型」（适合快速上手 AI 应用的人）。

**知识地图**（GPT 入门课）：
- 大模型是什么、能做什么
- Prompt 提示词工程入门
- 用 API 接入 GPT 做应用
- AI 写作、办公、编程助手实践
- 大模型应用的局限与合规

**经典案例**：小白问「提示词（Prompt）还有学问？」老师：**「同样的模型，`写一份周报` 和 `你是技术负责人，请用表格形式写一份周报，包含：本周进展、风险、下周计划，语气简洁专业`——输出质量天差地别。Prompt 工程不是玄学，是『把需求说清楚的艺术』：给角色、给结构、给约束、给示例。」**

**引发思考**：
1. 大模型是「搜索引擎」吗？本质区别是什么？（生成 vs 检索）
2. 你工作中哪些场景适合用大模型提效？哪些不适合？（涉及隐私、需要精确计算）
3. 为什么说「懂业务的人 + Prompt 能力 = 超级个体」？

# 二、机器学习

## 3. 零基础实战机器学习 ★（必学，ML 动手入门）

**为什么学**：机器学习是所有 AI 的地基。这门课从「机器学习是什么」讲到「用 Python 跑通常用算法」，案例驱动、代码可运行，是 ML 入门的最佳选择。

**知识地图**：
- 机器学习流程：数据 → 特征 → 模型 → 评估 → 部署
- 特征工程：缺失值、归一化、特征选择
- 经典算法：线性回归、逻辑回归、决策树、随机森林、KNN、聚类
- 模型评估：训练集/测试集、交叉验证、准确率/精确率/召回率/F1
- 过拟合与欠拟合、正则化
- 用 scikit-learn 实战

**经典案例**：小白训练了「预测房价」模型，训练集准确率 99%，测试集只有 70%——典型的过拟合。老师解释：**「模型把训练数据『背下来了』，而不是『学会了规律』。解决：加正则化、交叉验证、换更简单的模型、增加数据。机器学习 80% 的精力花在『防止模型作弊』上，而不是调参。」**

**引发思考**：
1. 过拟合的本质是什么？「泛化能力」为什么是 ML 的灵魂？
2. 精确率和召回率的区别？什么业务更看重精确率（垃圾邮件？），什么更看重召回率（癌症筛查？）
3. 特征工程为什么比调参更重要？（Garbage in, garbage out）
4. 你身边有没有「可以用机器学习解决」的问题？数据从哪来？

## 4. AI 应用实战课（选学，AI 工程落地）

**为什么学**：ML 课教你「训模型」，这门课教你「把模型做成产品」——模型服务化、上线、监控、迭代，补齐「AI 工程化」的短板。

**知识地图**：
- 模型的部署：REST API、模型服务框架
- 模型的版本管理与更新
- 线上推理的延迟与成本优化
- 模型的监控（数据漂移、效果退化）
- AI 产品的全流程（需求→数据→模型→上线→迭代）

**经典案例**：小白问「模型上线后效果变差了怎么办？」老师：**「这叫『数据漂移』——线上数据的分布和训练时不一样了（比如用户行为变了）。所以要监控：输入分布、预测分布、业务指标。发现漂移就重新训练。AI 工程不是『训完就完』，是『持续运营』：数据在变，模型就得跟着变。」**

**引发思考**：
1. 模型服务化要注意什么？（延迟、吞吐、显存/内存、并发）
2. 「数据漂移」怎么监测？有什么信号？
3. 一个 AI 功能的 ROI 怎么算？怎么判断它值得做？

# 三、深度学习

## 5. 深度学习应用实践 60 讲 ★（必学，DL 实战）

**为什么学**：深度学习是当前 AI 的主流技术（图像、语音、NLP 全靠它）。这门课以「应用 + 案例」驱动：从神经网络直觉、反向传播，到 CNN、RNN、Transformer，再到实际项目，60 讲覆盖 DL 工程全流程。

**知识地图**：
- 神经网络基础：神经元、激活函数、损失函数
- 反向传播与梯度下降直觉
- 卷积神经网络（CNN）：图像识别、目标检测
- 循环神经网络（RNN/LSTM）：序列建模
- Transformer 与注意力机制
- 训练技巧：学习率、正则化、BatchNorm、早停
- 项目实战：图像分类、文本分类等

**经典案例**：小白问「为什么深度学习能识别猫？」老师：**「神经网络里，前面的层学『边缘、纹理』，中间层学『形状、部件』，后面的层学『猫的概念』——像搭积木一样层层抽象。CNN 用『卷积』在图像上滑动提取局部特征，参数共享让模型又好又省。听懂这个『层层抽象』，你就理解了深度学习的全部直觉。」**

**引发思考**：
1. 为什么需要激活函数？（没有非线性，再多层也等价于一层）
2. 过拟合在深度学习里更严重，你会用哪些手段？（Dropout、数据增强、早停……）
3. Transformer 的「注意力机制」是什么直觉？为什么它取代了 RNN？
4. 训练一个模型 GPU 不够怎么办？（云 GPU、蒸馏、量化……）

## 6. PyTorch 深度学习实战 / TensorFlow 快速入门与实战 / TensorFlow2 项目进阶实战（选学，框架掌握）

**为什么学**：框架是 DL 的「操作工具」。PyTorch 是学术与工业最流行的框架（大模型全家都用它）；TensorFlow 是谷歌系框架（工业部署生态强）。**二选一主学 PyTorch**（推荐），TensorFlow 了解即可。

**知识地图**（PyTorch）：
- Tensor 与自动求导（autograd）
- 构建模型：nn.Module
- 数据加载（DataLoader）
- 训练循环：loss、optimizer、反向传播
- 模型保存与加载
- 实战：图像分类、文本分类、简单生成

**经典案例**：小白问「为什么 PyTorch 里定义一个模型那么简单？」老师：**「因为 `autograd` 自动帮你算了梯度——你只管定义前向计算（forward），反向传播和求导 PyTorch 全包了。这比手写反向传播（当年研究生要算一整页数学）友好一万倍。框架的本质，是把『又难又重复』的部分包起来，让你专注『模型设计』。」**

**引发思考**：
1. 自动求导（autograd）是怎么实现的？（计算图 + 链式法则）
2. GPU 和 CPU 训练差多少？你的代码怎么利用 GPU？（.cuda() / .to(device)）
3. 训练损失不降了，你会怎么调试？（学习率？数据？模型结构？）

# 四、推荐系统

## 7. 推荐系统三十六式 ★（必学，推荐全景）

**为什么学**：推荐系统是「算法 + 工程」结合最紧密的领域——电商、短视频、新闻、音乐全在用。这门课从推荐的本质（信息过滤）讲到召回、排序、冷启动、实时推荐，是进入推荐领域的最佳入口。

**知识地图**：
- 推荐系统的价值与评估指标（CTR、转化率、覆盖率）
- 召回（Recall）：协同过滤、基于内容、向量召回
- 排序（Rank）：LR、FM、深度学习排序
- 冷启动问题与解决方案
- 实时推荐与特征工程
- 推荐系统架构与工程化

**经典案例**：小白问「为什么抖音总能推我喜欢看的？」老师：**「推荐 = 召回 + 排序两步。召回：先从 10 亿个视频里快速捞出 1000 个候选（基于你的历史行为 + 相似用户 + 相似视频）；排序：用模型给这 1000 个打分，挑出你最可能点的那 20 个。你看，推荐不是『猜你喜欢』，是『海选 + 精排』的工业流水线。」**

**引发思考**：
1. 协同过滤（UserCF / ItemCF）的原理？为什么新用户/新物品会失效（冷启动）？
2. 召回和排序为什么要分开？合在一起行不行？（计算量）
3. 评估推荐系统：除了点击率，为什么还要看「多样性」「新鲜度」？
4. 推荐系统有没有「信息茧房」问题？产品上怎么缓解？

---

## 8. 深度学习推荐系统实战 / 手把手带你搭建推荐系统（选学，深度与实战）

**为什么学**：前者的核心是「深度学习如何做推荐」（Embedding、Wide&Deep、双塔模型）；后者是「从 0 搭一个推荐系统」（数据处理、召回、排序、接口）。按需选，动手做一遍才真懂。

**知识地图**（手把手搭建）：
- 数据集处理（MovieLens / 电商数据）
- 构建召回（协同过滤 / 向量召回）
- 构建排序模型（LR / FM / DNN）
- 推荐接口与在线服务
- 效果评估与调优

**经典案例**：小白搭的推荐系统只会推「热门」，个性化不强。老师：**「热门推荐（全局 TopN）是保底，真正的个性化靠『用户向量 × 物品向量』：把用户和物品都映射成向量，相似度高的就推。这就是 Embedding——深度学习推荐的基石。你写的这个双塔模型，就是今日头条、YouTube 推荐系统的简化版。」**

**引发思考**：
1. Embedding（嵌入向量）是什么直觉？为什么相似的用户/物品向量会「挨得近」？
2. 双塔模型为什么适合大规模召回？（离线算物品向量，在线算用户向量）
3. 你的推荐系统怎么处理「新用户没有任何行为」？（冷启动策略）

# 五、NLP

## 9. NLP 实战高手课（选学，自然语言处理）

**为��么学**：NLP 是 AI 应用最广的方向（搜索、翻译、客服、舆情、大模型底座）。这门课覆盖 NLP 全流程：分词、词向量、文本分类、序列标注、NER、文本生成，以及大模型时代的 NLP 变化。

**知识地图**：
- NLP 基础：分词、词性标注、句法
- 词向量：Word2Vec、Embedding
- 经典任务：文本分类、情感分析、命名实体识别（NER）
- 序列模型：RNN、LSTM、Transformer
- 预训练模型：BERT 及其应用
- 大模型时代的 NLP 应用

**经典案例**：小白问「为什么 '苹果' 在不同句子里意思不同？」老师：**「传统词向量给每个词一个固定向量，'苹果' 只有一个向量，分不清水果还是公司。BERT 解决了这个：它在『上下文』里动态生成每个词的向量——'苹果发布了新手机' 里的苹果，和 '我吃了一个苹果' 里的苹果，向量完全不同。这就是『上下文相关表示』，也是大模型的底层能力。」**

**引发思考**：
1. 词向量为什么能捕捉语义相似？（分布假设：相似词出现在相似上下文）
2. BERT 和 GPT 的核心区别？（双向编码 vs 单向生成）
3. 你能用大模型 API 做一个什么 NLP 应用？（分类、抽取、对话……）

# 六、大模型应用（最热方向）

## 10. AI 大模型之美 ★（必学，LLM 应用启蒙）

**为什么学**：这是通往「大模型应用开发」的入口课。它带你理解大模型的能力边界、Prompt 工程、以及怎么把大模型接进真实应用（文本、图像、Agent 雏形），并动手跑通一系列小项目。

**知识地图**：
- 大模型原理直觉（Transformer、预训练 + 微调）
- Prompt 工程进阶：思维链、Few-shot
- 函数调用（Function Calling）
- 文本生成、总结、翻译应用
- 多模态（文生图）入门
- 大模型应用的工程化（上下文管理、成本控制）

**经典案例**：小白问「为什么大模型有时会『一本正经胡说八道』？」老师：**「大模型是『预测下一个词』的机器，它追求『像人说的话』，不保证『事实正确』——这就是幻觉。解决：① RAG（检索增强生成）：先从知识库检索真实资料，再让模型基于资料回答；② 约束输出；③ 人工复核。你后面学 RAG，就是给模型『装上知识的骨架』。」**

**引发思考**：
1. 大模型的「幻觉」为什么无法根治？业务上怎么规避？（高价值场景必须 RAG + 人工兜底）
2. 上下文窗口（Context Window）是什么？超了怎么办？（截断/摘要/向量检索）
3. 为什么说「大模型应用的核心竞争力是数据与场景，不是模型本身」？

## 11. LangChain 实战课 ★（必学，LLM 应用框架）

**为什么学**：LangChain 是当下最火的 LLM 应用开发框架——把「模型、Prompt、工具、记忆、知识库」串成流水线，是 RAG 应用、Agent 开发的主流工具。学了它，你就能做出真正的 AI 产品。

**知识地图**：
- LangChain 核心概念：Chain（链）、Agent（代理）、Tool（工具）
- Prompt 模板与输出解析
- 模型接入（OpenAI/国产模型）
- RAG 全流程：文档加载、切分、向量化（Embedding）、检索、生成
- 记忆（Memory）：对话历史管理
- Agent 与 Function Calling：让模型调用工具
- 实战：客服机器人、知识库问答、AI 写作助手

**经典案例**：小白做了一个「公司知识库问答机器人」，直接让模型回答，结果各种瞎编。老师带着用 RAG 重写：**「① 把文档切成小块；② 用 Embedding 模型转成向量存进向量数据库；③ 用户提问时，先把问题转成向量，检索出最相关的文档片段；④ 把片段 + 问题一起给大模型，让它『基于资料回答，资料没有就说不知道』。回答准确率从 60% 提到 95%。这就是 RAG——让大模型学会『查资料再说话』。」**

**引发思考**：
1. RAG 的四个环节（加载/切分/检索/生成）各自有什么优化空间？
2. 文档切分（Chunk）的大小为什么影响效果？（太大检索不精确，太小上下文缺失）
3. Agent 和普通 Chain 的区别？什么时候该用 Agent？（需要多步决策 + 调用工具）
4. 你会怎么评估一个 RAG 系统的回答质量？（检索命中率？生成准确率？）

## 12. Dify 开发·AI Agent 进阶实战 / AI 大模型系统实战 / AI 大模型企业应用实战（选学，平台与系统）

**为什么学**：Dify 是「可视化 LLM 应用平台」（低代码搭 RAG/Agent/工作流）；AI 大模型系统实战讲「大模型背后的系统」（推理服务、部署、优化）；企业应用实战讲「企业怎么落地大模型」（私有化、安全、场景）。按方向选。

**知识地图**（Dify）：
- Dify 平台：应用编排、知识库、工作流
- 可视化搭建 RAG 应用
- Agent 工作流（多步、分支、工具调用）
- 插件与发布
- 从原型到上线

**经典案例**：小白问「代码写 RAG 好累，有没有更快的方式？」老师：**「Dify 拖拽就能搭：上传知识库 → 配置模型 → 设置检索参数 → 发布，20 分钟做出一个客服机器人。它把 LLM 应用工程化、平台化了——适合快速验证和交付。但记住：平台是『省事』，底层原理（向量化、检索、上下文）还是得懂，不然调优无从下手。」**

**引发思考**：
1. 低代码平台（Dify）和手写（LangChain）怎么取舍？（速度 vs 灵活性）
2. 企业私有化部署大模型要考虑什么？（算力、数据安全、合规）
3. 一个「AI 大模型系统」要支撑高并发调用，瓶颈在哪？（显存、推理延迟、成本）

## 13. AI 绘画核心技术与实战（选学，AIGC 创作）

**为什么学**：文生图（Stable Diffusion 等）是 AIGC 最火的赛道之一。学它，你理解扩散模型原理、会用工具出图、能把它接进产品（电商图、设计稿、内容创作）。

**知识地图**：
- 文生图原理直觉：扩散模型（去噪过程）
- Stable Diffusion 生态：模型、LoRA、ControlNet
- Prompt 工程（图）
- 工作流：生成、修复、放大、风格化
- 商业应用（电商、设计、营销）

**经典案例**：小白用 SD 生成商品图，总是不尽如人意。老师教 ControlNet：**「用线稿/姿态/深度图『控制』生成结果——产品图、模特姿势、构图全部可控。加上 LoRA 微调出品牌专属风格。AI 绘画不是『碰运气出图』，是『精确控制 + 批量生产』的工业化流水线。」**

**引发思考**：
1. 扩散模型「从噪声中生成图像」的直觉是什么？
2. AI 生成内容的版权问题怎么看？（训练数据、生成物的版权归属）
3. 你所在行业，有哪些内容可以用 AIGC 降本增效？

# 七、大数据

## 14. 从 0 开始学大数据 ★（必学，大数据全景）

**为什么学**：单机处理不了的数据量（TB/PB 级），需要大数据技术栈。这门课讲透大数据生态——Hadoop、HDFS、MapReduce、Spark、Hive、数据仓库，建立大数据世界观。

**知识地图**：
- 大数据的 4V：Volume、Velocity、Variety、Value
- Hadoop 生态：HDFS（分布式存储）、MapReduce（分布式计算）
- Hive（SQL 化大数据）
- Spark（内存计算，比 MR 快 100 倍）
- 数据仓库与数据湖
- 实时计算（Flink）
- 大数据架构与案例

**经典案例**：小白问「10 亿条日志怎么统计？」老师：**「一台机器存不下、算不动。HDFS 把数据『切开』存到 100 台机器上，Spark 把计算任务也『切开』分给 100 台机器并行算，最后汇总。这就是『分而治之』——大数据不是『更大的单机』，是『一群机器协作』。你阶段七学的分布式原理，在这里全部兑现。」**

**引发思考**：
1. HDFS 为什么把文件切成块存多份？（容错 + 并行）
2. MapReduce 的 map 和 reduce 各干什么？能举一个词频统计的例子吗？
3. 离线计算（Spark）和实时计算（Flink）分别适合什么业务？（日报 vs 风控）

## 15. 零基础入门 Spark / Spark 核心原理与实战 / Spark 性能调优实战（选学，Spark 系）

**为什么学**：Spark 是大数据计算的「事实标准」。三门按「入门 → 原理 → 调优」递进。主攻大数据方向的话，Spark 必须吃透。

**知识地图**：
- Spark 核心：RDD、DataFrame、Dataset
- Spark SQL 与 Hive 集成
- 流处理（Structured Streaming）
- Spark 运行原理：DAG、Stage、Task、Shuffle
- 调优：内存、并行度、Shuffle 优化、数据倾斜

**经典案例**：小白跑 Spark 任务，一个 10 分钟的任务跑了 2 小时。老师看 Spark UI 一眼定位：**数据倾斜——某个 key 的数据量是其他的 100 倍，所有任务都等这一个慢任务。解决：加盐打散 + 两阶段聚合。老师总结：Spark 调优 80% 的问题就三类——数据倾斜、Shuffle 过大、并行度不足。** 小白：**「性能问题，本质都是『数据分布』问题。」**

**引发思考**：
1. RDD 是什么？「不可变 + 惰性求值」设计解决了什么问题？（容错：血统 Lineage）
2. Shuffle 为什么慢？能避免吗？（宽依赖 vs 窄依赖）
3. 数据倾斜怎么定位、怎么解决？（加盐、广播、两阶段）

# 八、数据分析

## 16. 数据分析实战 45 讲 ★（必学，用数据说话）

**为什么学**：数据分析是「AI 的地基 + 通用职场能力」。学它，你会用 pandas/numpy/SQL 处理数据、用可视化讲故事、用统计思维做决策——这是「数据驱动」的第一步，也是转 AI 的必经之路。

**知识地图**：
- 数据分析流程：问题 → 取数 → 清洗 → 分析 → 结论 → 汇报
- Python 数据三件套：pandas、numpy、matplotlib
- 数据清洗：缺失值、异常值、重复值
- 数据分析方法：对比、分组、漏斗、留存、归因
- 数据可视化与图表选择
- SQL 取数与报表
- 实战案例：用户增长、转化率、流失分析

**经典案例**：老板问「为什么这个月用户流失变高了？」小白拍脑袋：「可能是竞品。」老师带着用数据说话：**「① 拆维度：流失用户集中在哪个渠道？哪个产品模块？② 看时间：流失从哪天开始？那几天发生了什么（发版、活动）？③ 建漏斗：用户在哪个环节流失最多？最后发现：某次版本更新后，注册流程多了一步，转化率掉了 30%。——用数据定位问题，而不是用情绪猜问题。」**

**引发思考**：
1. 「相关性」和「因果性」的区别？怎么避免「因为冰激凌销量高所以溺水多」的坑？
2. 漏斗分析、留存分析、同期群分析（Cohort）各回答什么问题？
3. 你工作中有什么决策是「拍脑袋」的？怎么用数据改进？

## 17. 数据分析思维课（选学，思维升级）

**为什么学**：工具是术，思维是道。这门课讲「数据思维」——怎么提好问题、怎么定指标、怎么看数、怎么用数据说服人，把「会用工具」变成「会做决策」。

**知识地图**：
- 数据思维：先问「要解决什么问题」再取数
- 指标设计：北极星指标、指标体系
- 数据解读：避免幸存者偏差、辛普森悖论
- 数据驱动决策的方法
- 用数据讲故事的技巧

**经典案例**：老师问小白：「日活 100 万，这个数字是好是坏？」小白：「好呀！」老师：**「要看趋势（环比涨跌）、看结构（哪些功能贡献）、看质量（活跃用户是不是机器人）。单点数字没有意义，『对比 + 结构 + 趋势』才有意义。数据思维的第一课：永远问『和什么比』『由什么构成』『往哪变』。」**

**引发思考**：
1. 辛普森悖论是什么？为什么分组看和整体看结论相反？
2. 怎么设计一个业务的「北极星指标」？它和虚荣指标的区别？
3. 你会怎么用数据向老板汇报一个「坏消息」？（先讲结论？先讲故事？）

# 九、云计算

## 18. 深入浅出云计算 / 云计算必修小课（选学，算力底座）

**为什么学**：现代系统几乎都跑在云上。理解云计算（IaaS/PaaS/SaaS、虚拟机、对象存储、弹性计算），你就理解「算力怎么被租用、系统怎么上云」——也是云原生（阶段七）的底座。

**知识地图**：
- 云计算的三种服务模式：IaaS / PaaS / SaaS
- 核心云服务：计算（ECS）、存储（OSS/COS）、数据库、网络
- 弹性伸缩与计费模式
- 公有云 vs 私有云 vs 混合云
- 上云迁移的步骤与坑

**经典案例**：小白问「上云到底省不省钱？」老师：**「看场景。流量波动大（大促）→ 云弹性伸缩省大钱；流量平稳 → 自建机房可能更省。云的本质是『按需付费的算力』——你把固定成本变成可变成本，把运维交给云厂商。但也要小心『云账单爆炸』（忘了关实例、数据出流量费）。上云不是目的，降本增效才是。」**

**引发思考**：
1. 虚拟机、容器、Serverless，三者的抽象层次和适用场景？
2. 对象存储（OSS/COS）和文件系统/数据库的区别？什么数据适合放对象存储？
3. 如果你要把公司的系统迁上云，第一步做什么、最怕什么？
