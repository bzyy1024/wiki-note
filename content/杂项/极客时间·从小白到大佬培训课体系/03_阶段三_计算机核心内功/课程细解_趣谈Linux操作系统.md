## 三、必须吃透的核心知识点

1. **进程 vs 线程**：进程是「资源分配单位」，线程是「调度执行单位」。一个进程多个线程共享内存，但各有各的栈。

2. **进程调度**：Linux 用 CFS（完全公平调度器），核心是「红黑树 + 虚拟运行时间」——让每个进程「公平」地分到 CPU 时间。还记得《数据结构》里的红黑树吗？这里就是它的真实应用。

3. **虚拟内存 + 页表**：每个进程以为独占内存，其实是页表做映射。缺页中断（page fault）是「按需分配」的关键机制。

4. **文件系统分层**：虚拟文件系统（VFS）是抽象层，下面挂 ext4、XFS 等具体实现——「面向接口编程」在系统层的体现。

5. **容器 = Namespace + CGroup**：Namespace 做「隔离」（让容器以为自己是独立系统），CGroup 做「限额」（限制 CPU、内存用量）。理解了这俩，就理解了 Docker 和 K8s 的地基。

## 四、引发思考

1. 进程和线程的本质区别？「上下文切换」为什么贵？
2. CFS 调度器为什么用红黑树，而不是链表或数组？（快速找「最该运行」的进程）
3. 缺页中断是什么？为什么「第一次访问内存」反而慢？
4. 页缓存（page cache）为什么能大幅加速文件读写？和阶段四的「缓存」思想有什么共通？
5. 容器的隔离（Namespace）和虚拟机的隔离，安全性和开销上有什么本质不同？
6. 学完本课，再看 K8s 的「Pod」，你是不是理解了「Pod 是共享 Namespace 的一组容器」？
