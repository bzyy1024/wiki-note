## 一、这门课到底讲什么

这门课的核心方法论是「**点线面网**」：每一讲是一个「点」（一个具体问题），连起来成「线」（如日志系统），再串成「面」（如事务），最后织成「网」（MySQL 全局）。学完你不再是「会用 MySQL」，而是「懂 MySQL 为什么这样设计」。

## 三、必须吃透的核心知识点

1. **redo log 与 binlog（第 2 讲，全课基石）**：redo log 是 InnoDB 的「循环账本」保证崩溃恢复，binlog 是 MySQL 的「归档账本」用于主备复制和恢复。两阶段提交保证两者一致。

2. **MVCC 与一致性视图（第 3、8 讲）**：可重复读靠「快照 + undo log 版本链」实现，读不加锁。理解「事务 id」和「活跃事务数组」就能理解「为什么改了我还看不见」。

3. **B+ 树索引（第 4–5 讲）**：主键索引（聚簇）叶子存整行，二级索引叶子存主键——所以「回表」。覆盖索引、最左前缀、索引下推是三大优化点。

4. **间隙锁与 next-key lock（第 20–21 讲）**：可重复读下用「行锁 + 间隙锁」锁住范围，防止幻读——这就是「只改一行却锁那么多」的原因。

5. **主备一致性（第 24 讲）**：binlog 的三种格式（statement/row/mixed），row 格式保证主备一致。

## 四、引发思考

1. 一条 `update` 语句，从执行到落盘，redo log 和 binlog 各自做了什么？两阶段提交为什么必要？
2. 为什么 InnoDB 用 B+ 树而不是哈希、红黑树？（从「范围查询 + 磁盘 IO + 稳定」三个角度）
3. 哪些写法会导致索引失效？（函数、隐式类型转换、前导模糊、最左前缀破坏……）
4. 「可重复读」下为什么还会出现幻读？间隙锁怎么解决？
5. 主从延迟的原因有哪些？读写分离后「读旧数据」怎么办？
6. 学完本课，回头看阶段三《数据结构》的 B+ 树，是不是「理论照进现实」了？
