## 知识地图

```
                    ┌─────────────────────────────────┐
                    │   理论层 Theory                   │
                    │   "为什么这样设计"                  │
                    │   抽象层次 · CAP定理 · 一致性模型    │
                    └──────────────┬──────────────────┘
                                   │
                    ┌──────────────▼──────────────────┐
                    │   模式层 Patterns                 │
                    │   "怎么解决问题"                   │
                    │   缓存策略 · 分布式锁 · 幂等设计    │

                                   │
                    ┌──────────────▼──────────────────┐
                    │   基础层 Foundations              │
                    │   "计算机如何工作"                  │

                    └─────────────────────────────────┘
```

## 三层融合示例：缓存一致性

同一个问题，在三个层次分别理解：

```
问题：为什么数据库和缓存会不一致？

├─ 基础层：CPU多级缓存如何保持一致？ → foundations/02-memory-addressing/
├─ 模式层：延迟双删、Cache-Aside方案  → patterns/consistency/01-cache-aside.md
└─ 理论层：一致性模型与CAP权衡       → theory/02-consistency-models.md
```

## 教材特色

- **对话式教学**：苏格拉底式提问，先思考再看答案
- **Go语言锚点**：用Go代码验证每一个概念
- **问题驱动**：每个主题从真实场景出发
- **模块化组织**：既能系统学习，也能按需查阅
- **三层贯通**：底层原理 → 工程模式 → 理论思维

## 学习路径

### 阶段一：建立底层认知（2-3周）
程序执行全流程 → 内存与地址 → 并发基础

### 阶段二：掌握工程模式（3-4周）
一致性问题 → 并发控制 → 可靠性设计

### 阶段三：构建理论思维（2-3周）
抽象与一致性 → CAP与共识 → 系统思维

详细路径请查看：[主线学习路径](journeys/01-main-path.md)
