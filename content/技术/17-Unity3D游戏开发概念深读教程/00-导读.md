## 先说一个最重要的学习方法

你提了一个特别对路的要求：不要只记参数，要理解"为什么这样设计"。

这恰恰是学游戏引擎最快的路。绝大多数人卡住，不是因为 `fogDensity` 这个滑块看不懂，而是因为他不知道**雾本来是为了解决什么现实问题才存在的**。一旦你搞清楚"为什么要雾"，那几个参数就自己长出意义了——它们不再是一堆孤立的旋钮，而是一套"用来回答某个问题"的工具。

所以这本教程每一章都固定走这条路径：

```
自然现象  →  现实中遇到的问题  →  工程师拿出的方案  →  方案落进引擎成了哪些参数
```

我管它叫**"溯源学习法"**。你读完任何一章，都应该能回答三句话：

1. 这个东西在现实世界里对应什么？（自然现象）
2. 没有它会出什么岔子？（问题）
3. 引擎给了哪几个旋钮来对付它？（参数 + 调参思路）

把这三句话糊墙上的话，参数表就再也吓不到你了。

## 关于"100 万字够不够"——我的实话

你说"不知道 100 万字是否够用"。我直接给结论：

**对你真正想搞懂的这批概念，15–20 万字就能讲透，而且讲得很扎实。**

100 万字不是不能写，但那往往意味着大量横向铺陈（每个概念的历史渊源、十几种变种、边角案例）。那未必是你现在最需要的。你现在最需要的，是**把"为什么"这条线焊死在脑子里**，然后能把不同概念组合起来解决实际问题。

所以这本教程的做法是：

- 先把**骨架铺全**（原目录 16 章，现已扩到 34 章、十二部分，覆盖坐标 / 像素 / 网格 / 纹理 / 光照 / 摄像机 / 雾化 / 音频 / 视频 / 组件 / 联机登录 / 游戏产品设计 / 图形学深度 / 动手实践）。
- 把你**点名**的概念（坐标、音视频怎么存、雾化）写深写透，绝不灌水。
- 其余章节保持同一套方法和质量，按需扩展。

**质量密度 > 字数。** 宁可一章讲透一个点，也不铺十章水词。

---

## 怎么读这本教程

1. **别跳思考题。** 每章末尾的【思考题】是故意留给你卡壳的。先自己想，再看【参考答案】。参考答案常会从另一个角度再戳你一下。
2. **遇到参数，先问"它对付的是什么问题"。** 这是全书的肌肉记忆训练。
3. **读完几章后，试着自己组合。** 比如"雾化 + 摄像机距离 + 音频衰减"能不能合成一个'雾里追人'的小场景？第 13、14 章会带你做这件事。
4. **允许反复。** 坐标变换、矩阵这类东西，第一次懵是正常的。教程里会反复从不同角度碰它。
