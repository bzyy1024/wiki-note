## 本章要解决的问题

小林在一家做实时数据平台的公司，负责一个 Go 写的流式计算服务。某天凌晨三点，服务开始周期性卡顿——P99 从 8ms 飙到 900ms，持续 40 秒，然后自己恢复。监控上 CPU、内存、GC 全正常。

运维重启了机器，问题消失。一周后又出现。

小林查了一周，把 Go 代码翻了个底朝天，profile 打了几十份，什么都没找到。最后是一个老同事路过说了一句：

> "你这个机器的 NUMA 节点是不是跨了？"

那一刻小林意识到：**他一直在 Go 这一层找问题，但问题在 Go 下面第 4 层。**

这一章，就是要帮你建立那个"第 4 层"的视角。

## 学完这一章，你应该能

1. 画出从 C 源码到 CPU 执行的完整数据流，指出每一步的中间产物是什么。
2. 解释一次 `malloc(8)` 背后，内核态和用户态分别做了什么。
3. 说清楚为什么 false sharing 能让多线程程序慢 5 倍，并写出复现代码。
4. 手写一个能工作的内存分配器，性能达到 glibc malloc 的 60% 以上。
5. 用 Go 实现一个能编译 C 子集（含指针、结构体、函数、控制流）的编译器。
6. 写出一个能从 BIOS 引导、进入保护模式、打印字符的最小内核。
7. 解释 `go build` 出来的二进制文件里，每一个 section 是干什么的。

## 这一章为什么最难

因为它要求你**同时**在四个抽象层级思考：

```
┌─────────────────────────────────────┐
│  层级 4：语言    Go/C 的语义          │  ← 你习惯在这里
├─────────────────────────────────────┤
│  层级 3：运行时  编译器、链接器、ABI    │
├─────────────────────────────────────┤
│  层级 2：OS      虚拟内存、进程、调度   │
├─────────────────────────────────────┤
│  层级 1：硬件    CPU、缓存、总线、MMU  │  ← 问题往往根在这
└─────────────────────────────────────┘
```

大多数工程师只在层级 4 工作，遇到怪问题就束手无策。
能下到层级 2 的人，已经能解决 90% 的疑难杂症。
能下到层级 1 并回来的人，才有资格设计系统。

## 阅读建议

- **不要跳**。这一章的内容是强依赖的，跳过 03 直接看 04 会看不懂。
- **代码一定要跑**。特别是 04 和 06，光看代码没用，跑起来加个 `fmt.Println` 看看中间态。
- **思考题先自己答**。参考答案是"老陈的答案"，不是"标准答案"，你有更好的答案就说明你真的懂了。
