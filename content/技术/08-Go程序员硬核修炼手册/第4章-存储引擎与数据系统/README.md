## 贯穿全章的核心问题

### 问题 1：持久化的本质是什么？

**四个层次：**

```
① 什么都没做
   写内存就返回 → 断电数据丢失

② write() 系统调用
   写到内核的 page cache → 断电还是丢（进程崩溃不丢）

③ fsync()
   刷到磁盘 → 断电不丢（但磁盘可能有自己的缓存，需要 FUA）

④ 复制
   写到多台机器 → 单机故障不丢
```

**每一层都在用性能换持久性。** 这一章你会看到 MySQL、Redis、RocksDB 各自选了哪一层，以及为什么。

### 问题 2：并发读写的本质是什么？

**三种方案：**

| 方案 | 思路 | 代价 |
|:---|:---|:---|
| **锁** | 读加锁，写加锁，互斥 | 并发度低 |
| **MVCC** | 每个事务看到"快照"，读写不冲突 | 存储多版本，需要 GC |
| **串行化** | 所有操作排队 | 最简单，但吞吐低 |

**MVCC 是现代数据库的标准答案。** 它的核心洞察是：

> **"读"和"写"的冲突，可以通过"给每个读者一个快照"来消除。**
>
> 代价是要存多个版本，并且要有机制回收旧版本。

### 问题 3：索引的本质是什么？

**索引回答的是"怎么少读数据"。**

```
无索引:  扫全表 → O(N) 次磁盘 IO
B+Tree:  树高 3-4 → O(log N) 次 IO（16 亿数据只要 3 次）
哈希:    1 次 IO，但不支持范围查询
布隆过滤器: 0 次 IO（如果确定不存在）
```

**每一种索引结构，都是"查询能力"和"维护成本"的权衡。**
