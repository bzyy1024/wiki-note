1. 说出一个算法的**缓存复杂度**（cache complexity），而不只是时间复杂度
2. 遇到新问题，能判断它属于哪种设计范式，以及为什么其他范式不适用

5. 写出 GC 友好的算法实现（避免逃逸、复用对象、利用 `[]byte` 免扫描特性）

## 这一章的核心观点

**数据结构不是"抽象的东西"，它是为存储层次设计的。**

```
CPU 寄存器    ~0.3 ns
L1 缓存       ~1 ns
L2 缓存       ~4 ns
L3 缓存       ~15 ns
主存          ~80 ns      ← 红黑树的一个节点访问
SSD           ~100 μs     ← B+Tree 的一个节点访问
机械硬盘      ~10 ms
网络          ~1-100 ms
```

**每一个数据结构的设计，都在针对某个特定的存储层次做优化：**

- **B+Tree**：节点大小 = 磁盘页大小（4KB/16KB），把树高从 30 降到 3
- **跳表**：用概率平衡代替严格平衡，实现简单且并发友好
- **LSM-Tree**：把随机写变成顺序写，用读放大换写放大
- **布隆过滤器**：用极小的空间快速排除"一定不存在"

**这跟第 1 章讲的缓存行、内存页、NUMA 是一脉相承的——都是"让相关的东西物理上靠近"这条法则的应用。**
