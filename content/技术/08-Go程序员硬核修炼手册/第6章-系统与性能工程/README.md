## 贯穿全章的核心思想

### 思想 1：没有测量就没有优化

这句话被说滥了，但真正做到的人很少。

**反面教材**：第 1 章的小林，查了一周的 P0 事故，因为他假设瓶颈在应用层。

**正确的流程**：

```
① 明确目标（P99 < 50ms？吞吐 > 10万 QPS？）
② 建立基线（现在是多少？）
③ 测量（到底哪里慢？）
④ 定位（瓶颈在哪个组件、哪个函数、哪行代码）
⑤ 优化
⑥ 验证（真的改善了吗？改善了具体多少？）
⑦ 回到 ②（瓶颈会转移）
```

**跳过 ③ 和 ④ 直接做 ⑤，90% 的情况下你在优化一个不是瓶颈的东西。**

### 思想 2：容器的本质不是"轻量虚拟化"

**容器 = 一组 Linux 内核特性的组合**：

```
namespace  → 隔离"看到什么"（视图隔离）
cgroup     → 限制"能用多少"（资源限制）
chroot/pivot_root → 隔离"文件系统"
capabilities → 限制"能做什么"（权限）
seccomp    → 限制"能调哪些系统调用"
```

**容器里的进程就是宿主机上的普通进程**，没有虚拟化层，没有额外的内核。

> 这就是为什么"容器比虚拟机轻"——不是因为"更少的资源"，而是因为**根本没有第二层内核**。
