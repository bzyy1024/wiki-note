## 为什么 Go 程序员要学这些

### 这 5 门课在教什么

不是教 Java 语法，也不是教前端。它们教的是**四个通用的系统设计问题**：

```
①  内存怎么自动回收？          → JVM 的 GC / V8 的 GC / Go 的 GC
②  代码怎么执行？              → JVM 的解释器+JIT / V8 的 JIT / Go 的 AOT
③  动态性怎么实现？            → JVM 的类加载 / V8 的隐藏类 / Go 的 interface
④  并发怎么组织？              → JVM 的线程 / V8 的事件循环 / Go 的 GMP
```

**这四个问题，任何一个"带 runtime 的语言"都要回答。Go 只是给出了它自己的答案。**

### 对照学习的价值

> 你只知道一种做法时，你不知道它是好是坏。
> 你知道三种做法，并且知道它们各自的取舍，你才算懂了。

| 问题 | JVM 的答案 | V8 的答案 | Go 的答案 |
|:---|:---|:---|:---|
| **内存回收** | 分代 + 多种 GC 可选 | 分代 + 增量标记 | 不分代 + 并发三色标记 |
| **代码执行** | 字节码 + 解释 + JIT | 字节码 + 解释 + 多层 JIT | 直接编译成机器码 |
| **动态分发** | 虚方法表 (vtable) | 隐藏类 + 内联缓存 | itab（接口表） |
| **并发** | 1:1 线程 | 单线程事件循环 | M:N goroutine |
| **启动速度** | 慢（JVM 启动 + 类加载） | 快（但要 JIT 预热） | 最快（直接是机器码） |
| **峰值性能** | 最高（JIT 能优化） | 高 | 中（AOT 无运行时信息） |

**看完这张表，你就明白了：Go 的每一个选择都是"用峰值性能换启动速度和确定性"。**

## 一个贯穿全章的问题

**为什么 Go 的 GC 不做分代？**

这是理解 Go runtime 设计哲学的钥匙。

标准答案（Java 视角）：
> 分代假说（Weak Generational Hypothesis）：大多数对象朝生夕死。所以把堆分成新生代和老年代，新生代用复制算法（只复制存活的少数），老年代用标记清除。

Go 的答案：
> **Go 没有分代，因为 Go 大量使用栈分配和值类型，堆上的对象大部分是长期存活的，分代假说在 Go 里不成立。**

**但这个答案引出了更多问题：**
- Go 为什么能大量用栈分配？（逃逸分析）
- Go 的写屏障为什么必须是"混合"的？（因为不分代，没有 Remembered Set）
- Go 的 GC 目标为什么是 1ms 而不是吞吐率？（因为 Go 主要用于在线服务）

**这一章就是要让你能回答这些"为什么"。**
