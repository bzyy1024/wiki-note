## 贯穿全章的核心洞察

### 洞察 1：并发的本质是"协调"

第 1 章我们讲过：单机并发的难题源于"CPU 会抢占"。

分布式系统里，难题源于：

```
① 没有全局时钟   → 无法判断两个事件的先后顺序
② 网络不可靠     → 消息可能丢失、重复、延迟、乱序
③ 节点可能失败   → 而且你无法区分"节点挂了"和"网络慢"
```

**这三点导致：分布式系统里，"现在发生了什么"这个问题无法被精确回答。**

所有的分布式算法（Raft、Paxos、2PC、向量时钟），本质上都是在**用额外的通信和约束，重建一个"可以被推理的顺序"**。

### 洞察 2：本地问题在分布式尺度的重演

你在第 1、3 章学过的很多东西，会在这一章以更大的尺度重现：

| 单机 | 分布式 |
|:---|:---|
| CPU 缓存一致性 (MESI) | 副本一致性（线性/顺序/最终） |
| 内存屏障 | 共识算法 |
| 锁 | 分布式锁 |
| 事务 (ACID) | 分布式事务 (2PC/TCC/Saga) |
| 顺序一致性（内存模型） | 顺序一致性（一致性模型） |

**"让相关的东西物理上靠近"** → **"让计算靠近数据"**
**"层次化缓存"** → **"CDN / 多级缓存"**
**"用约束换性能"** → **"用一致性级别换可用性"**

## 一个提醒

Raft 是这一章的重头戏。**它不是"看懂就行"的东西——你必须自己写一遍，才能理解那些看起来莫名其妙的规则。**

比如："为什么 leader 只能提交当前 term 的日志？"
——看论文你可能觉得"哦，是为了安全"，但自己写一遍，构造出那个反例，你才会真正理解。
