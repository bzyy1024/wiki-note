# 导读：从 Go 老兵到 Python 高级工程师

老哥，先别急着翻第一章。咱们把「为什么写这个、怎么用、以及你该拿什么心态读」这件事说清楚，比直接砸知识点有用。

## 你现在的处境，我门儿清

你写了五年 Go，CRUD、中间件、接口都玩得转，协议层也敢说自己「会用」。Python 呢？能跑，会用 AI 生成脚本，但你说自己「没多深入」——意思我懂：**语法你会，但一碰到「这个特性到底什么时候该用、用了图啥、坑在哪儿」，你就得去搜。**

这其实不是你的问题，是大多数「从编译型语言切过来」的人都会卡的一关。

Go 教会你一套很硬的思维：编译期就给你拦掉一大堆错，类型即文档，goroutine 随手起，error 显式返回逼你面对失败。你带着这身肌肉记忆进 Python，第一反应是「这语言怎么这么松」——类型不强制、报错跑起来才炸、并发像在泥里走路。

但 Python 的「松」不是没脑子，是它的设计哲学跟 Go 不一样。Go 说「显式优于隐式、少即是多」；Python 说「用最少的代码把事办了、可读性即正义、运行时灵活才是生产力」。**两套都对，只是解决不同问题。** 你缺的不是「学语法」，而是把 Python 那套哲学翻译成你能懂的语言——而最好的翻译桥梁，就是你已经会的 Go。

## 这本教程怎么用

24 篇技术章，按六层递进：

1. **语言特性**（第 1–8 章）：思维对撞、类型系统、装饰器、生成器、上下文管理器、函数式工具、数据模型、描述符。这是 Python 的「内功」。
2. **工程化**（第 9–13 章）：包与模块、虚拟环境、配置、异常设计、日志。这是「能进生产环境」的门槛。
3. **并发与性能**（第 14–17 章）：并发全景、asyncio、多线程多进程、性能剖析。这是 Go 老兵最容易高估自己、也最容易踩坑的地方。
4. **数据与标准库**（第 18–20 章）：dataclasses、标准库精读、文件 IO。
5. **测试与质量**（第 21–22 章）：pytest、代码质量流水线。
6. **设计模式与实战**（第 23–24 章）：Python 式设计模式、FastAPI 项目骨架。

**每篇独立成文件，中文字数 4500 上下，技术阅读带思考大约 30 分钟。** 你可以挑着读，但我建议按顺序——后面章频繁引用前面的概念。

## 阅读心态：把 Python 当「另一种武器」，别当「Go 的劣化版」

我见过太多 Go 转 Python 的人，写出来的 Python 全是 Go 味：满屏 `if err != nil` 式的防御、不敢用动态特性、把 duck typing 当洪水猛兽。结果就是「用 Python 写 Go」，既没拿到 Python 的生产力，又丢了 Go 的严谨。

反过来也有坑：把 Python 当脚本胶水，永远停留在「AI 生成 → 跑通 → 完事」，遇到诡异 bug 就懵。

**高级工程师的标志，是你知道每个工具的设计意图和边界。** 所以这本教程里，几乎每章我都会逼你回答三个问题：

- 这个特性**怎么用**？（最小可运行代码）
- **什么场景**该用、什么场景不该用？（边界 + 对照 Go）
- 用了**图啥**，代价是什么？（trade-off）

章末都有【思考题】和【参考答案】。思考题是让你自己先想，参考答案当学习材料看，不是测验——我把答案写详细，是因为你说过「答案当教材」。
