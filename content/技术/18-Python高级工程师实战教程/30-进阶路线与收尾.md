# 第 30 章 进阶路线与收尾：从「会用」到「精通」

老哥，走到这一章，说明 29 篇你至少翻完了。墨叔不跟你整虚的临别赠言，给你一张**能落地的下一步地图**——因为「读完教程」和「能在项目里用得像样」之间，还差三件事：刻意练习、读源码、以及建立自己的判断。

## 一、先确认你卡在哪一层

把 Python 能力分三层，你对着号入座：

- **L1 能跑**：AI 生成脚本，自己改改能跑通。你进门时就在这层。
- **L2 能设计**：知道装饰器/生成器/上下文管理器该用在哪，写完能给同事讲清「为什么这么写」。这是本教程的目标层。
- **L3 能造**：读得动 CPython 源码、能写框架级抽象（描述符、元类、异步调度），出问题能从解释器层面定位。这是「精通」。

本教程把你从 L1 推到 L2 中段。L3 不是靠教程推的，是靠下面三件事。

## 二、三件必须亲手做的事

**1. 把每章的【思考题】真写出来，再对照【参考答案】**
别扫一眼就过。你写的过程，才是把「墨叔讲的东西」变成「你自己的肌肉」。参考答案不是标准答案，是另一种思路——你和它不一致，多半是你漏了某个边界，去翻对应章节补。

**2. 读一个你常用库的源码**
挑一个你项目里用得最熟的：requests、pydantic、sqlalchemy、或者 FastAPI。打开 GitHub，顺着你最常用那个 API 往里读，找本教程讲过的影子：
- 看到 `@property` → 第 8 章描述符；
- 看到 `with` 资源管理 → 第 5 章上下文管理器；
- 看到装饰器堆叠 → 第 3 章；
- 看到 `async def` 满天飞 → 第 15、16 章。

当你能在别人的代码里认出「这是第 X 章讲的 XX」，你就从「用框架」跨到「懂框架」了。这一步，比再读十篇教程都值钱。

**3. 用 Python 重写一个你自己的 Go 小工具**
你五年 Go 攒下的工具/脚本，挑一个（比如日志切割、配置加载、一个简单的 HTTP 中间件），用 Python 重写一版。过程中你会被迫直面差异：没有 goroutine 你怎么处理并发？没有编译期检查你怎么保证类型？重写完，你拥有的不是「又一个 Python 脚本」，而是**两座语言之间的翻译能力**——这才是高级工程师的真正资产。
