# Kubernetes 系统设计者之路

> 一套"从问题入手、看后续演化"的硬核 K8s 系统设计教程。
> 不是 kubectl 使用手册，是把 K8s 当一部活着的系统设计史来拆。
> 对话讨论式，每章带「思考题 + 参考答案」，统一结构：**问题（为什么需要）→ 设计（怎么解的）→ 演化（后来怎么改的）**。

## 读法说明

- 每章结构统一：**问题 → 设计 → 演化**；
- 标记约定：`墨：` 老兵追问，`你：` 预设回答，`🔧 思考题` + `【参考答案】`，`📦 案例`，`⚠️ 坑`；
- 建议顺序：先 `00-序与问题地图.md` 立方法论，再 `03-声明式API与控制循环.md` 立脊椎，之后按需跳读。
- 当前规模：**26 章 + 序/结语**，并持续加硬核专题章（镜像/网格/GitOps/多集群/规模调优/灾备/攻防）向 30 万字目标推进。

## 给你的三个动手动作

1. 本地 `kind`/`minikube` 起集群，故意制造每章讲的故障并排障；
2. 用 kubebuilder 写一个最小 Operator（如 Timer），亲历"造系统的机制"；
3. 用第 19 章的 8 问清单，拆一遍你公司的一个内部系统。
