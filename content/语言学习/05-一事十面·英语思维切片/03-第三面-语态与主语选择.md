# 第三面：语态与主语选择（谁当镜头，谁被藏起来）

> 同一条迁移锁了 `orders` 表，为什么英文能把它讲成"Lin 干了一件事""表被锁了""表出事了"三种完全不同的面孔？中文翻出来却几乎都是"订单表被锁了"。这一面我们拆的不是一个语法点，是一台摄像机的机位。

---

## 1. 开场：三句话，先别往下看

**卡点 1（二选一型，其实是三选一）。**

下面三句，你看完先别往下读。在心里自己答一句：**a 和 b/c 差在哪？b 和 c 又差在哪？** 想三秒，最好出声答一遍。答不上来也算一种答案——那说明中文直觉正在替你兜底，你从没被逼着分过。

```
a. Lin ran a migration that locked the orders table.
b. The orders table got locked.
c. The orders table was locked.
```

中文你大概会这么翻，几乎一模一样：

- a. Lin 跑了条迁移，把订单表锁了。
- b. 订单表被锁了。/ 订单表锁了。
- c. 订单表被锁了。

你看，b 和 c 的中文翻译，基本是一个字都不差。"订单表被锁了"六字，谁都认得出说的是同一件事。a 的中文稍微长一点，但核心还是"订单表被锁"。

**那英文凭什么要给你三种写法？** 而且这三种写法，母语者一眼就能分出"谁在镜头里""谁被藏起来了""这事儿怪谁"。你中文脑子里那六字一句的"订单表被锁了"，根本装不下这三种区别。

先别急。我先把那个你心里大概率已经冒出来的错误答案替你说出来，省得你憋着：

> 八成你刚才想的是："b 和 c 不就是加了个'被'字吗？a 是主动，b/c 是被动，被动就是把主语和宾语颠倒一下，宾语提前，动词前面塞个 be 加过去分词，齐活。"

对。但这只答了"长什么样"，没答"为什么英语要这么折腾"。更要命的是——**你把 b 和 c 当成了一回事，这恰恰是最该分开看的两个东西。** `got locked` 和 `was locked`，中文都译"被锁了"，可镜头里的机位、这事儿的责任指向，完全不是一回事。

这一面，就是把"被字句"这个你以为早就懂了的东西，重新拆给你看。拆完你会明白一句话，这句话是全章的脊梁：

> **语态不是"被"字翻译问题，是镜头焦点问题。主语不是语法主语，是镜头对准的那个人或物。**

a 把镜头架在 Lin 身上，b 和 c 把镜头架在 `orders` 表身上。而 b 和 c 之间，还有一个你绝对想不到的、关于"责任"的细微差别。先记住这个悬念，我们一节一节来。

## 2. 被动的本质：镜头架在谁身上

先问你一个看起来很蠢、其实多数人答错的问题。

**卡点 2（判断对错型）。**

下面这句话对不对？

```
*The book was sold well.
```

你八成会愣一下，然后说"对啊，书被卖得好，被动嘛，book 是被卖的"。

**错。** 这句话语法上是病句。原因我们待会儿在第 5 节讲中动语态时再戳穿它。我先拿它当引子，问你另一件事：

> 你判断"被动"的标准，是不是"主语是那个被作用的对象"？

如果是，那问题来了——"`The book sells well.`" 这句话里，`book` 也是"被卖的对象"（书自己不会卖自己），可它用的是**主动形态** `sells`，没有 `was`，没有 `been`。按你的标准，它该算主动还是被动？

你卡住了。很好，这就是墙。

**打脸时刻。** 你八成会想："那说明被动不能只看主语是不是受事，还得看有没有 be 加过去分词。" 对，但那只答了"形态长啥样"，没答"英语为什么要允许两种镜头"。真正要问的是：

> **同一件事，凭什么英语能让你把镜头在'施事'和'受事'之间自由切换？**

### 2.1 核心洞见：主语 = 镜头对准的人/物

把一个句子想成一台摄像机。句子描述的是一个事件，事件里有"谁干的"（施事，agent）和"被作用的谁"（受事，patient）。

- 主动句：**镜头架在施事身上。** 主语是施事。读者第一眼看到的是"谁在动"。
- 被动句：**镜头架在受事身上。** 主语是受事。读者第一眼看到的是"谁被动了"。

这跟"被"字几乎没关系。`The orders table was locked.` 译成中文是"订单表被锁了"，那个"被"字是中文自己加的壳；英文 `was locked` 里根本没有对应"被"的单独词素，它只是一套把镜头从施事挪到受事的形态操作。

你可以用一个判断句钉死它：

> **语态 = 镜头机位的切换开关。主动把施事摆到 C 位，被动把受事摆到 C 位。**

### 2.2 类比一（计算机）：函数调用栈的栈顶是谁

你们后端天天跟调用栈打交道。一个函数调用另一个函数，被调用者（callee）被压进栈顶，调用者（caller）被压到下面，等 callee return 才回到栈顶。

- 主动句 = 你写 `caller()` 调 `callee()`，栈顶是 `caller`，`caller` 是这帧画面的主角，它干了什么一目了然。
- 被动句 = 你把 `callee` 直接摆到栈顶当主角，于是 `caller` 被压下去了，甚至可以**整个从栈里消失**（省略）。

`The orders table was locked.` 就是这么回事：镜头（栈顶）是 `orders` 表，而那个真正按压回车的 `Lin`/`migration`，被压到了 `by` 短语里，甚至可以被整个省略。事件还在，施事从画面里淡出。

这正好解释了卡点 1 里 a 和 b/c 的第一个差别：**a 是把 caller 摆栈顶，b/c 是把 callee 摆栈顶。** 同一个锁表事件，机位挪了。

### 2.3 类比二（生活）：监控摄像头拍哪块屏

想象 Pallet 机房里几路监控：

- 摄像头 A 正对 Lin 的工位，画面里是 Lin 敲下回车、按了执行键——这是主动句 `Lin ran a migration that locked the orders table.` 的镜头。
- 摄像头 B 正对数据库状态大屏，画面里是 `orders` 表的监控卡片从绿变红、顶上多了个锁的图标、旁边错误率曲线开始飙——这是被动句 `The orders table was locked.` 的镜头。

同一场事故，两路录像讲的是同一件事，但**机位不同，观众先注意到的"主角"就不同**。主动录像里 Lin 是主角，观众天然会想"他干了啥"；被动录像里那张表是主角，观众天然会想"这表出了啥事"。

回到母案例。卡点 1 的三句，对应的就是三路不同的机位：

- a 机位在 Lin（施事）-> 观众注意力落在"Lin 干了什么"。
- b 机位在 `orders` 表（受事）-> 观众注意力落在"表怎么了"。
- c 机位同样在 `orders` 表（受事）-> 但机位角度和 b 微妙不同，我们第 4 节再拆。

**回扣卡点 2。** 你刚才在 `The book sells well` 上卡住，不是因为你不懂被动，是因为你一直把"被动"定义成"主语是受事"——那个定义太窄了。被动真正的开关是**机位**，不是"主语是不是受事"。`book` 是受事没错，但句子用主动形态，是因为它想表达的压根不是"被卖"这个动作，而是"书自身的属性"（第 5 节详述）。你用错的标准去套，当然卡。

### 2.4 一个顺手要钉死的结论

中文里"被"字句是**词汇级**的选择：你想强调受事、淡化施事，就加个"被"。英文里语态是**形态级**的强制：你只要把镜头从施事切到受事，动词就得跟着变一套形状（be + 过去分词），躲不掉。

> 还是那句老话的变体：**中文把镜头机位挂在词汇上（被、让、叫），英文把机位焊进动词骨头里。** 中文翻"订单表被锁了"几乎一个样，英文 `got locked` / `was locked` / `was locked by Lin` 三副面孔，镜头和责任指向全不同——**中文翻译几乎一样，但英文思维完全不同。**

### 2.5 为什么英语要允许镜头自由切：底层设计动机

你可能会冒出一个更狠的疑问：**凭什么英语能让你在施事和受事之间随便切镜头？中文不也能说" Lin 锁了表"和"表被锁了"两种吗，这不也切了吗？**

问得好。但中文的"切"和英文的"切"不在同一层。

中文切换镜头，靠的是**词汇和语序的临时拼装**：想强调受事就加"被"，想强调施事就把人摆句首，动词本身纹丝不动。"被"是个可选的词，加不加由你，句子合法性不受影响。换句话说，中文的镜头切换是**运行时的、可选的、词层面的**。

英文的镜头切换是**编译期的、强制的、形态层面的**。一旦你把主语选成受事，动词就必须从 `lock` 变成 `was locked`，形态跟着改。你不是"加了点东西"，你是"重新声明了动词的身份"。这带来一个中文没有的副作用：**镜头位置被焊进了动词形状里，读者不必靠语境推断，看动词形态就知道机位在哪。**

为什么英语要这么设计？根子在英文是**形态化语言**这个老命题（详见第 0、1 面）。它的整套语法机器都建立在"动词形态携带元信息"之上——时、体、数、语气都焊在动词里，语态自然也走同一条路。这么做的好处是**信息密度高、歧义少**：一句话的主语是谁、镜头在哪、施事在不在，全写在形态上，听者零推断。代价是啰嗦、不自由，每说一个动词都要声明一堆维度。

所以"镜头能自由切"不是英语的恩赐，是它那套形态机器的必然产物。中文不焊形态，所以用词汇和省略来挪镜头——更灵活，但也更依赖语境，更容易"看不出在藏谁"。这正是后面几面（焦点、名词化、视角）反复要碰的底层分歧。

> **镜头族串联（先看一眼，不展开）：** 全书十个切面分三大族，第三面属于**镜头族（3 语态与主语 / 4 焦点与信息包装 / 10 视角与叙事距离）**。这三面其实在回答同一个问题的三个层级：镜头**架在谁身上**（本面，语态/主语）-> 镜头里**哪一块被打光**（第四面，焦点/cleft）-> 镜头**离现场多远**（第十面，视角）。你现在握的只是第一把镜头钥匙，后面两把是同一台摄像机的不同旋钮。时间族（1/2/6）管"什么时候、什么形状"，态度族（5/7/8/9）管"你怎么看待这件事"，而镜头族管的是"你让观众先看谁"。三族正交，互不打架。

## 3. 被动为什么会抹掉施事

上节说被动把施事压到 `by` 短语里。现在问你一个更狠的。

**卡点 3（翻译缺口型）。**

下面这句，请你翻成中文，但要满足一个条件：**不能出现"谁犯的错"这个信息。**

```
Mistakes were made.
```

你试着翻。"错误被犯了"？不通。"犯了一些错误"？——哎，等一下，"犯了一些错误"里，施事是谁？**没有。** 你翻不出来"谁"，因为原句里就没有 `by` 短语。

这就是英语里最著名的甩锅句式。**Mistakes were made.** 这句话在政客、CEO、危机公关稿里出镜率极高。它表面上认了"有错"，实际上把"谁犯的错"从句子里彻底抹掉了。

为什么被动能这么干？句法机制只有一句话：**被动的 `by` 短语是可省的。** `The orders table was locked.` 完全合法，施事可以一个字都不出现。主动句不行——`Lin locked` 后面必须接个宾语，施事 Lin 永远坐在主语位上，藏不掉。

### 3.1 神级素材：Mistakes were made 为什么破功只需两个字

我让你盯着 `Mistakes were made.` 看十秒。它妙在哪？

它选了被动，于是 `by someone` 被省了。句子在说"有错发生了"，却一个字没提"谁弄的"。听众的火气被"认错"的姿态接住了，而追责的链条在此断开——因为没有名字可追。

**然后点破它：只要你往后面加 `by Lin`，整句话立刻破功。**

```
*Mistakes were made by Lin.
```

（这里 `*` 不是语法错，是"修辞上自杀"。）你本来想遮掩，结果把名字亲口念了出来。"Mistakes were made" 的整套甩锅魔术，一旦补上 `by` 短语就灰飞烟灭——你想藏的人，恰恰是你自己补刀念出来的。这比直接说 "Lin made mistakes" 还尴尬，因为前者先装了半天无辜，再自己拆台。

### 3.2 母案例版：比甩锅更狠的一句

回到 The Outage。如果 Pallet 的公关或复盘纪要想彻底把锅挪走，他们有比 `Mistakes were made.` 更绝的句子：

```
A 51-minute outage occurred.
```

你品一品。这句牛在哪？它比 `Mistakes were made.` 还狠——**连 "mistake"（错误）这个词都不出现了**。事故被包装成了一个自发发生的"自然现象"，像"昨天下了一场雨""地震发生了"一样，没有施事、没有错误、没有责任，只有"一件事发生了"。

对比三档甩锅力度：

```
a. Lin caused a 51-minute outage.        （点名，施事在镜头 C 位）
b. Mistakes were made during the deploy. （认错，但施事蒸发）
c. A 51-minute outage occurred.          （连"错"字都不提，事故=天灾）
```

c 这种句子在正式 incident report 的开头特别常见，因为它把"事件"本身当成主角（存现句，详见速查表），先客观陈述事实，责任归属留到后面慢慢说。注意：**Pallet 实际的复盘是 blameless 的，根因是流程缺失而非 Lin 个人失误**，所以真实世界里这句反而用得理直气壮——它不是在遮掩，是在正确地把焦点从"人"移到"系统"。语态工具本身中立，拿它甩锅还是拿它做 blameless 复盘，是人心的事。

### 3.3 类比（计算机）：日志里把 user_id 字段置空

你写过日志吧。一条操作日志大概长这样：

```
{ "ts": "2024-11-12T02:14:00", "user_id": "lin_wei", "action": "alter_table", "table": "orders" }
```

被动抹掉施事，等于把这条日志的 `user_id` 字段**置空**：

```
{ "ts": "2024-11-12T02:14:00", "user_id": null, "action": "alter_table", "table": "orders" }
```

事件还在（action 有、table 有、时间有），但**溯源链断了**。你事后想追"谁干的"，翻日志发现 `user_id` 是 null，追不下去。`The orders table was locked.` 就是这条 `user_id: null` 的日志——表确实被锁了，但谁锁的，句子不告诉你。

这正是被动最锋利的地方，也是它最危险的地方：**它能让一件事"发生"却不必"归属"。** 用得好，是 blameless 复盘、是把焦点让给重要信息；用得歪，就是 `Mistakes were made` 式的精致甩锅。

**回扣卡点 3。** 你刚才卡在"怎么翻才能不出现施事"，说明你已经本能地摸到了被动的核心能力——**它天生能藏人**。`by` 短语可省，这不是偷懒的语法漏洞，是被动存在的核心理由之一。中文想藏施事得靠"被"字省略或"有人/大家"泛化，英文直接靠被动形态就办到了。两种语言处理"不想说谁干的"这件事，机制天差地别（思考题第 5 题我们专门拔高）。

### 3.4 实战：blameless 复盘怎么用被动才不心虚

母案例的真相是：**Pallet 的复盘是 blameless 的，根因归"流程缺失"而非 Lin 个人。** 这时候被动语态不是甩锅，而是**正确的工程实践**。我给你看区别：

```
甩锅式：  Lin broke production again.          （点名+定性"又"，攻击人）
blameless：A migration locked the orders table.  （镜头在表，施事淡化，聚焦事件）
```

blameless 复盘的第一条纪律就是**谈事件不谈人**：把镜头架在系统、流程、表、迁移这些"物"上，而不是架在 Lin 身上。被动（或事物主语）天然帮你做到这件事——`A migration locked the orders table.` 既不撒谎（确实是迁移锁的），也不诛心（没说"Lin 又搞砸了"）。施事被温和地推到背景，复盘会自然转向"我们缺什么流程"。

而真正的甩锅，是把被动当遮羞布：`Mistakes were made.` 表面 blameless，实则连"流程"都不想谈，只想让事件随风飘走。所以**语态工具本身中立，拿它做 blameless 还是做甩锅，分野在"你是否愿意在后续把 `by` 补上、把根因讲清"**。被动只是把施事请到后台，负责任的团队会在下一句把后台的门打开。

顺手把母案例完整事实钉死一遍（这些数字和名字全书贯穿，不许记错）：2024 年 11 月 12 日太平洋时间凌晨 2:14，后端工程师 **Lin Wei（林伟）**——28 岁、入职 8 个月、第一次独立 on-call——执行了一条没走 gh-ost 的原生 `ALTER`，锁住 `orders` 表（4.2 亿行）。总时长 51 分钟，约 12,300 笔下单失败，大客户 **Northwind Retail**（由客户成功经理 **Marcus Bell** 对接）损失约 8 万美元 GMV，但**无数据丢失**。次日 blameless 复盘根因归"流程缺失"，Lin 未受罚；三条行动项落地后，Pallet 此后 **22 个月无 P1**，到 2026 年 9 月现状是 Lin 成了 on-call 培训负责人、Priya 升工程总监、Northwind 续约。注意：这套事实你本章随便用被动去拍，但**任何人名、日期、结局都不能改**——镜头可以换，钻石本身不能磨。

## 4. got locked vs was locked 的微妙差别

好，现在到了全章最精微、也最容易被忽略的一对。

**卡点 4（二选一型）。**

下面两句，中文都译"订单表被锁了"。它们真的完全一样吗？

```
b. The orders table got locked.
c. The orders table was locked.
```

先别往下看，想三秒。中文翻译一个字不差，英文这两句在你耳朵里，味道一样吗？

你大概率说不上来具体差在哪，但母语者会告诉你：**不一样，而且差在"责任指向"。**

### 4.1 got = 出事了（不及物/事件突发感）

`got locked` 里的 `get` 在这里是个**使役/变化**的用法（get + 过去分词），它带着一股"**事情突然落到头上了**"的口语气息。它更像一个**不及物事件**——强调"这件事发生了"，而不是"被谁施加了动作"。

- `got locked` ~ "（不知怎么地）锁上了 / 出岔子被锁了"。
- 口语、新闻标题、吐槽里特别常见：`My phone got stolen.`（我手机被偷了）、`He got fired.`（他被炒了）。

注意它的潜台词：**它更像在描述一种"遭遇"**，主语是那个"倒霉摊上事"的对象。责任指向是模糊的、外来的——"事儿找上了我/它"。

### 4.2 was = 被谁干的（及物被动感）

`was locked` 是标准的**及物被动**（be + 过去分词），它更正式、更"书面"，强调的是"**有一个动作被施加到了主语身上**"。它天然在等一个 `by` 短语来补施事：

- `was locked` ~ "被（某人/某物）锁住了"。
- 正式报告、技术文档标配：`The connection was terminated by the system.`

它的责任指向是**可被点名的**——只要你愿意补 `by`，施事随时归位。

### 4.3 同一被动，两种责任味道（对立对）

把这对差别钉死，给两组对照。母案例一组：

```
b. The orders table got locked.        （出事了，像天降横祸，责任外悬）
c. The orders table was locked by a migration.  （被一条迁移锁的，责任可点名）
```

卫星案例一组（社交/生活）：

```
a. I got stood up by Wang.     （我被放鸽子了——口语，强调"我摊上这倒霉事"）
b. I was stood up by Wang.     （我被老王放了鸽子——更书面，强调"被施加了这个动作"）
```

你看，即便是同一件事、同一个施事 Wang，`got` 和 `was` 给人的"质感"不同：前者像朋友间吐槽"我特么被鸽了"，后者像在写正式陈述"我遭到了爽约"。**中文都译"我被放了鸽子"，但英文这两句，镜头的距离感和责任的外悬程度是不一样的。**

这正好回扣开场：卡点 1 里你以为 b/c 是"同一个被字句"，其实 `got locked` 是"事件突发、责任外悬"的镜头，`was locked` 是"被施加动作、责任可追"的镜头。**同一个被动，机位角度不同，责任的指向就不同。** 这是本章最精微的一点，值得你多读两遍。

顺手把这对差别接回母案例的事故沟通。Pallet 在 03:05 恢复后，对外通知和内部同步其实会自然选用不同的被动：

```
对外（客情通知）：Northwind's orders got affected during a brief outage.  （"出岔子了"，软化责任）
对内（工程群）：  The orders table was locked by a migration; we killed it at 2:47.  （"被迁移锁的"，点名可追）
```

对外用 `got affected`，把事故讲成"一阵突发状况波及了你们"，责任外悬、语气柔和，大客户 Northwind 听着没那么像"你们工程师闯祸"；对内用 `was locked by a migration`，冷静点名 root cause，便于后续行动项落地。同一个被动家族，旋钮拨到 `got` 还是 `was`，客情和工程的两边话语就分开了。**这不是修辞小花招，是责任叙事的工程化控制。** 你以后写 incident 通知，先想清楚这句该用 `got` 还是 `was`，比想"这句语法对不对"重要十倍。

## 5. 中动语态（middle voice）：主动形式，被动意义

前面把被动讲透了。现在来一个反着来的——**主动形态，却表达被动意义**。

**卡点 5（翻译缺口型）。**

下面这句，请你翻成中文，而且注意：**中文里"被"字出现不出现？**

```
The book sells well.
```

你大概会翻："这本书卖得好。" 或者 "这本书好卖。"

看出来没？中文里**没有"被"**，也没有"能"（虽然意思有点像"能被卖"），就是个干干净净的主动句，主语是"书"。可书自己不会跑出去叫卖啊——它明明是"被卖"的那个对象。英文却用主动形态 `sells` 把它讲出来了。

这就是**中动语态（middle voice）**。它夹在主动和被动中间：主语是受事，但动词用主动形式，而且**不接 `by`**，强调的不是"谁对它做了什么"，而是"**事物自身的属性**"。

### 5.1 机制：主语是受事，但焦点在"属性"而非"动作"

看这组：

```
a. The book sells well.        （这本书好卖——书自身的属性）
b. This knife cuts easily.     （这刀切得顺——刀自身的属性）
c. The migration doesn't rollback cleanly.   （这条迁移回滚不干净——迁移自身的属性）
```

c 直接借母案例的素材：`rollback` 是个动作，施事该是"人/DBA"，但句子把 `migration` 摆主语，用主动形态说"它回滚不干净"。它想表达的不是"谁没回滚好"，而是"**这条迁移这个东西，天生回滚就费劲**"——这是在描述系统的一种**固有属性**，像在说一个字段的契约。

对比真正的被动，差别就显出来了：

```
a. The migration was rolled back by Priya.     （Priya 把它回滚了——焦点在动作+施事）
b. The migration doesn't rollback cleanly.     （它回滚不干净——焦点在迁移自身的属性）
```

a 是被动，机位在 migration，但等一个 `by` 补施事，讲的是"一次具体的回滚动作"。b 是中动，机位也在 migration，但**根本不关心谁干的**，讲的是"这东西是什么质地"。

### 5.2 类比（计算机）：只读不写的字段，getter 暴露但 caller 不参与

你们写 struct，常有这种字段：它的值由内部状态决定，对外只暴露 getter，调用方只能"读"它、不能"写"它、也不参与它的计算。

```
type Migration struct {
    id string
    rollbackClean bool   // 只读，caller 不参与它的产生
}
func (m *Migration) RollbackClean() bool { return m.rollbackClean }
```

`The migration doesn't rollback cleanly.` 就像一个只读 getter 返回的值——主语 `migration` 是那个"被观测的对象"（受事），但句子用主动方法调用（`rollback cleanly`）把它暴露出来，**调用方（施事）根本不在画面里**，你只是在陈述这个对象自己的属性。中动语态 = 对外暴露对象自身属性的 getter，主动形式，但 caller 不出现。

### 5.3 为什么中文几乎不需要中动这个概念

中文里"这本书卖得好""这刀切得顺"本来就是主动句，主语是书、是刀，你不会觉得别扭，因为中文压根不强制动词变形。英文必须用形态区分"被卖的动作"（`was sold`，被动）和"好卖的属性"（`sells well`，中动），所以它硬造出了 middle voice 这一档。

这也顺手修了卡点 2 那个病句：

```
*The book was sold well.
```

错在哪？`was sold` 是被动，它在说"这本书被（某人）卖掉了"，是个**具体的销售动作**，后面通常接 `by the bookstore` 之类。可你想表达的是"这本书好卖"这种**属性**，该用中动 `sells well`，而不是被动 `was sold`。一个用错语态，镜头就从"书自身的质地"歪到了"一次具体的被卖动作"，味道全变。

**回扣卡点 5。** 你卡在"中文没有'被'怎么翻"，恰恰说明中动语态在中文里是隐形的——中文根本不分"被卖的动作"和"好卖的属性"，一个"卖"字全包。英文逼你选：是 `was sold`（被动，一次动作）还是 `sells`（中动，一种属性）？**镜头里到底在拍"一次动作"还是"一个属性"，英文要你声明，中文不问。**

### 5.4 卡点 7（判断对错型）：中动到底算不算被动？

讲完中动，来检验一下。下面这句话，你觉得它算主动还是被动？

```
The book sells well.
```

**先别往下看，想三秒。** 你八成会说："主语 book 是受事，动词还是主动形态，那它……介于两者之间？算半被动？"

**打脸时刻。** 你八成会想："既然主语是受事，那它本质还是被动的一种变体。" 错。中动语态（middle voice）在传统语法里被单独算作**第三类语态**，既不归主动也不归被动。为什么这么较真？因为"主动/被动"这对标签，盯的是**动作的方向（谁作用谁）**；而中动盯的是**主语的属性状态**——它压根不是在讲一个"动作发生了"，而是在讲"这个东西是什么质地"。

```
主动：  Someone sells the book.        （有人在卖——动作，施事在）
被动：  The book was sold (by someone). （书被卖——动作，施事可省）
中动：  The book sells well.           （书好卖——属性，无动作、无施事）
```

你看，主动和被动里都有"卖"这个**动作**（有人卖 / 被卖），唯独中动里"卖"不是动作，是 book 的一个**性质谓词**，像 "The book is red." 一样是在描述状态。把中动塞进"被动"里，等于把"描述属性"和"描述动作"混为一谈——这正是很多教材讲糊的地方。所以记住：**中动是镜头对准"事物自身属性"的一档独立机位，不是被动的表弟。**

## 6. 主语选择 = 信息流（承上启下，引出第 4 面）

前面所有讨论，都绕着"镜头架在谁身上"转。现在把镜头再往上提一层，问一个更实用的问题：

> 既然镜头能自由切，那**到底什么时候该把谁摆到主语位？** 总不能随心所欲吧。

**卡点 6（二选一型）。**

下面两句，都说的是同一件事。哪句更顺？为什么？

```
a. A migration locked the orders table.
b. The orders table was locked by a migration.
```

先别往下看，想三秒。中文都译"一条迁移锁了订单表 / 订单表被一条迁移锁了"，差不多。英文哪句更自然？

你八成选了 b，但说不清为什么。或者你选了 a，因为"主动总比被动顺"。错，这次不是非黑即白。

### 6.1 主位与述位：旧信息坐主语，新信息坐句尾

语言学界管这个叫**信息结构（information structure）**。一句话分成两个包袱：

- **主位（theme）**：放在句首、通常是**读者已经知道的信息**（旧信息）。它像舞台的底座，读者踩着它进场。
- **述位（rheme）**：放在句尾、是**你要告诉读者的新信息**。它像追光灯打上去的新东西。

这又叫**尾重原则（end-weight）**：新信息、重内容放句尾，读者印象最深。

为什么被动有用？因为被动能让你把"受事"摆回主语位。当**受事才是读者已知的旧信息**时，用被动把它放主语（主位），信息流才顺。

### 6.1.1 卡点 8（二选一型）：哪句读着顺？

还是母案例。假设你的读者刚在群里看过告警"orders 表挂了"，现在你接着说下面哪句更顺？

```
a. A migration locked the orders table, and 12,300 orders were dropped.
b. The orders table was locked by a migration, and 12,300 orders were dropped.
```

**先别往下看，想三秒。** 两句中文都译"一条迁移锁了订单表，一万两千笔订单没了"，差别在哪？

你八成觉得 a 更"自然"，因为"主动总比被动顺"。**错，这次直觉反而把你带沟里了。** 真正顺的是 b（或者至少 b 的后半不别扭）。为什么？因为读者已知的 `orders` 表已经在上一句当过主角了，b 接着把它摆主语（主位），认知链条不断；a 却突然把新信息 `a migration` 甩到句首当主语，读者得先接住"一条迁移"这个陌生主角，再绕回已知的表——认知顺序被拧了。

**回扣卡点 8。** 你刚才凭"主动顺"的直觉选了 a，说明你还没把"镜头机位"和"信息新旧"分开：主动被动从来不是顺不顺的标准，**已知信息坐主语才是顺不顺的标准**。被动在这里不是因为"想被动"，是因为它恰好能把已知信息请回镜头中心。

### 6.1.2 一段具体的改写演示

把母案例告警后的群聊消息，从"别扭"改成"顺"，你就看懂信息流怎么运作了。

别扭版（新人容易写的）：

```
*We had an incident. A migration locked the orders table. Priya killed the connection.
```

问题：三句主语分别是 We / A migration / Priya，镜头在三人之间乱跳，读者每次都要换主角。而且 `orders` 表这个读者最关心的已知信息，被压在第二句当宾语。

顺版（老手写的）：

```
We had a 51-minute incident. The orders table was locked by a migration; the connection was killed by Priya at 2:47.
```

改动：把 `orders` 表摆回主语 C 位（读者已知，主位），把 `migration` 和 `Priya` 都塞进 `by` 当新信息补在句尾。镜头从头到尾钉在"表/连接/事故"这些**物**上，读者顺着已知信息往下接，毫不费力。这就是尾重原则落地后的样子——不是语法对不对，是**镜头稳不稳**。

### 6.2 回到母案例：谁是你已知的？

在 The Outage 的叙事里，你的读者（假设是复盘会上的同事）早就被告警轰炸过了——他们**已知 `orders` 表出事了**，"`orders` 表"是旧信息。而"是一条迁移锁的"是事后定位出来的**新信息**。

所以：

```
b. The orders table (旧信息/已知) was locked by a migration (新信息).   -> 顺
a. A migration (新信息) locked the orders table (旧信息).                -> 把已知信息压到句尾，别扭
```

b 把读者已知的 `orders` 表放主语当底座，再把新情报"是一条迁移干的"追在句尾，读者顺着已知往上接新东西，毫不费力。a 反过来，把新信息"一条迁移"甩到句首当主语，旧信息"订单表"被压到句尾——读者的认知顺序被顶拧了，读着就膈应。

这不是"主动被动哪个好"的问题，是**信息流的先后秩序**问题。镜头切到受事，不是为了"被动而被动"，是为了把已知信息请回 C 位。

### 6.3 回扣开场卡点，并预告下一面

现在你彻底看得懂卡点 1 那三句了，它们不只是"被"字的有无：

- a `Lin ran a migration...`：把**施事 Lin（已知他 on-call）** 摆主语，镜头在 Lin。
- b/c `The orders table got/was locked`：把**受事 `orders` 表（读者已知出事）** 摆主语，镜头在表。

你当初以为"b/c 就是加了个被字"，现在知道那是把三件不同的事揉成了一团：**镜头机位（施事还是受事）+ 信息流里的已知/未知位置 + got/was 的责任指向**。中文六字"订单表被锁了"全包了，英文逼你一一声明。

> **记住这一句：** 主语不是语法主语，是**已知信息的座位**；语态不是语法变形，是**镜头机位的开关**。

这句话是通往下一面的桥。你发现没有——本章我们一直在说"镜头架在谁身上""把谁打光当主角"，可"打光"这件事本身，还有更系统的玩法：同样是被动，我能不能**只把某一个词拎出来单独打光**？比如 `It was the orders table that got locked.`（被锁的是订单表）这种" cleft 句"？那已经不是"语态"的事了，那是**焦点与信息包装**——第四面，我们接着转这颗钻石的下一个切面。这里先不展开。

## 7. 母案例十面之三：用本章维度重写母事件

把 The Outage 整个事件，用"语态 x 主语"这台摄像机重新拍一遍。下面每一句，我都标了**镜头在哪、施事在不在、责任指向**。你对照着看，同一场事故能有多少种"面孔"。

先说清楚为什么这一节值得你逐句读。前面六节你学的是"镜头旋钮"本身，这一节是让你看旋钮拧到不同位置时，同一场 51 分钟事故会呈现出多少种完全不同的叙事立场：可以点名到 Lin 个人，可以只盯着那张 `orders` 表，可以跳到那 12,300 笔掉的单，也可以把整件事包装成"一场发生了的故障"。这些都不是"换种说法"那么轻巧——**每一句的镜头一变，读者记下的"谁该负责"就跟着变**。中文里你大概只会说"订单表被锁了，一万多笔订单没了"，一个镜头到底；英文逼你把镜头一格一格拧过去，于是立场也被一格一格显形。这就是为什么这一节叫"十面之三"——它是同一颗钻石，转到第三切面时露出来的几副面孔。

### 7.1 主动版（镜头在施事）

```
Lin ran a migration that locked the orders table.
```

- 镜头：Lin（施事在主位）。
- 施事：在，C 位。
- 责任指向：直接落在 Lin 头上。这是"讲故事从人开始"的版本，复盘开头若想强调"谁在 on-call"，可用。

### 7.2 被动版（镜头在受事，施事可补）

```
The orders table was locked by a migration.
```

- 镜头：`orders` 表（受事在主位）。
- 施事：藏在 `by a migration` 里，可省。
- 责任指向：表是主角，"迁移"作为新信息补在句尾。读者已知表出事，这句信息流最顺（见第 6 节）。

```
12,300 orders were dropped.
```

- 镜头：那 12,300 笔订单（受事）。
- 施事：**完全省略**。没人关心"谁丢的"，关心的是"丢了多少、谁的损失"。这正是 SPEC 十面速览里的"换主语"例句——受事者当镜头。

### 7.3 甩锅/脱责版（施事蒸发到极致）

```
Mistakes were made.
```

- 镜头：mistakes（抽象名词当主角）。
- 施事：彻底蒸发，无 `by`。
- 责任指向：模糊到不存在。经典甩锅。但如前所述，Pallet 真实复盘是 blameless、根因归流程，所以这句在真实语境里反而是"正确地不点名个人"。

```
A 51-minute outage occurred.
```

- 镜头：outage 本身（事件当主角，存现意味）。
- 施事：连"错"字都不提，事故被当成自然现象。
- 责任指向：零。比上句还狠。这是 incident report 开篇"先陈述事实"的标准写法。

```
There was a 51-minute outage.
```

- 镜头：存在本身（存现句，There be）。
- 施事：无。
- 责任指向：零。和上一句同属"事件当主角"，只是 `There be` 更强调"有这么一件事发生过"。

### 7.4 got vs was 对比（责任外悬 vs 可点名）

```
The orders table got locked.              （出事了，像天降横祸，责任外悬）
The orders table was locked by a migration. （被一条迁移锁的，责任可点名）
```

两句中译都是"订单表被锁了"，但镜头质感不同：前者像告警群里有人喊"表锁了！"（突发、懵），后者像定位后的冷静陈述（被迁移锁的）。

### 7.5 中动版（讲属性，不关心谁）

```
The migration doesn't rollback cleanly.
```

- 镜头：migration（受事主语，但主动形态）。
- 施事：无，根本不关心谁回滚。
- 责任指向：不在人，在"这条迁移本身的质地"——它天生难干净回滚，暗示该用 gh-ost 这类在线工具。这一句其实暗合了根因："原生 ALTER 这东西，回滚不干净"，把矛头指向工具/流程而非 Lin。

你把这七句横着看一遍，会惊觉：**同一场 51 分钟事故，英文能让你在"点名 Lin""点名迁移""只说表""只说订单数""只说 outage 发生了""吐槽迁移难回滚"之间自由滑动。** 中文呢？"订单表被锁了""一万两千笔订单没了""出了次 51 分钟的故障"——翻译出来几乎一样，可每一句的镜头、施事、责任指向天差地别。**中文翻译几乎一样，但英文思维完全不同。** 这就是第三面要你刻进骨子里的东西。

### 7.6 卡点 9（翻译缺口型）：一句中文，几种镜头？

最后一道卡点，逼你亲手动一次镜头。

下面这句中文，请你翻成英文。但有个要求：**至少写出三种不同的英文，让镜头分别落在不同位置。**

```
订单表被锁了。
```

**先别往下看，自己写三种，最好出声念一遍。** 写不出第三种也算一种答案——那说明你的中文"被锁了"三个字，把你锁在了单一镜头里。

你大概率写出了前两种：

```
a. The orders table was locked.          （镜头在表，标准被动）
b. A migration locked the orders table.  （镜头在迁移/Lin，主动）
```

第三种你多半卡住。其实至少有这几种还能加：

```
c. The orders table got locked.          （镜头在表，但"出事了"突发感）
d. The orders table was locked by Lin.   （镜头在表，施事点名补上）
e. 12,300 orders were dropped.           （镜头跳到"掉的单"，连"表"都不提）
```

**回扣卡点 9。** 你卡在"第三种"，恰恰证明中文的"被锁了"是个**高度打包的表达**：它把"谁干的、镜头在哪、责任指向"全压进三个字里，你从来没被逼着拆。而英文逼你为每一种镜头选一套形态——`was`/`got`/`by Lin`/`were dropped`，一个都省不掉。这九道卡点从头到尾就在干一件事：**把中文替你打包好的东西，一件件拆开，摆回英文的镜头机器里。**

## 8. 卫星案例：换主语，换了什么立场

本章讲的全是"镜头机位"。光靠母案例撑不住——规则得像螺丝刀，拧得动不同领域的螺丝才算真懂。下面 8 个案例，跨工作、医疗、生活、社交、商业、运动六个领域，每个都配一个语态/主语的最小对立对，并说明**换主语到底换了什么立场**。技术案例本章一个都没用（母案例已是技术主场，按 SPEC 每章技术案例 <= 2，这里索性留给母案例独占）。

在进案例之前，先给你一把统一的"解码钥匙"。每一个案例，你都用同一个问题去戳它：

> **把谁摆到镜头 C 位，谁就是读者先注意到的主角；把谁塞进 `by` 或干脆省略，谁就从追责链上消失。** 所以"选主语"从来不是语法填空，是**立场声明**——你让观众先看谁、记住谁、原谅谁，全在这一句话的主语和语态里。

这把钥匙拧开下面八个锁，你会发现规律惊人地一致：生活里的吐槽、职场里的道歉、医疗报告里的客观、商业里的甩锅、运动里的"天意"、社交里的自嘲，底层都是同一台镜头机器在转。中文把这些全包进"被/让/叫"和上下文里，英文把它们焊进动词形状和主语位置——**中文翻译几乎一样，但英文思维完全不同**，这句话在卫星案例里会比在母案例里更刺眼，因为距离你的技术主场越远，你越能看清规则是通用的。

### 8.1 邮件发错收件人（工作）

你是市场部新人，把一份本该发内部团队的"Q3 促销预算"草稿，误发到了客户邮箱 `contact@bigclient.com`。10 分钟后发现，撤回失败（对方已读），客户看到了未定稿数字，尴尬但没泄密。

```
a. You sent the draft to the wrong address.     （你=镜头，施事在，强调"你手滑"）
b. The draft was sent to the wrong address.     （草稿=镜头，施事隐去）
```

换主语换了什么立场：写内部复盘/道歉信时你更倾向于 b——读者已知的"草稿"当主语，且你想淡化"你粗心"这件事，把焦点放在"邮件去错了地方"这个事实上。a 则把责任钉死在你头上，适合你对老板当面承认"我发错了"。

### 8.2 体检某项指标异常（医疗）

你妈 58 岁，年度体检，甲状腺超声提示"右叶低回声结节 TI-RADS 4a"。放射科医生在报告上圈了出来，你拿到纸质报告。

```
a. The radiologist flagged a suspicious nodule.   （医生=镜头，施事在）
b. A suspicious nodule was flagged on the scan.   （结节=镜头，施事隐去）
```

换主语换了什么立场：医院给病人的报告几乎一律用 b 类被动。为什么？因为报告的主语应该是"你的身体/影像"，不是"哪个医生看的"。病人关心的是"我身体上有什么"，不是"谁看的片子"。b 把施事（医生）蒸发，焦点纯粹落在发现本身，读起来客观、不吓人也不邀功。

### 8.3 外卖送错（生活）

周三晚你点黄焖鸡米饭，骑手把 3 栋 1802 的麻辣烫送到了你 2 栋 1503。你开门拿到的是别人的餐。

```
a. The courier mixed up the orders.     （骑手=镜头，施事明确）
b. My order got mixed up.               （我的订单=镜头，got 带"出岔子"口语感）
```

换主语换了什么立场：你发朋友圈吐槽用 b，因为你站在"受害者/受事"角度，且 `got` 那种"倒霉摊上事"的语气特别适合吐槽。平台客服内部记录用 a，要追责到人（哪个骑手、哪单串了）。同一件事，镜头在"我"还是"骑手"，决定了这是吐槽还是追责。

### 8.4 被朋友放鸽子（社交）

周六你和大学室友老王约火锅，他 18:00 答应来，19:30 才发微信"不好意思忘记对面了"，你已到店点好锅底。

```
a. Wang stood me up.          （老王=镜头，正式陈述"放鸽子"）
b. I got stood up by Wang.    （我=镜头，got 强调"我遭遇了这事"）
```

换主语换了什么立场：b 用 `got` 是母语者社交吐槽的标配——"我被人鸽了"，重点在"我这段倒霉经历"，施事 Wang 可省（直接 `I got stood up`）。a 更冷、更中性，像在跟第三个人客观转述"老王放我鸽子"。镜头在"我"还是"老王"，决定了这是抒发委屈还是陈述事实。

### 8.5 手机落出租车（生活）

周五深夜你打车从机场回城，下车时把 iPhone 落在后座，司机已接新单开走。你用 Find My 看到车在 5 公里外移动。

```
a. You left your phone in the taxi.      （你=镜头，强调"你忘了"）
b. Your phone was left in the taxi.      （手机=镜头，施事淡化）
```

换主语换了什么立场：你报警/挂失时脱口而出的多半是 b——你要描述"手机的状态和位置"，施事（你粗心）不重要甚至尴尬，省掉最舒服。朋友调侃你时说的却是 a，故意把"你"摆回镜头嘲你大意。换主语，就是把"谁该脸红"这件事轻轻挪走或狠狠钉死。

### 8.6 竞品抢先发布（商业）

你们创业公司做了半年"一键导购"功能，对手 ShopFast 周三突然官宣同款，抢了你们发布会的风头，媒体通稿全写"ShopFast 率先"。

```
a. ShopFast launched the feature first.            （对手=镜头，点名）
b. The feature got launched by a competitor first. （功能=镜头，got 带"被抢先"突发感）
```

换主语换了什么立场：内部复盘常用 b，甚至更狠的 `A feature launch beat us to it.`（存现式甩锅到"事件"），因为复盘要淡化"我们慢了"这个扎心事实，把焦点放在"功能被对手先发了"这个客观事件上。对外 PR 稿则用 a 点名对手，把竞争态势摆到台前。同一发布，镜头在"对手"还是"功能"，立场从"宣战"滑向"叹气"。

### 8.7 马拉松跑崩（运动）

你备战 4 个月首马，30 公里处小腿抽筋，配速从 5:30 崩到 7:20，最后走完，净成绩 4:52，目标 sub-4。

```
a. A cramp destroyed his race at 30k.     （抽筋=镜头/施事，像 root cause）
b. His race was ruined by a cramp.        （比赛=镜头，施事在 by）
```

换主语换了什么立场：两句都在把责任转移到"客观因素"（抽筋），而不是"我菜"。a 把抽筋当 culprit，像写事故 root cause（"元凶是抽筋"）；b 把"比赛"当主角更书面，施事补在 `by` 后。无论是 a 还是 b，镜头都刻意避开了"选手本人训练不足"——这正是被动/主语选择用来"温柔甩锅给天意"的典型。

### 8.8 表白被拒（社交）

你暗恋同事小周，团建酒后鼓起勇气表白，她笑说"你很好但我们还是做同事吧"。你当晚没睡。

```
a. Zhou turned me down.            （小周=镜头，施事明确）
b. I got turned down by Zhou.      （我=镜头，got 强调"我遭受拒绝"）
```

换主语换了什么立场：b 用 `got` 是母语者讲自己被拒经历时的自然说法——"I got turned down"，重点在"我这段被拒的遭遇"，施事 Zhou 可省，语气带点自嘲的轻松。a 更冷叙事，像第三方转述。注意这里 `got turned down` 和 8.4 的 `got stood up` 是同一套路：**got + 被动，母语者用来讲"我摊上了某件糟心事"**，口语感强，责任外悬。

八个案例横看，规律铁一样：

> **换主语 = 换立场。** 把谁摆到镜头 C 位，谁就是读者先注意到的主角；把谁塞进 `by` 或干脆省略，谁就从追责链上消失。语态和主语从来不是中性语法，是**叙事立场的旋钮**。

这八个案例横跨工作、医疗、生活、社交、商业、运动六个领域，没一个是技术题，可每一句的对立对和母案例用的是同一台镜头机器。这说明一件事：**第三面讲的不是"英语被动语态语法"，是一套通用的"注意力分配"手艺。** 你写代码注释、写事故复盘、写客户邮件、发朋友圈吐槽、甚至跟朋友解释"我为什么迟到"，都在不知不觉地做镜头决策——只是中文把这决策溶进了语境，你从没意识到自己在"选机位"。

给你一个立刻能用上的小练习：下次你写了句中文"X 被 Y 怎么了"，先别急着翻英文，先在心里拆三下——镜头该在 X 还是 Y？施事 Y 该不该露脸？已知信息是哪个？拆完你会发现，原来你中文里那一个"被"字，英文要用 `was` / `got` / `by Y` / `were dropped` 里某一格才能对上。**中文翻译几乎一样，但英文思维完全不同**——这句老话，到这八个案例才算真正落地。

## 9. 一面之得

第三面转完，把要点收成几条：

1. **语态是镜头机位，不是"被"字。** 主动把施事摆 C 位，被动把受事摆 C 位。中文的"被"是词汇外壳，英文的被动是焊进动词的形态开关。
2. **被动能抹施事，因为 `by` 短语可省。** `Mistakes were made.` 是经典甩锅；`A 51-minute outage occurred.` 连"错"字都不提，把事故包装成自然现象。抹施事 = 日志里把 `user_id` 置空，事件在，溯源断。
3. **`got locked` != `was locked`。** 前者是"出事了"的突发/外悬感（口语、遭遇到头），后者是"被谁干的"的及物被动感（正式、责任可点名）。同一被动，责任指向不同。
4. **中动语态：主动形式表被动意义。** `The book sells well.` 主语是受事，但讲"事物自身属性"而非"被施加的动作"，像只读 getter。
5. **主语 = 已知信息的座位。** 旧信息坐主语（主位），新信息坐句尾（述位），这叫尾重原则。被动的真正用处，是把已知的受事请回镜头中心，让信息流顺。

> **记住这一句就够了：语态不是语法变形，是镜头位；主语不是语法主语，是已知信息的座位。**

中文靠"被/让/叫"和上下文表达镜头与立场，英文把它焊进动词骨头和主语位置。**中文翻译几乎一样，但英文思维完全不同**——这一句，第三面你该刻进去了。下一面（第四面：焦点与信息包装）我们接着问：镜头已经架好，那束追光，到底打在句子的哪一个词上？

顺带收一下你这一面该带走的"肌肉记忆"。下次你写英文句子、尤其是事故通知、复盘、客户邮件时，别再问"这句语法对不对"，改问三个问题：

1. **镜头该架在谁身上？** 是施事（人/动作源）还是受事（物/受害者）？把该被看见的那个摆主语。
2. **施事该不该出现？** 要归责就补 `by`，要脱责或做 blameless 就省 `by`；想连"错"都不提就用 `occurred` 式存现句。
3. **已知信息坐没坐主语？** 读者已经知道的东西放句首当主位，新情报甩句尾当述位，信息流才不拧。

这三个问题全是"镜头决策"，没有一个在问时态或体（那些是前面两面、详见第 1、2 面）。你一旦习惯用镜头而非"语法"去想英文句子，写出来的东西会立刻少一股翻译腔——因为你终于不是在"把中文翻成英文"，而是在"给事件选一台摄像机"。

## 10. 思考题（5 道，附展开参考答案）

下面五道题按"辨析—辨析—应用—应用—拔高"三层排布，对应 SPEC 的思考题规格。重点不在"你答对没"，在参考答案本身的展开——它和正文一样，是这一面的学习材料。每道题先自己写一遍再翻答案，效果比直接读答案好得多。

### 第 1 题（辨析层）

下面两句中文翻译几乎一样，英文差在哪？

```
a. The server crashed.
b. The server was crashed by a bad deploy.
```

请说明：哪句是主动、哪句是被动？被动句里施事在不在？如果去掉 `by a bad deploy`，句子的"责任指向"会发生什么变化？

**参考答案**

a `The server crashed.` 是主动形态，但注意 `crash` 在这里是**不及物**用法，主语 `server` 既是语法主语也是"出事的对象"，没有施事——它描述的是服务器"自己崩了"，像自然事件。b `The server was crashed by a bad deploy.` 是及物被动，镜头在 `server`（受事），施事 `a bad deploy` 明明白白坐在 `by` 短语里，责任指向一次具体的"糟糕发布"。

关键在第三问：如果去掉 `by a bad deploy`，变成 `The server was crashed.`——这句在英语里其实很别扭，因为 `crash` 作及物时施事几乎总要出现（你总得说"被什么弄崩的"）。这反衬出 b 的用心：它**特意把施事点名**，不是想藏，是想归责。对比 `The orders table was locked.`（施事可省，因为锁表这种事读者能脑补出"人干的"），`was crashed` 硬要补施事，说明说话人急于把锅甩给"那次发布"。所以同一被动形态，补不补 `by`、补什么，直接改写责任叙事。这正是第三面说的：被动的 `by` 可省，但"省不省"本身就是一个立场选择。

### 第 2 题（辨析层）

下面两句，哪句更像"吐槽自己倒霉"，哪句更像"客观陈述事实"？为什么？

```
a. I got rejected by the committee.
b. The proposal was rejected by the committee.
```

**参考答案**

a `I got rejected by the committee.` 用 `got` + 被动，是母语者讲"我摊上糟心事"的口语标配。`got` 带来"出事了、遭遇到头"的突发感，主语又是 `I`（受事），整句焦点在"我这段被拒的经历"上，施事 committee 可省（直接 `I got rejected`）。所以它是吐槽/自嘲视角——"我被拒了，倒霉"。

b `The proposal was rejected by the committee.` 用标准 `was` 被动，正式、书面，镜头在 `proposal`（受事），施事 committee 在 `by` 里。它不讲"谁委屈"，只讲"提案被拒这个事实"，像会议纪要里的冷静记录。

差别本质在第三面第 4 节：`got` 是"事件突发、责任外悬"的镜头，`was` 是"被施加动作、责任可点名"的镜头。a 把镜头架在"我"身上强调遭遇，b 把镜头架在"提案"身上强调事实。中文都译"被委员会拒绝了"，但英文这两句，一个在抒发立场，一个在陈述立场。

### 第 3 题（应用层）

你是后端，要在团队周报里写一句话，说明"上周的缓存雪崩导致 3000 次请求超时"。两种写法：

```
a. The cache avalanche caused 3,000 timeouts.
b. 3,000 requests were timed out by the cache avalanche.
```

你的读者（组内同事）早就知道"上周缓存雪崩"这回事。你觉得哪句信息流更顺？为什么？如果要进一步弱化"雪崩"的责任感、只突出损失数字，你会怎么改主语？

**参考答案**

读者已知"缓存雪崩"，所以"缓存雪崩"是旧信息，该坐主位（句首）；"3000 次超时"是新信息，该坐述位（句尾）。a `The cache avalanche caused 3,000 timeouts.` 正是这个顺序：已知当主语，新信息在尾，信息流顺。b 反过来了——把新信息"3000 请求"摆主语，"缓存雪崩"压到 `by` 短语里，读者的认知顺序是拧的，读着别扭（而且 `requests were timed out` 搭配也生硬，超时通常是 `timed out` 不及物，不该用被动）。

要进一步弱化"雪崩"的责任、只突出损失，就把损失数字当绝对主角，施事彻底蒸发：

```
3,000 requests timed out last week.
```

这里连被动都不用，`requests` 作主语、`timed out` 不及物，雪崩这个词干脆不出现——镜头纯纯打在"损失"上。这正是第三面第 6 节讲的：主语是已知信息的座位，你想让谁被记住，就把谁摆上去；想让谁被遗忘，就别让它进画面。周报里想淡化事故、突出影响时，这招很实用。

### 第 4 题（应用层）

你写了一封邮件给客户，解释一次故障。下面两句，你会在"对客户致歉"和"对内部复盘"两种场景分别选哪句？

```
a. We caused the outage.
b. An outage occurred.
```

请说明理由，并说出每句里"施事"的状态，以及它如何影响客户/同事的感受。

**参考答案**

对**客户致歉**，选 a `We caused the outage.`——主动句，施事 `We` 在 C 位，明明白白认账。客户要的是"你们承认是你们的锅"，主动认责比任何被动都让人安心（至少显得不推诿）。此时若用 `An outage occurred.` 客户会火大：这跟 `A 51-minute outage occurred.` 一样的甩锅腔，像在说"天灾，不赖我"，道歉信里用这个等于没道歉。

对**内部复盘**，可选 b `An outage occurred.`——存现式陈述，施事蒸发，先把"事实"摆上桌。注意 Pallet 真实复盘是 blameless、根因归流程，所以这种"只陈述事件、不点名个人"的开头反而是专业做法，它把后续讨论引向"系统哪漏了"而非"谁蠢"。但内部复盘若已定位到具体动作，也可以写 `The migration locked the orders table.`（主动点名动作，不点名人），既具体又不伤人。

核心：施事"在镜头里"（a）还是"蒸发"（b），直接决定读者感受到的是"认责"还是"免责"。姿态由主语和语态共同决定，不是由"态度好"三个字决定的。

### 第 5 题（拔高层）

为什么中文几乎不存在"被动抹施事"这个让英语头疼的问题？中文想隐去"谁干的"，靠什么机制？和英文的被动相比，两种语言处理"不想说谁干的"这件事，底层逻辑有什么不同？这反映了什么？

**参考答案**

先给结论：中文不是"没有抹施事的需求"，而是**抹施事的机制和英文根本不是一回事**。

英文抹施事靠**被动语态的形态**：把受事摆主语，`by` 短语一省，施事就从句子里消失。这是形态级操作，是英语语法本身提供的"隐身按钮"。所以英语才有 `Mistakes were made.` 这种专用甩锅句——它利用了被动形态"可省施事"的天然特性。

中文抹施事靠两条路，都不是形态级的：

1. **"被"字省略 / 无标记被动。** 中文大量"受事主语句"根本不用"被"：`饭吃了`、`信写好了`、`窗户打破了`——主语是受事，但动词还是主动形态，施事直接不出现。这种"隐性被动"天生就没施事，比英文被动还彻底，且自然到没人觉得奇怪。
2. **泛化主语.** 不想点名，就用"有人""大家""人们""据说"把施事稀释成一团模糊的集体：`有人把表锁了`、`大家觉得该回滚`。施事还在，但被稀释到不可追责。

底层逻辑差异：**英文是"形态化"语言，隐身靠语法开关（被动）；中文是"词汇化"语言，隐身靠省略和泛化主语，动词本身不变形。** 英文的"抹施事"是一个清晰的、可识别的句式选择（你一眼看出这是被动）；中文的"抹施事"弥散在无数无标记句式里，反而看不见"操作痕迹"。

这反映的深层事实是：英文把"谁干的"焊进了主语位置和动词形态，要藏就得动用一套显性的被动机制，于是"藏"这个动作本身就显眼（所以 `Mistakes were made` 会被当成甩锅套路）；中文把"谁干的"外包给语境和省略，藏不藏都在词汇层面悄悄发生，反而更难被察觉是"在藏"。两种语言都在处理同一件事（不想说谁干的），但一个把操作摆在台面上（被动形态），一个把操作溶进沉默里（省略）。这恰好印证全书那句话：**中文靠词汇和上下文表达的东西，英文把它焊进了动词的形态里。** 第三面讲的"镜头机位"，在中文里是靠"省略谁"来挪的，在英文里是靠"动词变形 + 主语重选"来挪的——机制不同，但镜头逻辑相通。

## 11. 附：本面速查表

语态 x 主语 的所有变体，一表收全。每格给：形态 + 回答的问题 + 母案例例句 + 思维差异。

这一表是第三面的"镜头旋钮面板"。你写句子前扫一眼：想让镜头架在谁身上、施事要不要露脸、责任指向哪边，对应哪格直接套。注意最上面"主动"和最下面"事件作主语"是两个极端——前者施事死死钉在 C 位，后者连"错"字都不出现——中间那几格（was / got / 中动 / 无主语句 / 存现句）则是不同程度的"施事隐身术"。**同一件事，你在这张表上滑动一格，叙事立场就换一副面孔。** 这也再次印证：中文翻译几乎一样，但英文思维完全不同。

| 变体 | 形态 | 回答的问题 | 母案例例句 | 思维差异（镜头/施事/责任） |
|------|------|-----------|-----------|--------------------------|
| 主动（施事主语） | S(施事) + V + O | 谁干了什么？ | `Lin ran a migration that locked the orders table.` | 镜头在施事，施事在 C 位，责任钉死在人 |
| 被动（及物 was） | O(受事) + was + V-en + (by...) | 受事被怎么了？ | `The orders table was locked by a migration.` | 镜头在受事，施事可补可省，责任可点名 |
| 被动（不及物 got） | O + got + V-en + (by...) | 受事摊上啥事了？ | `The orders table got locked.` | 镜头在受事，突发/外悬感，责任像天降 |
| 中动（主动形被动意） | O(受事) + V(主动) + adv | 这东西自身什么属性？ | `The migration doesn't rollback cleanly.` | 镜头在受事但主动形，无施事，讲属性 |
| 无主语句 | (Pro-drop / 泛指) + V | 有件事发生了？ | `Mistakes were made.` | 施事彻底蒸发，经典甩锅/脱责 |
| 存现句（There be） | There + be + N | 存在过什么事件？ | `There was a 51-minute outage.` | 事件本身当主角，零施事，零责任 |
| 事件作主语（occur 类） | N(事件) + occurred | 出了什么状况？ | `A 51-minute outage occurred.` | 事故被包装成自然现象，连"错"字都不提 |

使用口诀：

- 想点名谁干的 -> 主动，施事坐主语。
- 想让受事当主角、施事可藏 -> `was` 被动。
- 想吐槽"出岔子了" -> `got` 被动。
- 想讲事物属性 -> 中动（`sells well`）。
- 想彻底隐身甩锅/客观陈述 -> 无主语句或存现句。
