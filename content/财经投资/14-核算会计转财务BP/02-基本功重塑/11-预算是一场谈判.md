# 第11章 预算：一场关于资源的谈判，不是填表

## 引子：一个真实的下午

十月十二号，周四。集团发下来一封邮件，标题是《关于启动 2026 年度预算编制的通知》。

附件里有一个 Excel，十二个页签，小林数了一下，一共要填四百三十七个格子。

她叹了口气，把邮件转发给各个部门，附了一句："请于十月二十五日前填好返回，逾期不候。"

这是她做预算的第五年。流程她闭着眼睛都能走完：

十月十二号发通知，十月二十五号收表，十月二十六号到十一月五号催表，十一月六号到十五号把各部门的数加总、调平、跟去年比一下，十一月二十号交集团，十二月集团砍一刀，十二月二十号下发。

五年了，她一直觉得预算就是这么回事——一个每年都要走一遍的流程，一趟苦差事。

真正让她觉得不对劲的，是十月十八号那天。

那天下午她去茶水间，路过会议室，门没关严。里面是张总监和华东区几个大区经理在吵。

"四个亿，这个数我报上去了，你们几个分一下。"

"张总，我这边去年才做了九千万，你给我一亿三，我上哪儿找这四千万去？"

"找不找得到是你的事。你先报，报了再说。"

"那我报了完不成怎么办？"

"完不成就完不成，先把预算盘子做大，资源才能抢到手。你不懂这个，就永远拿不到费用。"

小林在门外站了三秒钟，端着杯子走了。

回到工位，她看着那个四百三十七格的 Excel，忽然觉得有点恶心。

她做了五年预算，她一直以为自己在"编预算"。那天她才发现，别人在"抢资源"，而她在"收作业"。

周五中午，她把这事讲给墨叔听。

"墨叔，预算到底是个什么东西？"

"你觉得呢？"

"我觉得……是个骗局。"

"这个说法我喜欢。"墨叔笑了，"但只对了一半。我给你改一个字。"

"怎么改？"

"预算不是骗局，是**谈判**。"

## 对谈

"你先回答我一个问题。"墨叔说，"你们公司为什么要做预算？"

"因为集团要求。"

"我问的是：如果集团不要求，你们还做吗？"

"……不做吧。"

"那你们现在做的这个东西，本质上是什么？"

"是……交差。"

"你很诚实。"墨叔说，"但我要告诉你，预算这个东西，如果只是一个'交差'的东西，它每年要吃掉你们公司几百个小时，换回来一堆没人看的数字。"

"那它应该是什么？"

"三样东西，一个都不能少。"墨叔伸出三根手指。

"第一，**资源配置契约**。公司一共就这么多钱，给谁不给谁，白纸黑字写下来。"

"第二，**目标承诺**。销售说能做到四个亿，写下来，年底拿这个数问你。"

"第三，**考核基准**。年底发奖金、评绩效，拿什么比？拿预算。"

"这三样东西合在一起，你想想会发生什么？"

"会……有人想多要钱？"

"对。还会有人想把目标压低。"墨叔说，"**只要这三样东西绑在一起，预算就天生是个政治过程。谁的资源多、谁的目标低，谁年底就舒服。**"

"所以张总监说的'先把盘子做大，资源才能抢到手'……"

"他说的是实话。"墨叔说，"他的问题不在于'抢资源'，在于他抢的方式是拍脑袋，不是算账。"

"那我的位置在哪儿？"

"你说呢？你做了五年预算，你觉得你是什么角色？"

"……审核员？"

"错。"墨叔说，"我告诉你 BP 在预算里真正的三个角色，你记下来。"

### 一、BP 在预算里的三个角色

"第一个角色：**翻译官**。"

"翻译什么？"

"把业务的语言翻译成财务的语言，把财务的语言翻译成业务的语言。"墨叔说，"销售说'我明年要开拓华东的社区团购渠道'。这句话在预算上是什么？"

"……收入？"

"具体。多少收入？什么时候开始有收入？要配多少人？要多少进场费？退货率多少？账期多少天？"

"这些他不一定说得出来。"

"所以你要帮他写出来。"墨叔说，"你说：'张总，社区团购这个事，我帮你拆一下。你要进五个平台，每个平台进场费多少，预计月销多少，平台佣金多少，退货率按多少算。你给我这四个数，我帮你算出这条渠道明年能贡献多少。'"

"第二个角色：**挑战者**。"

"怎么挑战？直接说'你这个数太高了'？"

"那是吵架，不是挑战。"墨叔说，"**挑战的意思是：把对方没说出来的假设，摊到桌面上。**"

"我举个例子。销售说明年增长 25%。你不要说'太高了'。你要问："

```
"这 25%，是从哪儿来的？
 是老客户增长，还是新客户？
 如果是老客户，是哪几个？他们去年的增长是多少？明年凭什么涨这么多？
 如果是新客户，现在在谈的有几家？意向金额多少？转化率按多少算？
 如果是涨价，涨多少？去年涨过吗？客户的反应是什么？
 如果是新品，什么时候上市？谁负责？去年的新品成功率是多少？"
```

"这些问题问完，25% 这个数要么站得住，要么自己就塌了。你不需要跟他吵。"

"第三个角色：**记录者**。"

"记录什么？"

"记录每一个数字背后的假设和承诺。"墨叔说，"这是我做了二十年预算最有用的一招。"

"我给你看个东西。"

他掏出手机，翻出一张照片，是一张很旧的手写表格。

```
2013 年度预算假设登记表（节选）

华东区收入增长 18%
  假设 1：A 客户门店数从 86 家增到 120 家（张总监，2012-11-03 邮件确认）
  假设 2：新品 Q3 上市，贡献 1,200 万（研发部王工，2012-11-08 会议纪要）
  假设 3：电商渠道不增长（张总监口头确认）

费用：市场推广费 380 万
  假设 4：其中 150 万用于新品上市，分两次投放（市场部李经理）
  假设 5：剩余 230 万按去年实际 × 1.0（无说明）
```

"这张表有什么用？"

"三个用处。"墨叔说，"第一，次年三月复盘的时候，你拿着它去问：'张总，A 客户门店数说好开到 120 家，现在开了 94 家，是慢了还是不打算开了？'——他没法抵赖，因为有邮件。"

"第二，第二年做预算的时候，你把它翻出来，看看去年哪些假设是准的、哪些是吹的。**连着做三年，你就知道谁的假设可信，谁的假设要打折。**"

"第三，也是最重要的——**当你把假设都登记下来，业务部门报数的时候会认真很多。**因为他知道这个数是要被记住的。"

### 二、增量预算：奖励浪费的制度

"墨叔，我们现在的预算是怎么做的？"

"你说呢？"

"……去年实际，乘一个增长率。"

"这叫**增量预算**。"墨叔说，"我给你讲它最大的毛病。"

他拿起笔在纸上写了一个例子。

```
某区域差旅费：
  2023 年预算  120 万，实际支出   98 万
  2024 年预算 = 98 × 1.05 = 102.9 万，实际支出  135 万（超支 31%）
  2025 年预算 = 135 × 1.05 = 141.8 万
```

"你看出来了吗？"

"……2024 年超支了，2025 年的预算反而变高了。"

"高了 38.9 万，比 2023 年的预算还高 21.8 万。"墨叔说，"**这个制度在说什么？它在说：你今年花得越多，明年的基数越高，你就越舒服。**"

"这不就是奖励浪费吗？"

"准确地说，是**奖励超支、惩罚节约**。"墨叔说，"那个 2023 年花了 98 万、省下 22 万的区域经理，2024 年的预算是 102.9 万；那个花了 135 万、超支 31% 的，2025 年是 141.8 万。你让人家怎么想？"

"那……为什么不改？"

"两个原因。"墨叔说，"第一，改起来太麻烦。增量预算的好处是'快'——去年数拿来乘一下就好，全公司几百个科目，两天搞定。"

"第二，也是最要命的——**改了会得罪人。**你一动基数，动到的那个部门立刻就来找你。而增量预算谁都不得罪，因为它不动任何人的奶酪，它只让浪费的人越来越舒服。"

"那我怎么办？我一个人改不了制度。"

"你不需要改制度。"墨叔说，"你需要在**关键科目上做零基**。"

### 三、零基预算：不是一切都从零

"零基预算是不是就是一切都从零开始算？"

"这是最大的误解。"墨叔说，"真的一切从零，你一年都做不完。"

"那是什么？"

"是按**决策包**排序。"

"决策包？"

"我举个例子。"墨叔说，"你们华东区的市场费用，去年一共 850 万。零基的做法不是'从零开始论证每一分钱'，而是把这个 850 万拆成若干个'决策包'。"

他画了一张表。

| 决策包编号 | 内容 | 金额 | 类型 | 不花会怎样 | 优先级 |
|---|---|---|---|---|---|
| P1 | 商超堆头费（合同刚性） | 210 万 | 固定 | 违反合同，要赔违约金 | 必保 |
| P2 | 两名专职理货员 | 26 万 | 固定 | 货架缺货率上升至 15% | 必保 |
| P3 | 电商大促资源位 | 180 万 | 项目 | 线上份额掉，预计损失 600 万收入 | 高 |
| P4 | 新品上市推广 | 150 万 | 项目 | 新品铺市率从 60% 掉到 30% | 高 |
| P5 | 社区团购进场费 | 90 万 | 项目 | 进不去这个渠道 | 中 |
| P6 | 常规促销物料 | 78 万 | 酌量 |  影响有限，可压 30% | 中 |
| P7 | 行业展会（2 场） | 60 万 | 酌量 | 品牌露出减少，短期无收入影响 | 低 |
| P8 | 市场调研 | 34 万 | 酌量 | 无直接影响，可延后 | 低 |
| P9 | 经销商年会 | 22 万 | 酌量 | 影响客情，可缩规模 | 低 |
| **合计** | | **850 万** | | | |

"这张表做完，会发生什么？"

"……能看出来哪些能砍。"

"不止。"墨叔说，"这张表真正的威力在于——**它把'砍谁的'这个问题，变成了'排第几'这个问题。**"

"什么意思？"

"以前你要砍费用，你去找市场部李经理说'你们部门砍 15%'。他会跟你拼命，因为他觉得你在针对他。"

"现在你拿着这张表说：'李经理，我们今年市场费盘子是 780 万，比去年少 70 万。你帮我排个序，这九个包里，哪个排在最后？'"

"他自己会砍？"

"他会砍，而且他会砍得比你狠。"墨叔说，"因为他比你清楚 P7、P8、P9 哪个最不重要。**你要做的不是替他决定砍哪个，是逼他给这九件事排序。**"

"那排序的规则呢？"

"三条。"

"第一条，**先保固定，再排项目，最后处理酌量**。固定是刚性承诺（合同、编制内人员），不讨论。项目是有明确起止和交付物的，按投入产出比排。酌量是可增可减的，按'不花会怎样'的严重程度排。"

"第二条，**能算出产出的排前面**。P3 电商大促，能算出'花 180 万带来 600 万收入'，排前面；P8 市场调研，算不出产出，排后面。"

"第三条，**谁承诺的指标越硬，谁优先**。如果李经理愿意在 P4 上承诺'新品铺市率不低于 55%，否则我退回 30% 的费用'，那这个包优先。"

"最后一条我加一句。"墨叔说，"**砍下来的钱，不要全部收走。**你要留一部分给砍的那个部门，让他明年自己支配。这样他才有动力说实话。"

### 四、滚动预测和预算，不是一回事

"墨叔，还有个事我一直搞混。集团现在又要我们做'滚动预测'，说要'每季度更新一次全年预测'。这和预算有什么区别？"

"你觉得呢？"

"……都是预测全年的数。"

"我给你打个比方。"墨叔说，"**预算是合同，滚动预测是导航。**"

"合同？"

"你签一份销售合同，一年签一次，签完就不能改，年底拿它算账。这就是预算。"

"导航呢？"

"你开车去一个地方，导航每隔几分钟就重新算一次'按现在的路况，你几点能到'。路况变了，预计到达时间就变。你不会因为你晚到了十分钟就去改合同，但你会因为'预计要晚到一小时'而换条路。"

"哦……"小林眼睛亮了一下，"所以预算不改，滚动预测一直在改。"

"对。**预算是用来考核的，滚动预测是用来管理的。**"

"那两个数的关系是什么？"

"我给你一个表格。"

| 维度 | 预算 | 滚动预测 |
|---|---|---|
| 更新频率 | 一年一次 | 每月或每季度 |
| 能不能改 | 原则上不改 | 每次都改 |
| 用来干什么 | 考核、资源配置、定目标 | 发现问题、调整动作 |
| 谁看 | 集团、老板、人力 | 业务负责人、BP |
| 精度要求 | 高（要签字） | 中（要快） |
| 出错的代价 | 大（要担责） | 小（下月修正） |

"最常见的错误是什么？"

"把滚动预测当成预算来考核。"墨叔说，"**一旦你把滚动预测的数字拿去考核，它就再也不准了。**因为业务部门会为了'好看'而报假数。"

"那滚动预测还有什么意义？"

"意义在于'变化'本身。"墨叔说，"你要盯的不是'预测数是多少'，是'这个月预测和下个月预测，差在哪儿'。"

"我给你一个最简单的做法："

```
每月做一张"预测变动表"：
  项目            上月预测    本月预测    变动      变动原因（一句话）
  全年收入          38,600     37,200    −1,400    C 端电商 6 月大促效果低于预期
  全年毛利率        27.8%      27.1%     −0.7pct   猪肉价格上涨，未能全部转嫁
  全年费用          14,200     14,350     +150      新增两名销售支持
  全年营业利润       3,950      3,480     −470      上述三项合计
```

"这张表一个月做一次，一年十二张。年底你把它摞起来看，就是公司这一年的病历。"

### 五、实操流程：从"增长 25%"到"必须先解决华南厂产能"

"墨叔，那我具体怎么做？下个月就要启动预算了。"

"我给你一套流程，五步。"

"**第一步：目标拆解。**"

"集团给的是'增长多少'，你要把它拆成'增长从哪儿来'。"

"**第二步：收入自下而上搭建。**"

"从两个维度分别搭：客户维度、SKU 维度。搭完做交叉验证。"

"**第三步：费用按固定、酌量、项目三分类。**"

"**第四步：资源争夺排序。**"

"**第五步：产能与资源约束校验。**这一步最容易被漏掉，也最容易出问题。"

"我一步一步给你演示，用华东区的数。"

**第一步：目标拆解**

"张总监报的是华东区明年 4 个亿，今年 3.2 亿，增长 25%。"

"你要做的第一件事不是质疑这个数，是把它拆开。"

```
4 亿 = 3.2 亿 × 1.25

拆法一：按渠道拆
  B 端（餐饮连锁、团餐）：今年 1.9 亿 → 明年 ?
  C 端（商超、电商、社区团购、经销）：今年 1.3 亿 → 明年 ?

拆法二：按新老拆
  老客户老产品：今年 3.2 亿中的多少？明年自然增长多少？
  新客户 / 新品：需要贡献多少？

拆法三：按时间拆
  增长的 8,000 万，分布在哪些月份？
```

"为什么按时间拆最重要？"

"你猜呢？"

"因为……产能有季节性？"

"聪明。"墨叔说，"这个问题我们待会儿算。你先把前两个拆完。"

**第二步：收入自下而上**

"我给你两份数据，你自己算。"墨叔推过来两张纸。

**客户维度（B 端，今年 1.9 亿）**

| 客户 | 今年收入（万元） | 明年的变化与依据 | 明年（万元） |
|---|---|---|---|
| A（连锁餐饮） | 4,800 | 新开 120 家门店，单店年采购 8 万 | 5,760 |
| B（团餐） | 3,000 | 中标 2 个新区域，销量 +25%，单价 −3% | 3,637.5 |
| C（连锁快餐） | 1,800 | 自建中央厨房，流失 60% | 720 |
| D（连锁火锅） | 1,200 | 门店扩张，+30% | 1,560 |
| E（团餐） | 600 | 持平 | 600 |
| **大客户小计** | **11,400** | | **12,277.5** |
| 其他长尾客户 | 7,600 | 自然增长 8% | 8,208 |
| **B 端合计** | **19,000** | | **20,485.5** |

"验算 B 团餐：3,000 × 1.25 × 0.97 = 3,637.5 万元。"墨叔说，"注意这个算式的含义——销量增长和单价下降要分开乘，不能直接说'增长 25%'。"

"B 端增长多少？"

"两万零四百八十五万五，减一万九，增长一千四百八十五万五……"小林算了一下，"增长百分之七点八。"

"继续，C 端。"

**客户维度（C 端，今年 1.3 亿）**

| 渠道 | 今年收入（万元） | 明年的变化与依据 | 明年（万元） |
|---|---|---|---|
| 商超 | 7,000 | 整体持平略降，−2% | 6,860 |
| 电商 | 3,000 | 平台投入加大，+65% | 4,950 |
| 社区团购 | 1,500 | 新渠道，+120% | 3,300 |

**口径二：SKU 维度自下而上**

| 品类 | 今年 | 明年依据 | 计算过程 | 明年 |
|---|---|---|---|---|
| 水饺 | 15,500 | +15% | 15,500 × 1.15 | 17,825 |
| 汤圆 | 6,200 | +10% | 6,200 × 1.10 | 6,820 |
| 预制菜 | 4,800 | +60% | 4,800 × 1.60 | 7,680 |

```

```

**口径三：销售口径**

```

```

**三方对账**

| 口径 | 金额（万元） | 增长率 | 与销售口径的差 |
|---|---|---|---|
| 销售口径（自上而下） | 40,000 | 25.00% | 基准 |
| SKU 口径（自下而上） | 38,100 | 19.06% | −1,900 |
| 客户口径（自下而上） | 37,170.5 | 16.16% | −2,829.5 |

**两个维度的交叉差异**

```
SKU 口径 − 客户口径 = 38,100 − 37,170.5 = 929.5 万元
```

这 929.5 万元，是 SKU 表上承诺了增长、但客户表上找不到买主的收入。典型的来源是预制菜的 +60%（2,880 万增量）里，找不到客户支撑的那部分。

**结论与建议**

```
建议下达：37,170.5 万元（客户口径，最保守且最可验证）
挑战目标：40,000 万元（销售口径）
差额：2,829.5 万元，占销售口径的 7.07%

这 2,829.5 万元的达成条件（必须同时满足）：
  条件一：新客户开发不少于 X 家，且意向金额可量化
  条件二：预制菜新品在 6 月前上市
  条件三：华南厂水饺线在 6 月前投产（产能支撑）
```

**换个条件会怎样**：如果 C 端电商的增长率从 65% 降到 40% 呢？

```
电商 = 3,000 × 1.40 = 4,200 万元（原 4,950）
C 端合计 = 6,860 + 4,200 + 3,300 + 1,575 = 15,935 万元
客户口径合计 = 20,485.5 + 15,935 = 36,420.5 万元
增长率 = 13.81%
与销售口径的差 = 3,579.5 万元
```

**一个假设的变动，就让缺口从 2,830 万扩大到 3,580 万。**这就是为什么你要把假设登记下来——因为它比结论更脆弱。

## 墨叔的三条提炼

**一、预算是"资源配置契约 + 目标承诺 + 考核基准"的三合一，所以它是谈判，不是计算**
这三样东西绑在一起，就决定了每个人都会想多要资源、少背目标。增量预算（去年数乘一个增长率）之所以长盛不衰，不是因为它对，是因为它快、且不得罪人——但它系统性地奖励超支、惩罚节约。所以你不必推翻整个制度，只要在 key 科目上做零基：**把"砍你多少"变成"你给这些事排个序"**，让业务部门自己砍，他会砍得比你狠。

**二、收入一定要自下而上搭两遍：客户维度和 SKU 维度，然后做交叉验证**
销售报上来的是一个总数，你的工作是把这个总数翻译成"哪几个客户、哪几个产品、什么时候"。客户维度算一遍，SKU 维度算一遍，两个数的差额就是"承诺了增长但找不到买主"的部分，拿着这个差去问销售，比任何质疑都有力。三个口径（销售、SKU、客户）摆在桌面上，让报数的人自己选——你不需要替他决定，你只需要让他看见。

**三、收入预算做完，必须回头校验产能，而且要拆到月**
全年产能利用率看起来宽松，不代表每个月都宽松。冷冻食品有明显的季节峰（端午、年货），峰值月突破产能上限是常态。校验的顺序是：收入换算成销量 → 按历史季节占比拆到月 → 加上其他区域的需求 → 跟月产能上限比对 → 算提前生产的可行性和代价（冷库、资金、客户对生产日期的要求）→ 最后倒推出"要完成这个目标，必须先解决什么"。**预算的最后一页，永远应该是"要完成这个数，必须先做什么"。**

【参考答案】

**第 1 题**

**作为"资源配置契约"，它诱导虚报和抢资源。**

因为资源是有限的，而每个部门拿到的资源多少，直接决定了明年好不好过。所以理性的做法是"多报、报满、先拿到手再说"。张总监那句"先把预算盘子做大，资源才能抢到手"，就是典型。

反制做法有两条：
一是**把资源申请和承诺指标绑定**——你要这 150 万，可以，但你要承诺"新品铺市率不低于 55%"，年底拿这个验收。承诺越硬，资源越优先。
二是**给"资源池"而不是"部门额度"**——把一部分费用（比如市场推广、新品上市）做成公司级的资源池，按项目申请、按季度评审，谁的项目投产比高给谁。这样资源不是"你的"和"我的"，是"这件事的"。

**作为"目标承诺"，它诱导压低目标。**

因为目标越低，年底越容易完成，奖金越稳。所以销售会本能地把目标往低报，同时把困难往大说。

反制做法：
一是**双目标制**——下达一个"必保目标"（比如 3.72 亿，用来考核）和一个"挑战目标"（4 亿，超额部分给更高的提成系数）。这样压低目标没意义，因为压低了必保目标，你的挑战奖金也跟着降。
二是**让下游泳的人参与上游目标的制定**。让生产、采购、物流一起参加销售目标的评审——销售说要增长 25%，生产当场就问"那六月的产能怎么办"。同级的压力，比财务的压力有效得多。

**作为"考核基准"，它诱导突击花钱和跨期调节。**

因为今年的实际支出会成为明年的基数，所以年底一定要把预算花完，否则明年的钱更少。于是十二月会出现大量"没必要但必须花"的支出。同时，为了今年好看，会把能拖的支出拖到明年。

反制做法：
一是**把"预算执行率"从考核指标里拿掉**。只要"花完预算"这件事被当成好事，突击花钱就永远不会停止。改成考核"投入产出达成率"。
二是**设一个"节约留存"机制**——部门今年省下来的钱，允许留 40%-50% 到明年自己支配。这一条最有效，因为它把"省钱"从吃亏变成划算。
三是**对十二月的支出做专项审查**——十二月单笔超过一定数量的支出，需要 BP 和部门负责人双签，并说明"为什么必须在这个月花"。

**这三条反制的共同点是：不要指望靠道德约束，要靠机制设计。**预算参与者都是理性人，他们会按照规则优化自己的利益。你要做的是让"说实话、真增长、真节约"在规则下成为最优解。

**第 2 题**

核心思路：**不要一刀切，要按科目的性质分类处理。**

| 科目类别 | 典型科目 | 预算方法 | 为什么 |
|---|---|---|---|
| 刚性固定 | 折旧、租金、贷款利息、合同期服务费 | 直接按合同确认，不乘增长率 | 这些钱不受今年花多少影响 |
| 半固定（编制驱动） | 人员底薪、社保、公积金 | 按编制核定，编制单独审 | 按人头算，不按去年实际算，避免"今年临时工多、明年基数高" |
| 变动费用 | 运费、销售提成、平台佣金、包装费 | 按"费率 × 预算销量"算 | 随业务量走，不该用去年实际 |
| 酌量费用 | 差旅、招待、培训、咨询、会务、办公 | 零基，按决策包排序 | 最该管的一块，也是最容易"奖励浪费"的一块 |
| 项目费用 | 新品上市、展会、设备改造、进场费 | 单独立项，按投产比排序 | 必须算产出，算不出的一律往后排 |
| 维护与安全 | 设备维护、检验、消防、安全培训 | 按标准定额（厂商建议、法规要求） | 按标准算，不按去年实际，也不参与统一压降 |

**三条配套机制：**

**机制一：节约留存。**部门实际支出低于预算的部分，允许留存 40%-50% 到下一年度，由部门自主支配（用于团队激励或新增项目）。这一条直接消除了"不花白不花"。

**机制二：基数保护。**酌量费用的预算基数，不直接用"去年实际"，而用"近三年实际支出的中位数"。这样某一年的异常高（或异常低）不会永久地抬高（或压低）基数。

**机制三：分类压降。**如果必须整体压降 10%，不要一刀切，而是：维护与安全类 0%、刚性固定 0%、编制类 0%（走单独的编制评审）、变动类按费率自动调整、酌量类压 20%-30%、项目类按排序砍末尾。

**这样既保留了"快"的优点**——刚性固定和变动费用是自动算的，不用讨论；**又消除了副作用**——真正需要做决策的只有酌量和项目两类，而这两类恰恰是占比不高但水分最大的部分。一个中型公司，需要逐项讨论的决策包通常不超过 100 个，两到三周可以做完。

**第 3 题**

**如果把滚动预测纳入考核，会发生三件事：**

**第一，预测会变得"保守且稳定"，失去预警功能。**业务部门一旦发现每个月的预测数会影响年底考核，他们会怎么做？报一个"一定能完成"的数，然后每个月微调一点点。于是预测曲线变成一条平滑的直线，而真实的经营波动被完全掩盖。你花大力气建的这套预测体系，最后得到的只是一张"看起来很稳"的假图。

**第二，会出现"预测博弈"——上半年故意报低，下半年突然说超额完成。**这是最典型的手法：前三个季度把预测压低，让老板的预期降下来，第四季度再"意外"地交出一个好成绩。反过来也有：如果今年注定完成不了，就把预测一路往下调，让"坏消息"分批释放，避免一次性引爆。

**第三，最坏的结果是"数据的信任崩塌"。**一旦老板发现预测数不可信，他会回到原来的做法——不听预测，只看实际。你这套体系就白做了，而且以后再想建，没人信了。

**所以滚动预测绝对不能纳入考核。它唯一的作用是"看变化"。**

**滚动预测应该看三样东西，而不是绝对数：**

**一看变动额和变动率。**这个月的预测和上个月的预测，差了多少？差在哪一项？这个月预测全年收入 37,200 万，上个月是 38,600 万，差了 1,400 万——**这 1,400 万才是信息，那 37,200 万不是。**

**二看变动原因的可追溯性。**每一笔超过一定额度的变动，必须有一句话说明原因，并且要能追溯到具体的客户、项目或事件。"C 端电商六月大促效果低于预期"是可追溯的；"市场环境变化"是不可追溯的。

**三看预测的准确度本身。**做了一个季度之后，你可以回头看：上个月预测的这个月的数，和实际差多少？谁报的数经常偏、偏多少？这不是为了考核谁，是为了**让你知道下一年做预算的时候，谁的假设可以信、谁的假设要打折**。这才是滚动预测最长远的价值。

**一句话总结：预算问的是"你承诺什么"，滚动预测问的是"现在看起来会怎样"。**把这两个问题混在一起，两个都答不好。

**第 5 题**

这是一道必须"离开工位"才能完成的题。我给四条判卷标准。

**第一条，你必须能说出这项费用"是怎么定出来的"，而且要具体到动作。**如果答案是"去年数乘 1.05"，那你要接着问一句"这个 1.05 是谁定的、什么时候定的"。如果你问了一圈发现没人知道，那你找到的就是最典型的"历史惯性"。

**第二条，你的固定/酌量/项目分类，必须给出依据，而且依据要能被验证。**比如你说"设备维护费是固定的"，依据是"设备厂商的保养合同，一年四次，每次 X 万"——这是可验证的。如果你说"我觉得它不该砍"，那不是依据。

**第三条，是这一题的硬指标：你必须真的去问一个人，并把他的原话记下来。**这一条做不做，决定了你是在学知识还是在建立关系。

给你一个提问的示范，注意它的结构：

"王哥，我想跟您请教个事。今年预算我在看培训费这一项，去年是 32 万。我不是要砍您的钱——我是想把这一项在预算表里写得更有说服力，别让上面一看就想砍。我想问您：这 32 万如果砍掉 20%，也就是少 6 万多，您这边会有什么影响？是会少开几场课，还是有些课就干脆不做了？"

这段问话里有四个要素：
- 先声明"我不是来砍你的"（消除防御）
- 把你的目的说成"帮他在预算里站住脚"（变成同盟）
- 问"会怎样"而不是问"能不能砍"（让他自己说）
- 给出具体金额（6 万多，比"20%"更真实）

**第四条，你的"决策包"拆分，必须至少拆出五个包，并且要能排序。**

一个及格的示范：

```
培训费 32 万决策包拆分：

P1  新员工入职培训（安全 + 制度）     6 万   刚性：不做违反法规      必保
P2  特种设备操作证年审培训            5 万   刚性：不做停不了机      必保
P3  班组长管理技能培训                8 万   承诺指标：班组离职率降 5%  高
P4  质量管理内审员培训                5 万   承诺指标：内审不符合项降 30% 高
P5  通用职业素养外训                  4 万   无明确交付物           中
P6  外部公开课（按报名）              3 万   无明确交付物           低
P7  培训物料与场地                    1 万   可压缩 30%             低
                                      ────
                                      32 万
```

不及格的拆法是"按部门拆"（生产部多少、销售部多少）——那不叫决策包，那叫分摊。决策包的核心特征是：**每一个包都能独立回答"这笔钱买了什么"和"不花会怎样"。**

最后提醒一句：**你做完这件事，不要急着交给预算委员会。先拿给那个"王哥"看，让他确认你的排序对不对。**这一步有两个好处：一是你的排序会更准，二是等你在会上拿出这份东西的时候，他已经是你的人了。
